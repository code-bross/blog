터미널에서 에이전트와 함께 개발하기 Android CLI 공식 플러그인

November 2, 2026 · 4 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
최근 Android Dev Summit 2026에서 공개된 Android CLI 공식 에이전트 플러그인에 대해 설명해드리겠습니다.

배경​

최근 Android 개발 환경에서는 AI 코딩 에이전트의 역할이 빠르게 커지고 있습니다.
Android Studio Rabbit 2에서는 IDE 안에서 원하는 에이전트를 고르는 Bring Your Own Agent가 안정화되었습니다.
그런데 모든 개발자가 IDE 안에서만 에이전트를 쓰는 것은 아닙니다.
터미널에서 작업하는 에이전트, CI 파이프라인에서 동작하는 자동화 흐름도 함께 고려해야 합니다.
이번에 공개된 Android CLI 공식 에이전트 플러그인은 바로 이 지점을 겨냥합니다.
터미널에 상주하는 에이전트에게 Android 개발 도구를 직접 쥐여주는 방식입니다.

Android CLI 공식 플러그인 살펴보기​

플러그인은 Claude Code, OpenAI Codex, Google Antigravity에 공식으로 제공됩니다.
플러그인을 설치하면 에이전트에게 android-cli 스킬이 추가됩니다.
이 스킬을 통해 에이전트는 프로젝트 생성, 가상 기기 관리, 실시간 UI 레이아웃 검사, Journeys 실행, 공식 Android Knowledge Base 검색을 수행합니다.

설치하기​

각 에이전트마다 설치 명령이 조금씩 다릅니다.
Claude Code에서는 마켓플레이스를 추가한 뒤 플러그인을 설치합니다.

claude plugin marketplace add android/android-cli-plugin
claude plugin install android-cli@android-cli-plugin

Codex에서는 두 번째 명령의 동사가 add라는 점이 다릅니다.

codex plugin marketplace add android/android-cli-plugin
codex plugin add android-cli@android-cli-plugin

Antigravity에서는 전용 마켓플레이스 경로로 설치합니다.

agy plugin install android-cli-plugin@antigravity-plugins-official

설치가 끝나면 에이전트 세션 안에서 Android CLI를 바로 사용할 수 있습니다.
먼저 android init으로 에이전트 설정을 마치고, android skills list로 제공되는 스킬 목록을 확인하는 흐름이 안내됩니다.

Compose 프리뷰와 기기 스트리밍​

터미널 기반 에이전트의 약점은 화면을 직접 보지 못한다는 점이었습니다.
Android CLI는 이 약점을 두 가지 기능으로 보완합니다.
첫 번째는 Compose 프리뷰 렌더링입니다.
에뮬레이터를 띄우거나 APK를 설치하지 않고도 프리뷰를 렌더링해 UI 변경을 즉시 시각적으로 검증합니다.
두 번째는 Android Device Streaming입니다.
Firebase 기반으로 원격 실기기를 연결해 기기별 이슈를 직접 확인합니다.
구글은 내부 테스트 기준으로 android preview를 활용한 에이전트가 UI 작업을 더 빠르게 마쳤다고 밝혔습니다.
이 수치는 구글 자체 테스트 결과이므로, 참고용 지표로 받아들이는 편이 좋습니다.

프로파일링과 분석​

Android CLI에는 성능 분석 도구도 함께 들어 있습니다.
Perfetto 기반 시스템 트레이스를 수집해 콜드 스타트 지연, UI 끊김, 백그라운드 깨어남을 살펴봅니다.
메모리 누수 탐지에는 오픈소스 LeakCanary가 내장되어 있습니다.
analyze 기능은 앱 번들과 라이브러리를 검사해 난독화, 최적화, 축소 점수를 확인합니다.
Google Play에 업로드하기 전에 스토어와 같은 기준으로 품질 신호를 미리 점검하는 용도입니다.

30개 이상의 Android 스킬​

플러그인과 함께 제공되는 Android 스킬은 30개 이상이며, 20개 이상의 영역을 다룹니다.
권한 보안, Glance 위젯 레이아웃, Compose 성능 최적화 같은 주제가 포함됩니다.
에이전트가 범용 지식만으로 추측하지 않고, Android 공식 가이드에 근거해 작업하도록 돕는 장치입니다.
필요한 스킬만 골라 추가하는 방식이라, 프로젝트 성격에 맞게 범위를 조절할 수 있습니다.

실무 관점​

MTS처럼 보안과 정확성이 중요한 프로젝트에서 에이전트 도구를 쓸 때는 범위를 좁게 잡는 편이 좋습니다.
에이전트에게는 프리뷰 렌더링, 레이아웃 검사, 트레이스 수집 같은 확인 작업부터 맡기고, 실제 반영은 사람이 검토하는 구조가 안전합니다.
실기기 검증은 원격 스트리밍으로 1차 확인하고, 최종 검증은 내부 테스트 트랙과 실기기에서 마치는 편이 좋습니다.
에이전트가 생성한 코드는 빌드와 테스트를 통과했는지, 기존 아키텍처와 어긋나지 않는지 별도로 확인해야 합니다.

마치며​

Android CLI 공식 플러그인은 에이전트의 작업 공간을 IDE 밖으로 넓혔습니다.
터미널과 CI에서도 프리뷰, 기기, 프로파일링 도구를 같은 방식으로 쓸 수 있게 되었습니다.

안드로이드 개발자에게 열린 Gemini 4 Argon — 자가 복구 빌드와 AGSL 셰이더

October 15, 2026 · 4 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
안드로이드 개발자에게 개방된 Gemini 4 Argon에 대해 설명해드리겠습니다.

배경​

구글은 10월 13일 Android Developers Blog에서 최신 플래그십 모델 Gemini 4 Argon을 안드로이드 개발 표면에 개방한다고 발표했습니다.
자세한 내용은 원문 글(Jason Buchel)에서 확인할 수 있습니다.
지난주에 다뤘던 Android CLI와 디바이스 스트리밍, BYOA(원하는 에이전트 쓰기) 흐름의 연장선에 있는 발표입니다.
모델 자체보다 에이전트가 빌드를 스스로 고치고 셰이더까지 작성한다는 부분에 주목할 필요가 있습니다.

Gemini 4 Argon 살펴보기​

접근 경로​

  • Google Antigravity에서 사용할 수 있습니다. AI Ultra 구독이 전제이고, 데스크톱 앱·CLI·Android Studio Canary 안에 포함됩니다.
  • Android Studio에서는 Gemini API 유료 티어로 사용할 수 있습니다.
  • Google AI Studio의 Playground와 Build에서도 사용할 수 있습니다. AI Ultra 또는 Gemini API 유료 티어가 필요합니다.
  • 클라이언트 인앱 AI는 Firebase AI Logic 경유로 제공됩니다. Gemini API 유료 티어 개발자가 앱 안에서 Gemini 4 Argon을 직접 쓸 수 있습니다.

Self-Healing Build Loops​

  • 빌드 실패 시 Antigravity 하네스가 Gradle 데몬과 Kotlin 컴파일러 로그를 모델에 그대로 피드백합니다.
  • 모델은 근본 원인을 반복 진단해 수정안을 냅니다.
  • 편집 라운드마다 가설을 일관되게 유지하고 AST 인지를 활용해 표면 증상이 아닌 진짜 원인에 도달하도록 훈련되었다는 설명입니다.
  • 지금까지의 에이전트 코딩이 코드 자동완성의 연장에 가까웠다면, 이번 방향은 빌드 → 실패 로그 수집 → 원인 진단 → 수정 → 재빌드를 하네스와 모델이 돌리는 클로즈드 루프 실행입니다.

Compose 셰이더 생성​

  • AGSL(Android Graphics Shading Language)을 Compose Modifier.graphicsLayer나 셰이더 브러시에 직접 작성합니다.
  • 120fps Compose 애니메이션과 함께 도는 경량 GPU 셰이더를 생성합니다. 프로스트드 글래스, 동적 조명, 파문 같은 효과가 예시입니다.
  • 벡터·렌더링 수학까지 처리해 뽑아낸다고 합니다.
  • Compose 셰이더는 AGSL 문법과 렌더링 수학, 성능 예산 때문에 실무에서 진입 장벽이 높은 영역입니다.

터미널 에이전트 연결​

  • 터미널 에이전트 연결은 공식 Android CLI 플러그인이 맡습니다.
  • android init 한 줄이면 어떤 터미널 에이전트든 로컬 Android 도구와 연결됩니다.
  • Antigravity라면 플러그인 설치로 끝납니다.

실무에서 주의할 점​

빌드 로그가 곧 에이전트의 입력입니다.
Self-Healing이 동작하려면 빌드 실패 로그가 잘 읽혀야 합니다.
난독화된 멀티모듈 빌드에서 에이전트가 원인에 닿으려면, 지금부터라도 Gradle 빌드 스크립트와 에러 메시지를 사람이 읽을 수 있게 정리해 두는 것이 이득입니다.
비용 구조도 확인해야 합니다.
Antigravity는 AI Ultra 구독 전제이고, API 경로는 Gemini API 유료 티어 전제입니다.
인트로 가격은 2026년 11월 30일까지 적용되므로, 이후 정가를 모르면 팀 도입 판단이 어렵습니다. 도입 전에 Console에서 실제 과금을 먼저 확인해야 합니다.
셰이더 코드는 리뷰가 필수입니다.
"프로덕션급"이라는 표현은 모델 벤더의 주장일 뿐이고, AGSL 셰이더는 GPU와 디바이스별로 동작이 달라 실기 검증 없이는 쓸 수 없습니다. 에이전트가 짠 셰이더는 초안으로 보고 프레임 타임과 배터리부터 측정해야 합니다.
Firebase AI Logic 경로는 인앱 기능용입니다.
개발 워크플로(빌드 복구·코드 생성)와 앱 내 AI 기능(사용자 대면)은 접근 경로가 다르므로, 팀에서 둘을 혼동하면 과금·권한 설계가 꼬입니다.
터미널 에이전트에 Android CLI를 붙이는 방법은 다음과 같습니다.

# 어떤 터미널 에이전트에서든: 로컬 Android 도구와 연결
android init

# Antigravity를 쓴다면: 공식 Android CLI 플러그인 설치
agy plugin install android-cli-plugin

Firebase AI Logic으로 인앱에 붙일 때는 모델 선택만 새 모델로 바꾸는 구조라, 기존 Vertex AI와 Gemini Developer API 연동 코드의 모델명 교체 수준에서 검토가 가능합니다.
정확한 모델 식별자는 Firebase AI Logic 문서를 확인해야 하고, 릴리스 직후에는 SDK 업데이트가 필요할 수 있습니다.
샘플 프로젝트 gemini-4-antigravity-quickstart도 함께 공개되었으니, 에이전트 워크플로를 팀에 도입하기 전에 퀵스타트로 확인하는 것이 좋습니다.

마치며​

Gemini 4 Argon의 핵심은 모델 성능보다 빌드와 셰이더까지 에이전트 워크플로에 들어왔다는 점입니다.
도입 전에 비용 구조와 실기 검증 절차부터 정리해 두는 것이 좋겠습니다.
