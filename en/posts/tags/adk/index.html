챗봇을 넘어서 — Google ADK for Kotlin 1.0으로 앱에 AI 에이전트 붙이기

October 18, 2026 · 5 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
최근 1.0이 공개된 Google의 Agent Development Kit(ADK) for Kotlin에 대해 설명해드리겠습니다.

배경​

앱에 AI를 넣는다는 것은 그동안 프롬프트를 보내고 텍스트를 받아 화면에 보여주는 것과 같은 의미였습니다.
챗봇은 그렇게 만들 수 있지만, 모델이 직접 앱의 데이터를 조회하고 API를 호출하는 것은 다른 차원의 일입니다.
민감한 작업을 실행하기 전에 사용자에게 확인까지 받는 구조가 필요하기 때문입니다.
ADK for Kotlin은 2026년 9월에 1.0이 공개되었고, 공식 블로그 발표는 9월 9일에 올라왔습니다.
이 글에서는 공식 발표와 10월 14일 Medium에 올라온 Sagar Singh의 튜토리얼을 함께 정리합니다.

ADK for Kotlin 살펴보기​

에이전트와 도구​

에이전트는 도구를 사용할 수 있는 모델을 말합니다.
ADK는 모델이 어떤 도구를 언제 호출할지 스스로 결정하는 루프를 프레임워크가 대신 실행해 주는 오픈소스 도구킷입니다.
개발자는 도구와 설명만 작성하면 됩니다. 도구는 그냥 코틀린 함수입니다.
도구에는 @Tool 어노테이션을 붙이고, KSP가 빌드 타임에 도구 설명을 생성합니다.
런타임 리플렉션이 없기 때문에 폰에서 시작 속도가 빠릅니다.
실행 결과는 코루틴 Flow로 돌아오므로 ViewModel에 자연스럽게 연결됩니다.

다섯 가지 구성 요소​

  • LlmAgent: 이름, 모델, 지시문, 도구 목록을 정의하는 에이전트입니다.
  • Model: 두뇌 역할을 하며, Firebase AI의 Gemini나 온디바이스 모델을 사용합니다.
  • Tools: @Tool 어노테이션을 붙인 함수들입니다.
  • Runner: 루프를 실행하고 이벤트 Flow를 반환합니다.
  • Session: 대화를 기억합니다.

1.0에서 달라진 점​

0.1.0은 I/O 2026에서 공개된 실험적인 버전이었습니다.
1.0은 ADK 1.0 Core(Python/Java)와 기능 동등성(feature parity)을 달성했고, 프로덕션용 도구킷을 표방합니다.
코어는 Kotlin Multiplatform으로 구성되어 백엔드 코틀린에서도 사용할 수 있고, 안드로이드 모듈은 별도 아티팩트로 붙습니다.
안드로이드 전용 확장으로 온디바이스(LiteRT-LM, ML Kit 베타), 하이브리드(Firebase AI Logic), 프로세스가 종료되어도 이어지는 세션(Room), 시맨틱 메모리(AppSearch)가 포함됩니다.

모델 백엔드 선택​

모델 백엔드는 한 줄로 교체할 수 있고, 종류는 다음과 같습니다.

백엔드아티팩트위치도구 호출
Firebase AI (Gemini)google-adk-kotlin-firebase-android클라우드가능
LiteRT-LM (예: Gemma)google-adk-kotlin-litertlm온디바이스가능
ML Kit (Gemini Nano)google-adk-kotlin-mlkit-android (베타)온디바이스아직 불가

적용 예시​

주문 상태를 물어보면 직접 조회해서 답하는 지원 에이전트를 한투 앱 문맥으로 옮기면 뼈대는 다음과 같습니다.

// 1. 도구는 그냥 suspend 함수 + 어노테이션. Retrofit/Room 호출이 자연스럽다.
class OrderTools(private val repo: OrderRepository) {
    @Tool(description = "고객 주문의 현재 배송 상태를 반환한다.")
    suspend fun getOrderStatus(
        @Param("주문번호, 예: ORD-1042") orderId: String,
    ): Map<String, String> {
        val o = repo.getOrder(orderId) // 실제 레포지토리 호출
        return mapOf("orderId" to o.id, "status" to o.status, "eta" to o.eta)
    }
}

// 2. ViewModel은 Runner의 Flow만 collect한다.
//    "언제 도구를 호출할지"를 결정하는 if문은 내가 쓰지 않는다.
fun send(message: String) {
    viewModelScope.launch {
        runner.runAsync(
            userId = "local-user",
            sessionId = sessionId, // 같은 세션을 재사용하면 이전 대화를 기억한다
            newMessage = Content.fromText(Role.USER, message),
        ).catch { e -> _reply.value = "오류: ${e.message}" }
         .collect { event ->
            event.content?.parts?.firstOrNull()?.text
                ?.takeIf { it.isNotBlank() }
                ?.let { _reply.value = it }
        }
    }
}

빌드 한 번 돌리면 KSP가 OrderTools().generatedTools() 확장 함수를 만들어줍니다.
빨간 줄이 보이면 빌드를 한 번 돌리라는 것이 원문 튜토리얼의 팁입니다.

실무에서 주의할 점​

  • 세션은 기본이 인메모리입니다. InMemoryRunner의 대화는 프로세스가 종료되면 사라집니다. 재시작 후에도 대화를 이어가려면 Room 기반 RoomSessionService를 러너에 넘겨야 합니다. 금융 앱의 상담 흐름에서는 필수 요건입니다.
  • 민감한 작업은 확인을 강제할 수 있습니다. @Tool(requireConfirmation = true)로 선언하면 에이전트가 함수를 실행하기 전에 멈춰서 사용자의 승인을 기다립니다. 주문 취소나 이체 같은 작업의 안전장치가 프레임워크에 내장되어 있습니다.
  • Gemini Nano는 아직 도구 호출을 지원하지 않습니다. ML Kit 백엔드는 함수 호출 파트를 제외하므로, 도구를 사용하는 에이전트라면 첫 선택은 Firebase AI가 됩니다.
  • GenAI SDK의 Gemini 모델 클래스는 안드로이드 앱용이 아닙니다. README에서 안드로이드에서의 API 키와 크리덴셜 사용을 차단하고 Firebase AI를 권장합니다. 비밀 키는 APK에 넣으면 안 되므로, 이는 제약이 아니라 올바른 방향입니다.
  • 튜토리얼의 버전을 확인해야 합니다. 0.1.0(5월)에서 1.0.0(9월)으로 네 달 만에 올라오면서 의존성 이름과 셋업 단계가 바뀌었습니다. 오래된 글을 보고 1.0.0 아티팩트(com.google.adk:google-adk-kotlin-core:1.0.0 등)와 섞어 쓰면 빌드가 깨집니다. 공식 Android 가이드의 요구사항은 compileSdk 34 이상, minSdk 24 이상입니다.
  • 도구 설명이 곧 스펙입니다. 모델은 @Tool과 @Param의 description을 읽고 호출 여부를 결정합니다. 모호한 설명은 모호한 호출을 만듭니다. 지시문(instruction)도 마찬가지입니다.

마치며​

ADK for Kotlin 1.0을 적용하면, 도구를 사용하는 AI 에이전트를 코틀린 코드 안에서 구성할 수 있습니다.
세션 저장 방식과 확인 절차만 먼저 정해 두면, 금융 앱의 상담 흐름에도 단계적으로 도입할 수 있습니다.
