AppFunctions 1.0.0-rc01 살펴보기 — 앱 기능을 AI 에이전트에 연결하기

November 7, 2026 · 2 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 11월 4일에 공개된 AppFunctions 1.0.0-rc01에 대해 설명해드리겠습니다.

배경​

AppFunctions는 앱의 기능을 AI 에이전트가 호출할 수 있게 노출하는 Jetpack 라이브러리입니다.
Android Dev Summit 2026에서 베타로 발표됐고, 11월 4일 RC 단계에 들어갔습니다.
RC는 API 표면이 확정된 예비 stable 릴리스입니다.
에이전트는 기능을 직접 실행하는 대신, 앱이 선언한 설명을 보고 호출합니다.

AppFunctions 1.0.0-rc01 살펴보기​

의존성을 추가합니다​

dependencies {
    implementation("androidx.appfunctions:appfunctions:1.0.0-rc01")
    ksp("androidx.appfunctions:appfunctions-compiler:1.0.0-rc01")
}

테스트용 아티팩트도 같은 버전으로 제공됩니다.
Android 16(API 36) 이상에서 동작하며, compileSdk 36이 필요합니다.

기능을 선언합니다​

@AppFunctionServiceEntryPoint
class MarketFunctions {

    /**
     * 보유 종목의 현재가를 조회합니다.
     *
     * @param symbol 종목 코드입니다.
     * @return 현재가 정보입니다.
     */
    @AppFunctionDeclaration(isDescribedByKDoc = true)
    suspend fun getStockPrice(symbol: String): StockPrice {
        return withContext(Dispatchers.IO) {
            stockRepository.getPrice(symbol)
        }
    }
}

선언은 @AppFunctionServiceEntryPoint가 붙은 서비스 클래스 안에 둡니다.
@AppFunctionDeclaration이 붙은 함수는 외부 앱이 호출할 수 있습니다.
KSP 컴파일러가 함수 설명을 XML로 만들어 assets에 넣고, 시스템이 이를 색인합니다.
isDescribedByKDoc은 KDoc을 에이전트용 설명으로 쓸지 정합니다.
beta01부터 기본값이 없어 반드시 지정해야 합니다.

기본적으로 메인 스레드에서 실행됩니다​

선언한 함수는 기본적으로 메인 스레드에서 실행됩니다.
네트워크나 파일 작업이 있으면 suspend 함수로 만들고 디스패처를 바꿉니다.
호출자는 EXECUTE_APP_FUNCTIONS 권한이 필요합니다.
사용자 정의 타입을 주고받을 때는 직렬화 규칙을 따라야 합니다.

RC01 변경점​

버전이 RC로 올라갔고, 기존 집계 컴파일러 옵션이 제거됐습니다.
Java 라이브러리 desugaring을 켠 앱에서 java.time 파라미터 역직렬화가 실패하던 문제가 수정됐습니다.
테스트는 Android 17 기기나 에뮬레이터에서 adb shell cmd app_function 명령으로 할 수 있습니다.

실무 관점​

노출하는 기능은 읽기 전용 조회부터 시작하는 것이 안전합니다.
주문처럼 돈이 움직이는 기능은 에이전트에 노출하지 않습니다.
프로덕션 배포는 Connected Apps Platform 프리뷰 등록이 별도로 필요합니다.
설명 문구는 에이전트가 기능을 선택하는 기준이 되므로, KDoc을 정확히 씁니다.

마치며​

AppFunctions가 RC에 들어서면서 에이전트 연동 준비가 한결 가까워졌습니다.
조회 기능부터 작은 범위로 적용해보고, 안정 버전에서 범위를 넓히겠습니다.

Android Dev Summit 2026 정리: 에이전트와 적응형 UI의 시대

November 5, 2026 · 5 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 28일부터 29일까지 열린 Android Dev Summit 2026의 핵심 발표를 정리해드리겠습니다.

배경​

이번 서밋은 도구와 에이전트, 에이전트 경험 API, 적응형 UI, XR이라는 네 가지 방향으로 발표가 나뉘었습니다.
구글은 개발자가 원하는 코딩 에이전트를 직접 고를 수 있게 하고, 앱이 에이전트와 연결되는 방식을 넓히는 데 초점을 맞췄습니다.
공개된 내용 중 상당수는 이미 stable 단계에 도달했거나, 베타와 알파로 구분되어 공개되었습니다.
실무에서는 어느 발표가 당장 적용 대상인지, 어느 발표가 준비 단계인지 구분하는 것이 중요합니다.

Android Studio Rabbit 2 살펴보기​

Android Studio Rabbit 2가 stable로 공개되었습니다.
이제 Claude Agent, Codex, Antigravity를 비롯해 40개 이상의 ACP 호환 에이전트를 IDE 안에서 직접 고를 수 있습니다.
에이전트는 에뮬레이터와 빌드 시스템, Logcat 같은 Android Studio의 개발 도구를 함께 쓸 수 있습니다.
Gemini만 쓰던 구조에서 벗어나 팀이 이미 쓰고 있는 에이전트를 그대로 가져올 수 있게 된 점이 가장 큰 변화입니다.

Android CLI 살펴보기​

Android CLI도 에이전트 중심으로 기능이 넓어졌습니다.
Firebase 기반의 Android Device Streaming으로 실제 기기를 원격으로 테스트할 수 있습니다.
에이전트는 Jetpack Compose 프리뷰를 렌더링해서 에뮬레이터나 APK 배포 없이 화면을 바로 확인할 수 있습니다.
프로파일링은 Perfetto 기반의 시스템 트레이스를 수집해 콜드 스타트와 UI 끊김, 백그라운드 깨움을 분석합니다.
Analyze 기능은 앱 번들과 라이브러리의 난독화와 최적화, 축소 점수를 검사해 Play 업로드 전에 품질 문제를 찾습니다.
20개 이상의 영역을 다루는 30개 이상의 Android 스킬도 함께 공개되었습니다.

android init
android skills list

위 명령으로 에이전트용 Android CLI 환경을 초기화하고, 설치된 스킬 목록을 확인할 수 있습니다.
공식 에이전트 플러그인도 Antigravity용에 이어 Claude Code와 Codex용이 새로 나왔습니다.

에이전트 경험을 만드는 API 살펴보기​

앱이 에이전트의 도구가 되는 흐름도 이번 서밋의 한 축입니다.
AppFunctions는 앱 기능을 에이전트가 호출할 수 있게 만드는 통합 도구 호출 계층입니다.
이번 서밋에서 AppFunctions가 베타 단계에 들어섰습니다.
에이전트는 함수 이름과 설명만 보고 호출을 결정하므로, 이름과 KDoc이 곧 스키마라는 점을 염두에 두어야 합니다.

/**
 * 코스피 지수 요약 정보를 반환합니다.
 *
 * @param market 조회할 시장 코드입니다.
 */
@AppFunctionDeclaration(isDescribedByKDoc = true)
suspend fun getIndexSummary(
    market: String
): IndexSummary = withContext(Dispatchers.IO) {
    marketRepository.getIndexSummary(market)
}

A2UI for Jetpack Compose는 알파로 공개되었습니다.
에이전트가 텍스트 답변이 아니라 앱 자체 컴포넌트로 만든 인터랙티브 UI를 반환할 수 있게 됩니다.
네이티브 Jetpack Compose 렌더러가 들어가 앱 안에서 자연스럽게 동작합니다.

ML Kit의 새로운 Agentic API도 알파로 공개되었습니다.
Gemini Nano 4를 기반으로 함수 실행과 대화 기록, 오케스트레이션 루프를 자동으로 처리하고 가드레일도 포함합니다.
온디바이스 에이전트를 만들 때 서버 왕복 없이 기기 안에서 루프를 돌릴 수 있다는 점이 특징입니다.

Connected Apps Platform도 함께 소개되었습니다.
앱 서비스를 Gemini가 시스템 AI 에이전트로 동작하는 사용자에게 공유하는 구조입니다.
지금은 프로토타입 단계이며, 프로덕션 게시를 위해서는 미리보기 프로그램 등록이 필요합니다.

Compose 1.13과 적응형 개발 살펴보기​

다가오는 Compose 1.13 stable에는 적응형 레이아웃 지원이 들어갑니다.
Grid와 Flexbox가 stable로 전환되고, Progressive Blur와 Formatted Text가 새로 추가됩니다.
Navigation 3 1.2는 딥 링크 지원과 함께 stable이 되었습니다.
AppState는 Compose의 반응형 모델을 상태 계층까지 확장하는 알파 단계의 building block입니다.
기기 설정이 바뀌어도 상태를 유지하는 구조를 앱과 AI 에이전트가 함께 쓸 수 있게 만드는 것이 목표입니다.

적응형 개발은 폰과 폴더블, 태블릿, 노트북, 차량, XR까지 한 코드베이스로 대응하는 방향으로 정리되었습니다.
Compose adaptive skill이 업데이트되어 기존 Compose UI를 감사하고 키보드 단축키와 커서, 호버 상태, 툴팁을 자동으로 구현합니다.
내비게이션 패턴 이전과 Grid, Flexbox, mediaQuery 기반의 레이아웃 이전도 skill이 다룹니다.
미디어와 카메라 화면을 폴더블의 테이블탑 레이아웃으로 바꾸는 최적화도 포함되었습니다.
내년부터 Google Play는 폴더블에서의 앱 동작을 자세히 살피고, 적응형으로 잘 만든 앱에 더 많은 노출 기회를 줄 예정입니다.
구체적인 스토어 요구사항은 올해 안에 발표될 예정입니다.

@Composable
fun AdaptiveStockList() {
    BoxWithConstraints {
        if (maxWidth > 600.dp) {
            StockGrid()
        } else {
            StockList()
        }
    }
}

XREAL과 함께 XREAL AURA가 공개되었습니다.
Android XR 기반의 첫 유선 XR 글라스입니다.
SceneCore와 ARCore for Jetpack XR, XR Runtime을 비롯한 핵심 Jetpack XR SDK 라이브러리가 stable이 되었습니다.
Android Studio의 Android XR 에뮬레이터도 stable이 되어 실물 기기 없이 XR 글라스 경험을 검증할 수 있습니다.

실무 관점​

MTS 앱에 적용한다면, 단계를 나눠 접근하는 것이 안전합니다.
Rabbit 2의 BYOA는 stable이므로 팀이 이미 쓰는 에이전트를 IDE에 연결하는 것부터 검토할 수 있습니다.
AppFunctions는 베타, A2UI와 ML Kit Agentic API는 알파 단계이므로 프로덕션 노출보다 내부 빌드에서의 검증이 먼저입니다.
AppFunctions에 노출할 함수는 조회처럼 부작용이 없는 것부터 시작하고, 주문이나 이체처럼 돈이 움직이는 동작은 대상에서 빼는 편이 안전합니다.
Compose 1.13의 적응형 기능은 폴더블 대응을 준비하는 팀이라면 미리 살펴볼 만합니다.
내년 Play의 폴더블 평가에 대비해 Compose adaptive skill로 현재 화면을 한 번 감사해 보는 것도 좋습니다.

마치며​

이번 서밋은 에이전트를 IDE에 들이는 것과 앱을 에이전트에 연결하는 것, 두 방향을 동시에 제시했습니다.
적응형 UI까지 합치면, 앞으로의 Android 개발은 폼팩터와 에이전트라는 두 축으로 넓어질 것으로 보입니다.

AppFunctions 베타와 A2UI 알파, 앱이 에이전트와 연결되는 방법

October 29, 2026 · 3 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 28일에 열린 Android Dev Summit 2026에서 공개된 AppFunctions의 베타와 A2UI, ML Kit Agentic API에 대해 설명해드리겠습니다.

배경​

사용자는 앱의 화면을 하나씩 눌러 가며 작업을 마치는 대신, 말로 요청하고 결과를 받는 방식에 익숙해지고 있습니다.
기존 앱은 화면 중심이라, 에이전트가 앱의 기능을 호출할 공식 경로가 없었습니다.
화면 자동화 방식은 깨지기 쉽고, 앱이 의도하지 않은 동작까지 허용할 위험이 있습니다.
AppFunctions는 앱이 스스로 공개한 기능만을 에이전트가 호출하게 만드는 구조입니다.

AppFunctions와 에이전트 API 살펴보기​

AppFunctions 베타​

AppFunctions는 앱의 기능을 온디바이스 또는 시스템 에이전트에 노출하는 통합 도구 호출 계층입니다.
연결 방식은 Model Context Protocol 기반의 Android MCP이며, Android 16 이상 기기에서 동작합니다.
Jetpack 라이브러리는 2026년 10월 21일 기준 1.0.0-beta01이 공개되어 있습니다.
함수는 AppFunction 어노테이션으로 선언하고, KDoc 설명이 도구의 스키마로 함께 전달됩니다.
에이전트는 앱이 공개한 함수만 발견하고 실행하므로, 노출 범위를 앱 개발자가 직접 정할 수 있습니다.

dependencies {
    implementation("androidx.appfunctions:appfunctions:1.0.0-beta01")
    ksp("androidx.appfunctions:appfunctions-compiler:1.0.0-beta01")
}
@AppFunction(isDescribedByKDoc = true)
suspend fun getFavoriteStockPrice(
    symbol: String
): StockPrice {
    // 관심 종목의 현재 시세를 조회하는 함수입니다.
    return repository.getPrice(symbol)
}

A2UI 알파​

에이전트의 답변이 텍스트로만 나오면, 사용자는 다시 앱 화면으로 돌아가 확인해야 합니다.
A2UI는 에이전트가 앱 자체의 컴포넌트로 만든 인터랙티브 화면을 그대로 보여주는 방식입니다.
Jetpack Compose용 네이티브 렌더러가 포함되어 있어, 에이전트 응답이 앱의 UI로 자연스럽게 이어집니다.
현재 알파 단계이며, AppFunctions와 함께 앱의 에이전트 경험을 구성하는 한 축입니다.

ML Kit Agentic API 알파​

온디바이스에서 동작하는 에이전트 기능은 ML Kit의 Agentic API가 담당합니다.
Gemini Nano 4를 기반으로 하며, 함수 실행과 대화 기록 저장, 오케스트레이션 루프 관리, 자동 가드레일을 함께 제공합니다.
앱 안에서 도구를 실행하는 에이전트를 만들 때, 호출과 기록과 안전장치를 직접 구현하지 않아도 됩니다.
AppFunctions로 공개된 기능도 이 API를 통해 발견하고 실행할 수 있습니다.

Connected Apps Platform 프리뷰​

앱의 서비스를 Gemini와 검색까지 연결하는 통로는 Connected Apps Platform 프리뷰가 담당합니다.
Android MCP나 원격 MCP 서버로 연동하고, Google Connected Console에서 등록해 관리합니다.
Google은 Adobe와 Peloton, Experian 등 50개 이상의 파트너 연동이 이미 Gemini 앱에서 동작하고 있다고 밝혔습니다.

실무 관점​

MTS 앱에 적용한다면, 노출할 함수의 범위를 정하는 일이 구현보다 먼저입니다.
주문이나 이체 같은 자금 이동 기능은 에이전트 호출 경로에 두지 않는 것이 안전합니다.
시세 조회나 관심 종목 확인처럼 읽기 전용 기능부터 베타 단계에서 검증하는 순서가 적절합니다.
아직 베타와 알파 단계라 API가 바뀔 수 있으므로, 노출 함수는 별도 모듈로 분리해 교체 비용을 낮추는 것이 좋습니다.

마치며​

AppFunctions는 앱을 화면의 집합이 아니라 에이전트가 호출할 수 있는 기능의 집합으로 바꾸는 시도입니다.
A2UI와 온디바이스 Agentic API가 함께 갖춰지면서, 앱 안에서의 에이전트 경험이 텍스트 응답을 넘어 실제 화면 동작으로 이어지게 되었습니다.

앱이 AI 에이전트의 도구가 된다 — AppFunctions 1.0.0-beta01 살펴보기

October 24, 2026 · 4 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 21일에 공개된 AppFunctions 1.0.0-beta01의 릴리스 노트를 정리해드리겠습니다.

현재 상황​

AppFunctions는 앱의 기능을 AI 에이전트가 발견하고 실행할 수 있게 만드는 Jetpack 라이브러리입니다.
앱이 온디바이스 MCP 서버처럼 동작한다는 비유로 설명되곤 합니다.
사용자가 앱을 직접 열지 않아도, 에이전트가 앱의 함수를 찾아 호출하고 결과를 돌려주는 흐름이 목표입니다.
그동안 알파 단계를 거치며 애너테이션 이름과 서비스 구조가 여러 차례 바뀌었습니다.
이번 beta01은 알파를 벗어난 첫 베타라는 점에서 의미가 있습니다.
아직 stable은 아니지만, API가 안정화 단계에 들어섰다는 신호로 읽을 수 있습니다.

AppFunctions 1.0.0-beta01 살펴보기​

앱 메타데이터 이름 변경​

AppFunctionAppMetadata의 description이 instructions로 바뀌었습니다.
XML 속성 이름도 함께 바뀌었습니다.
MCP의 명명 관례에 맞추기 위한 변경입니다.
앱 수준의 동작 방식과 제약을 에이전트에게 전달하는 필드이므로, 이름을 보고 역할을 짐작하기가 더 쉬워졌습니다.
기존 메타데이터를 쓰고 있었다면 이번 베타에서 이름을 함께 바꿔야 합니다.

isDescribedByKDoc 기본값 제거​

AppFunctionDeclaration, AppFunctionSerializable, AppFunctionSignature에서 isDescribedByKDoc의 기본값이 제거되었습니다.
이제 값을 반드시 명시적으로 지정해야 합니다.
이 값은 KDoc 주석을 에이전트가 읽는 설명으로 쓸지를 결정합니다.
기본값이 사라졌다는 것은, 설명 방식을 개발자가 의식적으로 선택하라는 뜻으로 읽힙니다.
KDoc을 대충 쓰면 에이전트가 함수를 잘못 이해할 수 있으니, 주석이 곧 스키마라는 점을 염두에 두어야 합니다.

@RequiresApi(36)
@AppFunctionServiceEntryPoint(
    serviceName = "PortfolioAppFunctionService",
    appFunctionXmlFileName = "portfolio_app_function_service"
)
abstract class BasePortfolioAppFunctionService : AppFunctionService() {

    /**
     * 보유 종목의 요약 정보를 반환합니다.
     *
     * @param accountId 조회할 계좌의 식별자입니다.
     */
    @AppFunctionDeclaration(isDescribedByKDoc = true)
    suspend fun getPortfolioSummary(
        accountId: String
    ): PortfolioSummary = withContext(Dispatchers.IO) {
        portfolioRepository.getSummary(accountId)
    }
}

위 예시에서 함수는 기본적으로 메인 스레드에서 실행됩니다.
그래서 블로킹 작업이 있다면 suspend 함수로 만들고 백그라운드 디스패처로 전환해야 합니다.
공식 API 레퍼런스에서도 같은 주의사항을 강조하고 있습니다.

그 밖의 API 변경​

AppFunctionName이 androidx.appfunctions.metadata 패키지에서 androidx.appfunctions 패키지로 이동했습니다.
임포트 경로를 정리하지 않으면 컴파일이 깨지니, 베타로 올릴 때 임포트부터 확인하는 편이 좋습니다.
AppFunctionResourceContainer와 AppFunctionTextResource는 실험적 API로 표시되었습니다.
@AppFunctionStringValueConstraint의 정규식 패턴은 android.os.PatternMatcher 기반의 패턴 매처로 대체되었습니다.
테스트 쪽에서는 AppFunctionTestRule이 AppFunctionServiceEntryPoint를 지원하게 되었습니다.
테스트에서 엔트리 포인트를 직접 다룰 수 있게 된 만큼, 함수 단위 검증이 조금 수월해졌습니다.

버그 수정​

자바 라이브러리 디슈가링을 켠 앱에서 java.time 파라미터 타입의 역직렬화가 실패하던 문제가 수정되었습니다.
생성되는 파일 이름에 특정 운영체제에서 허용되지 않는 문자가 들어갈 수 있던 문제도 수정되었습니다.
SDK 37 이상에서 URI 권한이 두 번 부여되던 문제도 함께 수정되었습니다.
어느 하나 거창한 기능은 아니지만, 실무에서 마주치면 원인을 찾기 어려운 유형의 수정입니다.

의존성 선언​

[versions]
appfunctions = "1.0.0-beta01"

[libraries]
appfunctions = { module = "androidx.appfunctions:appfunctions", version.ref = "appfunctions" }
appfunctions-compiler = { module = "androidx.appfunctions:appfunctions-compiler", version.ref = "appfunctions" }
appfunctions-testing = { module = "androidx.appfunctions:appfunctions-testing", version.ref = "appfunctions" }
dependencies {
    implementation(libs.appfunctions)
    ksp(libs.appfunctions-compiler)
    testImplementation(libs.appfunctions-testing)
}

실무 관점​

MTS 앱에 적용한다면, 노출 범위를 좁게 잡는 것이 먼저입니다.
조회처럼 부작용이 없는 함수부터 시작하고, 주문이나 이체처럼 돈이 움직이는 동작은 에이전트 호출 대상으로 두지 않는 편이 안전합니다.
에이전트는 함수 이름과 KDoc만 보고 호출을 결정하므로, 모호한 이름과 부실한 설명은 오호출로 이어질 수 있습니다.
아직 베타 단계이므로 프로덕션 노출은 stable 승격을 기다리는 것이 안전합니다.
그 전에 내부 빌드에서 KDoc 품질과 호출 범위를 먼저 다듬어 두는 편이 좋습니다.

마치며​

이번 베타는 기능 추가보다 API 정리와 안정화에 무게가 실린 릴리스입니다.
베타로 올리는 팀이라면 이름 변경과 필수 지정 항목부터 정리하고, KDoc을 스키마처럼 다듬는 것이 좋습니다.
