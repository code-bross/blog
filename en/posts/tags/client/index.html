Ktor 3.6.1 살펴보기: Android 엔진 크래시 수정과 연결 관리 개선

November 15, 2026 · 3 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.

10월 29일에 공개된 Ktor 3.6.1에 대해 설명해드리겠습니다.
3.6.0 이후 나온 패치 릴리스로, 연결 관리와 요청 취소, 스트리밍, 웹소켓을 중심으로 수정이 들어갔습니다.

배경​

Ktor 클라이언트는 안드로이드 앱에서 네트워크 계층으로 널리 쓰입니다.
3.6.0이 9월에 나온 뒤 한 달 만에 3.6.1 패치가 이어졌습니다.
기능 추가보다는 엔진 동작을 바로잡는 수정이 중심입니다.
안드로이드 엔진과 관련된 크래시 수정이 세 건 포함되어 있어 실무에서 바로 확인이 필요합니다.

Ktor 3.6.1 살펴보기​

Android 엔진 수정​

이번 패치에서 안드로이드 엔진과 직접 관련된 수정은 세 가지입니다.
첫 번째는 응답 읽기 취소 시 크래시가 나는 문제입니다.
두 번째는 메인 스레드에서 채널을 닫아 NetworkOnMainThreadException이 나는 문제입니다.
세 번째는 플러그인 실행 중 로거 초기화로 DiskReadViolation이 나는 문제입니다.
세 가지 모두 요청 취소와 스레드 경계에서 발생합니다.
취소 경로를 자주 타는 화면에서는 릴리스 전에 동작을 확인할 필요가 있습니다.

CIO 엔진과 연결 관리​

CIO 엔진에서는 TLS 종료 과정의 경합이 수정되었습니다.
close_notify가 마지막 레코드와 동시에 쓰이면서 TLS 출력과 메모리 풀이 손상되는 문제였습니다.
응답을 쓰기 전에 실패한 keep-alive 연결이 멈추는 문제도 고쳐졌습니다.
CPU 부하가 높을 때 서버가 빈 응답으로 연결을 닫는 문제도 함께 수정되었습니다.
클라이언트 쪽에서는 연결 누수 수정이 포함되었습니다.

리다이렉트와 HTTP 규정 준수​

리다이렉트 처리에서는 상대 경로의 점 세그먼트가 정규화되지 않는 문제가 수정되었습니다.
If-None-Match가 있을 때 If-Modified-Since를 무시하도록 ETag 동작이 바뀌었습니다.
3.6.0에서 사라졌던 잘못된 경로에 대한 BadRequestException도 다시 던져집니다.
이 항목들은 서버 동작에 가깝지만, 클라이언트가 받는 응답을 해석하는 기준과 이어집니다.

네이티브 소켓과 Netty​

네이티브에서 허용된 TCP 소켓에 TCP_NODELAY가 기본으로 켜지지 않는 문제가 수정되었습니다.
JVM과 달리 네이티브에서는 작은 패킷이 Nagle 알고리즘 때문에 지연될 수 있었습니다.
Netty에서는 delay 호출 성능이 개선되었습니다.
두 항목 모두 지연 시간에 직접 영향을 주는 변경입니다.

버전 올리기​

Version Catalog에서 버전을 교체하면 패치를 적용할 수 있습니다.

[versions]
ktor = "3.6.1"

[libraries]
ktor-client-core = { module = "io.ktor:ktor-client-core", version.ref = "ktor" }
ktor-client-android = { module = "io.ktor:ktor-client-android", version.ref = "ktor" }
ktor-client-content-negotiation = { module = "io.ktor:ktor-client-content-negotiation", version.ref = "ktor" }
ktor-client-logging = { module = "io.ktor:ktor-client-logging", version.ref = "ktor" }
ktor-serialization-kotlinx-json = { module = "io.ktor:ktor-serialization-kotlinx-json", version.ref = "ktor" }

Android 엔진으로 클라이언트를 만드는 예시는 다음과 같습니다.

val client = HttpClient(Android) {
    install(ContentNegotiation) {
        json()
    }
    install(Logging) {
        logger = Logger.DEFAULT
        level = LogLevel.INFO
    }
}

실무 관점​

패치 릴리스라도 네트워크 계층 변경은 검증 없이 올리지 않는 것이 안전합니다.
이번 패치에서는 요청 취소 경로와 연결 누수가 핵심입니다.
화면 이탈 시 요청을 취소하는 흐름이 있다면 취소 후 크래시가 나지 않는지 확인합니다.
장시간 유지되는 연결이 있는 화면에서는 연결 수 변화를 함께 봅니다.
StrictMode를 켠 디버그 빌드에서 디스크 읽기 위반이 사라졌는지도 확인합니다.

마치며​

3.6.1은 기능을 더하는 릴리스가 아니라 동작을 바로잡는 릴리스입니다.
안드로이드 엔진 크래시 수정이 포함되어 있어 클라이언트 버전을 올릴 때 우선 검토할 만합니다.
