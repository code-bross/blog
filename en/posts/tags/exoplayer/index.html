Media3 1.12.0-beta01 살펴보기 — CodecDB와 메모리 절감, JSpecify 마이그레이션

November 13, 2026 · 4 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.

11월 11일에 공개된 Media3 1.12.0-beta01에 대해 설명해드리겠습니다.

배경​

Media3 1.12.0은 10월 21일 alpha01, 10월 26일 alpha02를 거쳐 11월 11일 beta01에 도달했습니다.
alpha01에서는 플래그 레지스트리와 Display P3 지원이 들어왔고, alpha02에서는 Play services 이펙트 모듈이 추가되었습니다.
지난달 27일 글에서 이 두 알파 버전을 다룬 바 있습니다.
beta는 API 표면이 확정되는 단계입니다.
이번 beta01에서는 인코더 설정을 추천하는 CodecDB가 새로 들어왔고, 메모리 사용량을 줄이는 변경과 JSpecify 마이그레이션이 함께 포함되었습니다.

Media3 1.12.0-beta01 살펴보기​

Transformer에 들어온 CodecDB​

Transformer에 androidx.media3.transformer.codecdb 패키지의 CodecDB가 추가되었습니다.
단말에서 측정된 인코더 품질 데이터를 바탕으로 비디오 인코더 설정을 추천합니다.
추천 대상은 코덱과 인코더 설정, 비트레이트입니다.
트랜스코딩 품질을 단말마다 일일이 튜닝하지 않아도 됩니다.
단말별 인코더 성능 편차가 큰 환경에서 유용합니다.

샘플 버퍼 메모리 사용량 절감​

C.DEFAULT_BUFFER_SEGMENT_SIZE가 65536에서 65520으로 줄었습니다.
버퍼 할당 하나가 바이트 배열 객체 헤더까지 포함해 OS 페이지 단위에 딱 맞게 들어갑니다.
4 KiB 페이지 단말에서는 샘플 버퍼 메모리가 약 6% 줄어듭니다.
16 KiB 페이지 단말에서는 약 20% 줄어듭니다.
재생 동작을 바꾸지 않고 메모리만 줄이는 변경입니다.

JSpecify 마이그레이션과 Kotlin 코드에 미치는 영향​

androidx.media3.common.util.NullableType이 JSpecify의 org.jspecify.annotations.Nullable로 교체되었습니다.
UnknownNull도 JSpecify 널니스 어노테이션으로 대체되어 제거되었습니다.
이 변경은 Kotlin 코드에도 직접 영향을 줍니다.
RunnableFutureTask를 상속받는 Kotlin 서브클래스는 결과 타입이 널 가능하면 타입 인자도 널 가능으로 명시해야 합니다.
예를 들어 RunnableFutureTask<Void?, Exception>처럼 씁니다.
CompositeMediaSource도 마찬가지이며, 널 가능한 자식 소스 ID를 쓰는 경우 CompositeMediaSource<Void?>처럼 명시합니다.
Media3 클래스를 상속해 쓰는 코드가 있다면 빌드 시점에 확인이 필요합니다.

Player.listen 스레드 문제 수정​

Player.listen이나 Player.listenTo를 플레이어의 애플리케이션 스레드가 아닌 스레드에서 취소하면 IllegalStateException이 발생했습니다.
오류 메시지는 "Player is accessed on the wrong thread."입니다.
Compose UI 테스트 종료 시점에 자주 마주치는 상황이었습니다.
이번 beta01에서 이 문제가 수정되었습니다.

Compose UI에 들어온 자막 슬롯​

ContentFrame과 Player에 subtitles 컴포저블 슬롯이 추가되었습니다.
media3-ui-compose-material3에서는 비트맵 자막과 가로 텍스트 자막 큐를 기본으로 렌더링합니다.
SubtitleView.setTextDirectionHeuristic도 추가되어 양방향 자막 텍스트의 줄 바꿈 기준을 바꿀 수 있습니다.
한편 Player의 모든 컨트롤 슬롯에 애니메이션이 적용되면서 PlayerDefaults.TopControls와 CenterControls, BottomControls에서 visible 파라미터가 제거되었습니다.
불안정한 API에 대한 변경이라 커스텀 컨트롤을 쓰는 화면은 빌드 확인이 필요합니다.

광고와 캐스트 변경점​

IMA 확장에서는 인터랙티브 광고가 재생 중 비디오 플레이어 뷰를 리사이즈할 수 있게 되었습니다.
AdViewProvider.getAdVideoView()가 광고 재생 중 크기를 바꿀 수 있는 비디오 컨테이너 뷰를 제공합니다.
ImaAdsLoader.requestAds에는 AdViewProvider를 받는 오버로드가 추가되었고, ViewGroup을 받는 기존 오버로드는 Deprecated 처리되었습니다.

// 변경 전: ViewGroup을 받는 오버로드 (Deprecated)
// ImaAdsLoader.requestAds(DataSpec, Object, ViewGroup)

// 변경 후: AdViewProvider를 받는 오버로드
// ImaAdsLoader.requestAds(DataSpec, Object, AdViewProvider)

Cast 확장에서는 시스템 출력 전환기 설정이 추가되었습니다.
CastParams.Builder.setSystemOutputSwitcherEnabled로 선언 없이 출력 전환기에 Cast 기기를 표시할지 정할 수 있습니다.
API 37 이상을 타깃으로 하고 API 37 이상 단말에서 실행되는 앱은 기본적으로 활성화됩니다.
play-services-cast-framework 의존성은 23.0.0으로 업데이트되었습니다.

의존성 선언​

beta01을 적용하는 의존성 선언은 다음과 같습니다.

dependencies {
    val media3Version = "1.12.0-beta01"
    implementation("androidx.media3:media3-exoplayer:$media3Version")
    implementation("androidx.media3:media3-transformer:$media3Version")
    implementation("androidx.media3:media3-ui-compose-material3:$media3Version")
}

실무 관점​

beta는 API가 확정되는 단계지만 정식 릴리스가 아닙니다.
운영 앱에는 1.11.1 stable을 유지하고, beta01은 별도 브랜치에서 검증하는 것이 좋습니다.
JSpecify 마이그레이션은 Media3 클래스를 상속해 쓰는 코드를 건드릴 수 있습니다.
적용 전에 해당 코드의 컴파일을 먼저 확인하는 것이 좋습니다.
CodecDB는 단말별 인코더 편차를 직접 다뤄야 하는 트랜스코딩 기능에서 검토합니다.
자막 슬롯과 컨트롤 애니메이션 변경은 커스텀 플레이어 UI를 쓰는 화면부터 빌드 확인이 필요합니다.

마치며​

Media3 1.12.0-beta01은 CodecDB라는 새 기능과 함께 메모리 절감, JSpecify 정리, 스레드 문제 수정을 한 번에 담았습니다.
beta 단계인 만큼 별도 환경에서 검증한 뒤, 정식 릴리스 시점에 적용 여부를 결정하는 것이 좋습니다.

Media3 1.12.0 알파 — 플래그 레지스트리와 Play services 이펙트

October 27, 2026 · 3 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 21일의 alpha01과 10월 26일의 alpha02로 공개된 Media3 1.12.0 알파 변경 사항에 대해 설명해드리겠습니다.

배경​

Media3는 ExoPlayer를 중심으로 재생, 세션, 변환, 이펙트를 묶은 미디어 라이브러리입니다.
현재 안정 버전은 1.11.1이며, 1.12.0은 알파 단계에서 다음 변경을 준비하고 있습니다.
공식 Media3 릴리스 노트를 기준으로 실무에 닿는 변경만 정리합니다.
알파 API는 정식 출시 전에 바뀔 수 있으므로, 적용 전에 변경 범위를 확인하는 것이 중요합니다.

Media3 1.12 알파에서 달라진 것​

중앙 플래그 레지스트리​

alpha01에서 실험적 기능 플래그를 관리하는 중앙 Flags 레지스트리가 추가되었습니다.
기존에 흩어져 있던 실험적 API를 플래그 API로 단계적으로 전환하는 기반이 됩니다.
카나리아 모드를 켜는 진입점도 함께 제공되어, 실험 기능을 단계적으로 공개하는 흐름을 만들 수 있습니다.
플래그가 늘어날수록 어떤 실험이 켜져 있는지 한곳에서 파악할 수 있다는 점이 실무적으로 의미가 있습니다.

Display P3 색 공간 지원​

C.COLOR_SPACE_DISPLAY_P3가 추가되고, MediaFormatUtil과 ColorInfo의 ISO 색상 매핑에서 Display P3가 지원됩니다.
광색역 콘텐츠를 다루는 화면에서는 색 공간 정보가 형식 변환 과정에서 유지되는지 확인해 볼 만합니다.
Ultra HDR 프레임 추출 시 BT.2020 색상이 sRGB로 잘리던 문제도 함께 개선되었습니다.
범위를 벗어난 색은 자르는 대신 부드럽게 압축되어 SDR 기본 이미지에 담깁니다.

재생 목록 메타데이터 확장​

MediaMetadata에 재생 목록 식별자와 카테고리가 추가되었습니다.
재생 목록 단위로 식별하고 분류하는 정보가 메타데이터 자체에 들어간다는 뜻입니다.
세션 쪽에서는 재생 목록 식별자, 제목, 아트워크, 카테고리를 채우는 엑스트라 키도 함께 추가되었습니다.

val metadata = MediaMetadata.Builder()
    .setPlaylistId("playlist-market-briefing")
    .setCategories(listOf("market", "briefing"))
    .build()

기본 동작 변경​

setLoadOnlySelectedTracks(true)가 기본값이 되었습니다.
선택되지 않은 비디오와 이미지 트랙은 로드하지 않으므로 메모리가 절약됩니다.
오디오와 텍스트 트랙은 항상 로드되어, 끊김 없는 트랙 전환을 유지합니다.
재생 중 선택되지 않았던 비디오 트랙을 새로 켜면 추가 버퍼링이 생길 수 있다는 점은 주의해야 합니다.
DASH 다중 기간 재생에서 다음 기간의 첫 청크 로드가 실패하면 재생이 멈추던 문제도 수정되었습니다.

Play services 이펙트 모듈​

alpha02에서는 새로운 media3-effect-play-services 모듈이 추가되었습니다.
비디오 향상 기능을 제공하는 EnhancementSessionDecorator와 음원 분리 기능을 제공하는 StudioSoundAudioProcessor가 포함됩니다.
이펙트 쪽에서는 스튜디오 사운드 기반 음원 분리 프로세서 구현도 함께 들어갔습니다.
Play services 모듈에 의존하는 기능이라, 단말의 Play services 제공 여부를 전제로 설계해야 합니다.

알파를 적용하는 의존성 선언은 다음과 같습니다.

dependencies {
    implementation("androidx.media3:media3-exoplayer:1.12.0-alpha02")
    implementation("androidx.media3:media3-effect-play-services:1.12.0-alpha02")
}

실무 관점​

알파 라이브러리는 프로덕션 모듈에 바로 올리기보다 별도 브랜치에서 검증하는 것이 안전합니다.
트랙 로드 기본값 변경은 재생 화면의 메모리와 전환 동작에 직접 영향을 주므로, 기존 재생 시나리오로 회귀 테스트를 먼저 돌려보는 것이 좋습니다.
자막 시간 오프셋 기능은 사이드로드 자막의 싱크를 맞추는 용도로, 재생을 중단하지 않고 교체할 수 있습니다.
MTS처럼 미디어가 부가 기능인 앱에서는, 재생 모듈 전체를 올리기보다 필요한 아티팩트만 골라 적용하는 편이 의존성 부담을 줄입니다.

마치며​

Media3 1.12 알파는 새 재생 기능보다 플래그 관리 체계와 색 공간, 메타데이터 같은 기반 정리에 무게가 실려 있습니다.
Play services 이펙트 모듈은 알파 단계의 새로운 축이라, 정식 출시 과정을 지켜보며 검증 범위를 정하는 것이 좋습니다.
