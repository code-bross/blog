Jetpack Compose 1.13 안정화 버전 살펴보기

November 25, 2026 · 4 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.

2026년 11월 18일에 공개된 Jetpack Compose November '26 릴리스에 대해 설명해드리겠습니다.

이번 릴리스는 코어 Compose 모듈 전반이 1.13으로 안정화되었습니다.
그래픽, 텍스트, 레이아웃, 성능 영역에 걸쳐 새로운 기능이 추가되었고, 주의해야 할 변경 사항도 함께 포함되었습니다.

배경​

기존에는 점진적 블러나 다각형 모양을 구현하려면 별도의 라이브러리를 직접 사용해야 했습니다.
다각형 모양은 graphics-shapes 의존성을 추가하고, 픽셀 크기에 맞는 도형을 만든 뒤 경로로 변환하는 과정이 필요했습니다.
또한 Flow 레이아웃과 ConstraintLayout 등 여러 레이아웃 방식이 공존하면서 선택 기준이 모호한 경우도 있었습니다.
이번 릴리스는 이런 영역을 정리하고, 자주 쓰이는 패턴을 기본 기능으로 끌어올렸습니다.

Compose 1.13 살펴보기​

업데이트를 적용하려면 Compose BOM을 2026.11.01로 올립니다.
이 업그레이드에는 Kotlin 2.2 이상과 compileSdk 37.1이 필요합니다.

dependencies {
    implementation(platform("androidx.compose:compose-bom:2026.11.01"))
}

점진적 블러​

Compose 1.13에서는 요소가 선명한 상태에서 흐릿한 상태로 자연스럽게 전환되는 점진적 블러를 지원합니다.
Modifier.blur의 람다 형태와 BlurRadiusSpec을 사용합니다.
선형 그라데이션, 방사형 그라데이션, 커스텀 AGSL 셰이더를 이용한 블러 맵까지 표현할 수 있습니다.

Modifier.blur {
    blurRadiusSpec = BlurRadiusSpec.linearGradient(
        start = DpOffset.Zero,
        end = DpOffset(size.width, size.height),
        stops = listOf(
            BlurStop(fraction = 0f, radius = 0.dp),
            BlurStop(fraction = 0.5f, radius = 0.dp),
            BlurStop(fraction = 0.75f, radius = 14.dp),
            BlurStop(fraction = 1f, radius = 28.dp),
        ),
    )
}

헤더 이미지의 하단 가장자리를 배경에 녹이는 효과나, 터치 위치를 따라가는 스포트라이트 효과에 활용할 수 있습니다.
다이얼로그와 팝업에도 블러 관련 속성을 직접 지정할 수 있게 되었습니다.
DialogProperties에서는 blurBehindRadius와 backgroundBlurRadius, scrimAlpha, windowShape을 설정할 수 있습니다.

다각형 모양과 모핑​

PolygonShape과 MorphPolygonShape이 androidx.compose.foundation에 추가되었습니다.
PolygonShape은 일반적인 Compose Shape이므로 Modifier.clip이나 컴포넌트의 shape 파라미터에 그대로 사용할 수 있습니다.
레이아웃 크기에 맞게 자동으로 조정되므로 별도의 크기 계산이 필요 없습니다.
MorphPolygonShape은 리컴포지션 없이 진행률 람다를 읽어 두 다각형 모양 사이를 애니메이션으로 전환합니다.

var recording by remember { mutableStateOf(false) }
val progress by animateFloatAsState(if (recording) 1f else 0f)
val shape = remember {
    MorphPolygonShape(
        start = PolygonShape.circle(),
        end = PolygonShape.star(
            numPoints = 9,
            innerRadiusRatio = 0.8f,
            outerRounding = CornerRounding.fraction(0.5f),
        ),
        progress = { progress },
    )
}

Box(
    Modifier
        .size(96.dp)
        .clip(shape)
        .background(MaterialTheme.colorScheme.primary)
        .clickable { recording = !recording }
)

Material 3 1.5.0​

Compose Material 3 버전 1.5.0이 안정화되었습니다.
Slider와 RangeSlider는 SliderState를 사용하는 상태 기반 모델로 전환되었습니다.
ToggleButtons와 WavyProgressIndicators, TimePickers 같은 새로운 컴포넌트가 추가되었습니다.
실험적 애너테이션은 120개에서 58개로 52% 줄었습니다.
이와 함께 Compose Material 2 라이브러리는 더 이상 적극적으로 유지보수되지 않으며, Material 3으로의 마이그레이션이 권장됩니다.

텍스트와 레이아웃​

값 기반 BasicTextField와 Material 2의 TextField는 공식적으로 deprecated 되었습니다.
상태 기반 BasicTextField와 TextFieldState API로의 전환이 권장됩니다.
LineHeightStyle.Mode.PerLine이 추가되어, 다국어 텍스트에서 줄마다 높이를 독립적으로 계산할 수 있게 되었습니다.
FlexBox와 Grid 레이아웃은 Compose 1.11에서 실험적으로 도입된 뒤 이번 릴리스에서 안정화되었습니다.
FlexBox는 Flow 레이아웃을 대체하며, 새 코드에서는 FlowRow와 FlowColumn 대신 FlexBox 사용이 권장됩니다.
반면 Compose용 ConstraintLayout과 MotionLayout은 deprecated 되었습니다.

성능​

computedStateOf는 derivedStateOf의 가벼운 대안으로 도입되었습니다.
계산 결과를 캐시하지 않으므로, 자주 변경되는 상태에서 조건 검사나 필터링을 수행할 때 오버헤드가 적습니다.
무거운 계산이나 캐시가 필요한 경우에는 derivedStateOf를 계속 사용하는 것이 권장됩니다.
LazyLayoutCacheWindow도 안정화되어, 지연 레이아웃의 윈도우 기반 프리페치가 기본 동작이 되었습니다.

실무 관점​

업데이트 전에 Kotlin 버전과 compileSdk 요구 사항을 먼저 확인해야 합니다.
Kotlin 2.2 이상과 compileSdk 37.1을 충족하지 못하면 빌드가 실패합니다.
값 기반 텍스트 필드와 ConstraintLayout을 사용 중인 화면은 deprecated 경고를 확인하고 마이그레이션 계획을 세워야 합니다.
특히 MTS처럼 화면이 많은 프로젝트에서는 텍스트 필드 마이그레이션을 한 번에 적용하기보다 화면 단위로 나누어 진행하는 것이 안전합니다.

마치며​

Compose 1.13은 그래픽 표현력과 레이아웃 선택지를 넓히면서도, 오래된 API를 정리한 릴리스입니다.
BOM 업데이트와 함께 deprecated 항목을 점검하면 안정적으로 적용할 수 있을 것으로 보입니다.

Android Dev Summit 2026 미리보기, Android 18과 새 그래픽 기능 예고

October 23, 2026 · 2 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
10월 28일에 열리는 Android Dev Summit 2026의 아젠다와 Android 18 예고에 대해 설명해드리겠습니다.

배경​

Android Dev Summit은 Google의 Android 개발자 컨퍼런스로, 2022년 이후 열리지 않고 있었습니다.
2026년 10월 28일부터 29일까지 이틀간 마운틴뷰의 Bay View 캠퍼스에서 열리며, 런던에서는 10월 28일 Extended 행사가 함께 진행됩니다.
기조연설은 Android 리더십이 맡아 최신 기능과 업데이트를 설명합니다.

Android Dev Summit 2026 아젠다 살펴보기​

이번 서밋은 네 개의 트랙으로 구성됩니다: AI experiences, Android XR, Apps foundation, Tools and performance.
가장 주목받는 세션은 Elevate your apps with the latest graphics features in Jetpack Compose and Android 18입니다.
Jetpack Compose의 최신 그래픽 기능을 둘러보고, 메시 그라디언트(mesh gradient)부터 프로그레시브 블러(progressive blur)까지 새로운 비주얼 효과를 만드는 방법을 다룹니다.
여기에 Android 18의 새로운 그래픽 기능이 함께 언급되어, Android 18에서 강력한 그래픽 기능이 제공될 것임을 예고했습니다.
성능 파트에서는 배터리 수명이나 프레임 레이트를 희생하지 않고 그래픽 성능을 개선하는 방법도 함께 다룹니다.
10월에 Android 18이 언급되는 것은 예년 일정에 비춰 매우 이른 시점입니다. 참고로 Android 16의 테스트는 전년도 11월에 시작되었습니다.
아직 Android 18의 발표 시점이나 프리뷰 제공 여부는 확인되지 않았습니다.

AI와 Android XR 트랙​

AI 관련 세션에서는 앱을 Gemini, 검색, Android intelligence system에 연결하는 방법을 다룹니다.
Android Context Engine을 활용해 에이전트가 여러 앱에 걸친 작업을 조율하고, 능동적인 경험을 제공하는 구조도 소개됩니다.
Android XR 트랙에서는 Gemini Nano 4 기반의 스마트 안경용 오디오 우선 경험을 만드는 세션이 포함되어 있습니다.

실무 관점​

MTS 앱 관점에서는 그래픽 성능 세션이 실질적입니다.
Compose에서 고급 비주얼 효과를 사용할 때 프레임 레이트와 배터리 소모를 함께 고려하는 가이드가 나오므로, 차트나 애니메이션 화면을 운영 중이라면 세션 내용을 체크할 만합니다.
AI 트랙은 앱 기능과 직접 연결되는 부분보다 플랫폼 방향성 파악용으로 참고하면 됩니다.

마치며​

Android 18에 대한 공식 발표는 아직 없지만, 그래픽 기능이 첫 단서로 등장했습니다.
서밋이 끝나는 대로 주요 세션 내용을 정리해 후속 글로 공유하겠습니다.

Compose 1.13.0-beta01 정리 — Dp.Unspecified가 리컴포지션을 막던 버그 수정

October 8, 2026 · 3 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 7일 공개된 Compose 1.13.0-beta01에 대해 설명해드리겠습니다.

배경​

Compose의 stable 채널 최신 버전은 1.12.1이고, 1.13은 베타 단계에 있습니다.
이번 글에서는 Compose Runtime 릴리스 노트를 기준으로, runtime에서 실무에 닿는 변경만 추려서 정리하겠습니다.
특히 공용 컴포넌트를 많이 사용하는 코드베이스에서는 리컴포지션 관련 수정이 체감 성능에 영향을 줄 수 있습니다.

Compose 1.13.0-beta01 살펴보기​

Kotlin 2.2 타깃으로 상향​

1.13부터 Compose 라이브러리는 Kotlin 2.2를 타깃으로 빌드되며, kotlinc 2.2가 필요합니다.
버전 카탈로그에서 Compose BOM만 올리는 습관이 있다면, Kotlin 플러그인 버전이 뒤처진 모듈에서 먼저 걸릴 수 있으니 함께 확인하는 것이 좋습니다.

Dp.Unspecified를 받는 컴포저블이 스킵되지 않던 버그​

Float.NaN이나 Double.NaN을 인자로 받는 @Composable은 인자가 그대로여도 스킵되지 않고 매번 리컴포지션되는 버그가 있었습니다.
Dp.Unspecified가 내부적으로 Float.NaN 기반이기 때문에, 선택적 간격이나 크기를 Dp.Unspecified 기본값으로 받는 공용 컴포넌트가 조용히 리컴포지션 비용을 치르고 있었던 것입니다.

// 이런 공용 컴포넌트가 인자 변화가 없어도 스킵되지 않을 수 있었다
@Composable
fun PriceRow(
    label: String,
    topPadding: Dp = Dp.Unspecified
) { /* ... */ }

사내 디자인 시스템처럼 공용 컴포넌트에 Dp.Unspecified 기본값이 흔한 코드베이스라면, 1.13 stable이 나올 때 체감 성능이 좋아질 수 있습니다.

computedStateOf 계산 블록은 읽기 전용으로 강제​

computedStateOf의 계산 블록 안에서 상태에 쓰면 이제 IllegalStateException이 발생합니다.
기존에 계산 블록 안에서 쓰기까지 하던 코드가 있었다면 런타임에서 바로 드러나므로, 베타를 올리는 모듈부터 확인이 필요합니다.

그 외 버그 픽스​

  • CompositionObserver가 컴포지션 패스마다 한 번만 해석되고, 교체는 다음 패스부터 적용됩니다. movable content 삽입 시에도 begin/end 콜백이 보고됩니다.
  • movableContent 이동 시 래퍼 그룹 슬롯이 남아 있던 LinkComposer 메모리 누수를 고쳤습니다.
  • lifecycle-runtime 의존성이 2.10.0으로 올라갔습니다. 번들된 lifecycle lint 검사는 AGP 9.5.0-alpha04 이상과 맞물려 있으니, AGP 베타 채널을 쓰는 프로젝트는 같이 보는 것이 좋습니다.
  • ComposeTracer를 메인 스레드 밖에서도 쓸 수 있게 됐습니다.

실무에서 주의할 점​

1.12.1 stable은 1.12.0에서 변경이 없는 버전이라, 운영 앱은 stable 유지가 무난합니다.
베타는 성능 검증이 필요한 화면 위주로 먼저 올려 보고, 앱 전체 확대는 stable 이후가 안전합니다.
공용 컴포넌트를 많이 쓰는 MTS 특성상 리컴포지션 이슈가 체감되는 화면부터 적용해 보는 것이 좋습니다.

마치며​

이번 베타의 핵심은 Dp.Unspecified 기본값을 받는 공용 컴포넌트의 불필요한 리컴포지션을 막은 수정입니다.
stable이 공개되면 공용 컴포넌트 비중이 높은 프로젝트부터 우선 적용해 보시기 바랍니다.
