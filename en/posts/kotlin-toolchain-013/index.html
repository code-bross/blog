Kotlin Toolchain 0.13 살펴보기 — kotlin new와 SwiftPM 의존성

November 10, 2026 · 4 min read
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 7일에 공개된 Kotlin Toolchain 0.13에 대해 설명해드리겠습니다.
이번 릴리스는 프로젝트 생성과 SwiftPM 의존성 지원이 중심입니다.

배경​

Kotlin Multiplatform을 시작할 때는 플랫폼마다 도구 설치와 빌드 설정을 따로 익혀야 합니다.
Android 개발자가 iOS를 처음 다루면 Xcode와 시뮬레이터 설정에서 시간을 쓰게 됩니다.
Kotlin Toolchain은 환경 설정부터 빌드와 테스트, 발행까지 한 곳에서 처리하는 단일 CLI입니다.
Amper 프로젝트에서 이어진 도구이며, 올해 초 Alpha 단계로 승격되었습니다.
0.13부터 JetBrains는 대부분의 신규 KMP 프로젝트에 Toolchain을 권장합니다.
다만 아직 0.x 버전이라, 기존 Gradle 프로젝트의 이주는 아직 권장하지 않습니다.

Kotlin Toolchain 0.13 살펴보기​

kotlin new으로 프로젝트 만들기​

0.13에는 kotlin new 명령이 새로 들어왔습니다.
Kotlin Multiplatform Wizard와 비슷한 대화형 흐름으로 프로젝트를 만듭니다.
첫 번째 질문에서 앱 종류를 고르고, 두 번째 단계에서 타깃 플랫폼을 고릅니다.
기존 kotlin init 명령도 남아 있습니다.
kotlin init은 kotlin new와 같은 동작으로 바뀌었고, 현재 디렉터리에 바로 파일을 만듭니다.
이미 Toolchain을 쓰고 있다면 kotlin update 명령으로 0.13으로 올릴 수 있습니다.

# 대화형 흐름으로 새 프로젝트를 만듭니다
kotlin new

# 이미 설치된 Toolchain을 0.13으로 올립니다
kotlin update

iOS 온보딩 매끄럽게 하기​

깨끗한 머신에서 iOS 앱을 설정하는 과정이 한결 매끄러워졌습니다.
Xcode 라이선스 동의와 첫 실행 상태에 대한 진단 메시지가 명확해졌습니다.
iOS 시뮬레이터 런타임은 필요할 때 자동으로 내려받습니다.
시뮬레이터가 하나도 없으면 자동으로 만듭니다.
CLI의 TUI에는 다운로드 진행률 막대도 표시됩니다.
JDK와 Android SDK 구성 요소, 컴파일러를 내려받을 때도 같은 막대가 나옵니다.

Android SDK 자동 프로비저닝 맞추기​

이전 버전에서는 Android SDK가 kotlin build나 kotlin run을 실행할 때만 자동으로 준비되었습니다.
프로젝트를 IDE에서 먼저 열면 SDK가 없어서 설정 오류가 날 수 있었습니다.
0.13부터는 CLI와 IDE의 동작이 맞춰졌습니다.
IDE에서 프로젝트를 가져올 때도 빠진 Android SDK 구성 요소가 자동으로 준비됩니다.
네임스페이스와 애플리케이션 ID 검증도 엄격해졌습니다.
com.example.app 같은 샘플 ID로 실수로 앱이나 라이브러리를 발행하는 일을 막습니다.

SwiftPM 의존성 가져오기​

0.13부터 Apple 플랫폼용 Swift Package Manager 의존성을 쓸 수 있습니다.
Apple 플랫폼을 지원하는 모듈에서 SwiftPM 의존성을 선언하면 됩니다.
가져온 Objective-C API는 swiftPMImport 접두사와 모듈 이름으로 이름이 지어집니다.
로컬 SwiftPM 패키지는 localSwiftPackage 키로 연결합니다.
멀티플랫폼 라이브러리를 발행할 때는 Compose Resources와 SwiftPM 의존성 메타데이터도 함께 발행됩니다.

product: ios/app
dependencies:
  - swiftPackage:
      repository: "https://github.com/firebase/firebase-ios-sdk.git"
      version: "12.17.0"
      products: [ "FirebaseCore", "FirebaseFirestore", "FirebaseAnalytics" ]
// app/src/app.kt
import swiftPMImport.app.FIRAnalytics
import swiftPMImport.app.FIRApp

Kotlin/Native 컴파일러 캐시로 재빌드 빠르게 하기​

Kotlin/Native 재빌드가 빨라졌습니다.
컴파일된 네이티브 의존성을 캐시에 저장하고 빌드와 프로젝트를 넘어서 재사용합니다.
프로젝트 코드는 파일 단위 캐시를 써서 링크할 때 바뀐 부분만 다시 컴파일합니다.
캐시가 채워지면 작은 수정에는 적은 작업만으로 충분해집니다.
이 기능은 settings.kotlin.compileIncrementally 설정을 사용합니다.
최적화하지 않은 디버그 바이너리에서 동작하고, .klib 파일로의 컴파일은 계속 전체 컴파일로 진행됩니다.

IDE 동기화 상태와 에이전트 워크플로 확인하기​

IDE 에디터 안에서 현재 동기화 상태를 볼 수 있게 되었습니다.
동기화가 어디까지 진행됐는지 에디터를 벗어나지 않고 확인할 수 있습니다.
Toolchain은 처음부터 AI 에이전트와 함께 쓰기 좋게 설계되었습니다.
선언형 설정과 명확한 오류 메시지가 에이전트 작업의 기반이 됩니다.
0.13에서는 Hot Reload MCP 서버와 전용 에이전트 스킬도 들어왔습니다.
JetBrains의 내부 측정에서는 에이전트가 Toolchain 프로젝트를 더 안정적으로 만들고 토큰도 덜 쓴다고 합니다.

실무 관점​

Toolchain 0.13은 새로 시작하는 KMP 프로젝트에 적용하는 것이 좋습니다.
기존 Gradle 프로젝트를 당장 옮기는 일은 아직 권장되지 않습니다.
Swift Export 지원과 스토어 발행 자동화는 로드맵에 남아 있습니다.
Toolchain은 Alpha 단계라, 앞으로의 변경에서 프로젝트 수정이 필요할 수 있습니다.
Android만 다루는 MTS 앱에는 당장 적용할 대상이 아닙니다.
KMP를 새로 검토할 때 진입 도구로 알아두는 것이 실무적인 쓰임입니다.
SwiftPM 의존성을 쓸 때는 한 가지에 주의해야 합니다.
CryptoKit처럼 Swift 전용 API는 Kotlin에서 바로 부를 수 없습니다.
Objective-C로 노출되는 작은 Swift 래퍼 패키지를 먼저 만들어야 합니다.

마치며​

0.13은 kotlin new와 SwiftPM 지원으로 KMP 시작 지점을 한층 낮췄습니다.
신규 프로젝트에서 먼저 써 보고, 기존 프로젝트 이주는 로드맵이 채워질 때까지 기다리는 것이 좋습니다.
