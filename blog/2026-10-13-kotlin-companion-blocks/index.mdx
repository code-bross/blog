### 배경

`TAG` 하나, `newInstance()` 하나를 선언할 때마다 `companion object`를 만들고 `Companion` 싱글턴이 따라붙는 구조가 반복되어 왔습니다.<br/>
JetBrains는 2026년 9월 30일 발표한 [The Companions to Come](https://blog.jetbrains.com/kotlin/2026/09/the-companions-to-come/) 글에서 이 구조를 개선하는 실험 기능을 공개했습니다.<br/>
companion 블록은 `companion object`와 문법은 거의 같지만 컴파일 방식이 근본적으로 다릅니다.<br/>
전체 설계는 KEEP-0449 제안서에 정리되어 있습니다.<br/>

### companion 블록과 확장 살펴보기

#### companion 블록
- `companion object`에서 `object` 키워드를 뺀 형태입니다.
- Kotlin 2.5.0-Beta1부터 실험 기능으로 사용할 수 있습니다.
- 컴파일러 플래그 `-Xcompanion-blocks`(블록만) 또는 `-Xcompanion-blocks-and-extensions`(둘 다)를 넘겨야 합니다.
- JVM에서는 진짜 static 멤버로 컴파일됩니다.

```kotlin
data class Vector(val x: Double, val y: Double) {
    companion {
        val ZERO = Vector(0.0, 0.0)
    }
}

// 사용은 똑같이
val v = Vector.ZERO
```

companion object는 실제 객체라서 인터페이스 구현이나 값으로 전달하는 것이 가능합니다.<br/>
반면 자바에서 호출하면 `Vector.Companion.getZERO()` 같은 이름이 드러나고, 리플렉션과 바이트코드 크기에도 흔적이 남습니다.<br/>
companion 블록은 컴파일 전략을 다른 플랫폼의 static 멤버처럼 바꿔서, JVM에서는 순수 static 멤버가 됩니다.<br/>

#### companion 확장
- 내가 만든 클래스가 아니어도 "클래스 멤버처럼" 선언할 수 있는 새 문법입니다.
- Java 클래스에도 쓸 수 있고, 원래 companion object가 없어도 됩니다.
- 라이브러리에서 내려준 클래스에 팩토리 함수를 붙이고 싶을 때, 유틸 오브젝트를 따로 만들지 않고도 `SomeClass.myFactory()` 형태로 붙일 수 있습니다.

```kotlin
companion fun Vector.unit(angle: Double) = Vector(cos(angle), sin(angle))
```

#### 기존 companion object와의 관계
- 기존 companion object는 그대로 지원되고 강제 마이그레이션은 없습니다.
- 인터페이스를 구현해야 하는 companion은 여전히 object만 가능합니다. 블록은 객체가 아니기 때문입니다.
- 새 코드에서 단순 상수와 팩토리는 블록을 선호하는 방향이 되겠지만, 서두를 이유는 없습니다.

#### KMP와의 연결
- companion 블록 멤버는 KMP에서 expect로 선언할 수 있습니다.
- Java 클래스의 static 멤버로 actualize할 수 있습니다.
- 멀티플랫폼 라이브러리에서 플랫폼 네이티브 static API를 companion 멤버로 감싸던 패턴이 언어 차원에서 정식으로 지원됩니다.

### 실무에서 주의할 점

실험 기능이므로 지금 당장 실무에 적용할 단계는 아닙니다.<br/>
특히 companion 확장을 쓴 라이브러리는 pre-release 바이너리가 되어 안정화될 때까지 의존성으로 소비할 수 없습니다.<br/>
companion 블록은 이 제한이 없지만, 소비하는 쪽도 플래그를 켜야 합니다.<br/>
사내 공통 모듈에 실험 문법을 넣으면 그 모듈을 쓰는 모든 프로젝트에 플래그가 전파됩니다.<br/>
마이그레이션할 때는 `object` 키워드를 지우는 것으로 대부분 충분하지만, 프로젝트와 의존하는 코드 전체를 다시 컴파일해야 합니다.<br/>
R8/ProGuard 규칙에서 `Companion`을 참조하던 룰이 있다면 함께 점검해야 합니다.<br/>
생태계 툴링이 아직 블록을 인식하지 못할 수 있다는 점도 발표에서 언급되었습니다.<br/>
Android 관점에서는 Activity와 Fragment의 `newInstance`, `TAG` 상수, `CREATOR` 같은 상용구의 바이트코드가 깔끔해집니다.<br/>
다만 DEX 메서드 수나 APK 크기에서 큰 변화는 기대하지 않는 것이 좋습니다.<br/>
실험 플래그를 켜는 방법은 다음과 같습니다.<br/>

```kotlin
// app/build.gradle.kts (Kotlin DSL)
kotlin {
    compilerOptions {
        // companion 블록만 허용
        freeCompilerArgs.add("-Xcompanion-blocks")
        // 블록 + 확장을 모두 허용
        // freeCompilerArgs.add("-Xcompanion-blocks-and-extensions")
    }
}
```

```kotlin
// 실험해 볼 후보 1: Fragment 팩토리
class DetailFragment : Fragment() {
    companion {
        private const val ARG_ID = "arg_id"
        fun newInstance(id: String) = DetailFragment().apply {
            arguments = bundleOf(ARG_ID to id)
        }
    }
}

// 실험해 볼 후보 2: 인터페이스 구현이 필요하면 object 유지
class AnalyticsTracker {
    companion object : EventSink {  // 블록으로는 안 됨
        override fun sink(event: Event) { /* ... */ }
    }
}
```

### 마치며

companion 블록은 겉보기에는 `object` 한 단어 차이이지만, 바이트코드 관점에서는 static 멤버로 컴파일되는 큰 변화입니다.<br/>
실험 기능인 만큼 테스트 모듈에서 먼저 확인하고, 안정화 이후에 새 코드부터 적용하는 것이 좋겠습니다.<br/>
