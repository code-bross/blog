### 배경

Rabbit 2는 현재 Stable 채널에 있습니다.<br/>
다음 버전인 Rabbit 3은 Canary 채널에서 제공되고 있습니다.<br/>
Canary 빌드는 최신 기능을 먼저 써볼 수 있지만 가볍게 테스트된 단계입니다.<br/>
기능이 추가되거나 변경될 수 있다는 전제가 붙습니다.<br/>
Canary 2는 Android Gradle Plugin 9.6.0-alpha02와 함께 릴리스됐습니다.<br/>
프리뷰 버전의 Studio는 대응하는 프리뷰 AGP와 함께 쓰는 것이 원칙입니다.<br/>
이번 글에서는 Rabbit 3에 새로 들어온 기능 네 가지를 살펴보겠습니다.<br/>

### Rabbit 3 살펴보기

#### Compose Preview Screenshot Testing 도구

Compose UI의 회귀를 막는 스크린샷 테스트 도구가 들어왔습니다.<br/>
이 도구는 Compose 프리뷰를 기준으로 스크린샷 테스트를 수행합니다.<br/>
결과는 HTML 리포트로 생성돼 UI 변화를 눈으로 확인할 수 있습니다.<br/>
디자인 시스템 컴포넌트처럼 화면이 자주 바뀌는 영역에 유용합니다.<br/>
스냅샷 비교를 수동 눈대중이 아니라 테스트로 고정할 수 있습니다.<br/>

#### Model Assignment

AI 모델을 작업 종류별로 다르게 지정하는 기능입니다.<br/>
복잡한 추론이 필요한 Agent Mode에는 큰 규모의 모델을 지정할 수 있습니다.<br/>
커밋 메시지 생성이나 다음 편집 예측처럼 지연에 민감한 작업에는 가벼운 모델을 지정합니다.<br/>
이렇게 하면 품질과 속도, 쿼터 사용량을 작업별로 균형 있게 조절할 수 있습니다.<br/>
설정은 다음 경로에서 변경합니다.<br/>

```text
File > Settings > Tools > AI > Model Providers > Model Assignment 탭
```

Agent Mode 패널의 모델 선택 드롭다운에서 직접 바꾸는 방법도 있습니다.<br/>
이 경우 Thinking 기능에 대한 Model Assignment 설정이 함께 업데이트됩니다.<br/>

#### iOS, Flutter, React Native 앱 마이그레이션

기존 크로스 플랫폼 앱을 네이티브 Android 앱으로 바꾸는 도구가 들어왔습니다.<br/>
새 프로젝트 마법사에서 마이그레이션 어시스턴트를 호출합니다.<br/>
변환 대상은 iOS와 Flutter, React Native 프로젝트입니다.<br/>
결과물은 Kotlin과 Jetpack Compose 기반의 Android 앱입니다.<br/>
작업 계획과 코드 변환, 컴파일 검사가 통합 진행 UI로 보입니다.<br/>
결과물은 바로 테스트와 검증이 가능한 기능하는 프로젝트 형태입니다.<br/>

#### Publish to Google Play for testing

Play Console 테스트 트랙에 IDE에서 바로 업로드하는 기능이 들어왔습니다.<br/>
서명된 앱 번들 생성 흐름이 끝나는 지점에서 이어서 선택합니다.<br/>
새 앱의 첫 릴리스는 내부 테스트 트랙에 업로드할 수 있습니다.<br/>
기존 앱은 다른 종류의 테스트 트랙에도 업로드할 수 있습니다.<br/>
이 기능을 쓰려면 Google Play Console에 등록돼 있어야 합니다.<br/>

### 실무 관점

Canary는 Stable과 별도로 설치해 운영하는 것이 안전합니다.<br/>
운영 프로젝트의 빌드 환경을 Canary로 통째로 옮기는 것은 피하는 것이 좋습니다.<br/>
스크린샷 테스트는 전체 화면보다 디자인 시스템 컴포넌트부터 적용하는 것이 좋습니다.<br/>
Model Assignment는 쿼터가 소진되는 지점을 확인하면서 조정하는 것이 좋습니다.<br/>
Play 테스트 업로드는 내부 트랙부터 검증하고, 이후 트랙을 넓히는 순서가 안전합니다.<br/>
마이그레이션 도구는 자동 변환 결과를 그대로 운영에 쓰기보다 컴파일과 동작 검증 뒤에 적용합니다.<br/>

### 마치며

Rabbit 3는 AI 모델 선택과 UI 회귀 방지, 마이그레이션, 테스트 배포를 한 번에 다룹니다.<br/>
Canary라는 전제를 지키면서, 팀에 맞는 기능부터 별도 환경에서 검증하는 것이 좋습니다.<br/>
