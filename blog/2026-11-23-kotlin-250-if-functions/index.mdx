### 배경

`Boolean` 값을 검사한 뒤 분기하는 코드는 안드로이드 개발에서 자주 등장합니다.<br/>
검사 결과가 참일 때만 로그를 남기거나, 거짓일 때만 안내 문구를 보여주는 경우가 그 예입니다.<br/>
지금까지는 이런 패턴을 쓰려면 `if` 식과 `else` 분기를 매번 직접 작성해야 했습니다.<br/>
검사 결과가 필요 없는 경우에도 분기 구조가 남았고, 코드가 길어질수록 의도가 잘 보이지 않았습니다.<br/>
Kotlin 2.5.0-RC에는 이런 반복 패턴을 줄여주는 표준 라이브러리 함수가 새로 들어왔습니다.<br/>
`onTrue`와 `onFalse`, `ifOrNull`이 그 주인공입니다.<br/>

### 새 함수 살펴보기

세 함수는 모두 [Kotlin 2.5.0-RC](https://kotlinlang.org/docs/whatsnew-eap.html)에서 실험 API로 제공됩니다.<br/>
사용하려면 `@OptIn(ExperimentalStdlibApi::class)` 애너테이션을 붙이거나, 컴파일러 옵션으로 `-opt-in=kotlin.ExperimentalStdlibApi`를 지정해야 합니다.<br/>
함수마다 동작이 다르므로, 하나씩 살펴보겠습니다.<br/>

#### onTrue

`onTrue`는 `Boolean` 값이 `true`일 때만 지정한 블록을 실행합니다.<br/>
블록을 실행한 뒤에는 원래의 `Boolean` 값을 그대로 돌려줍니다.<br/>
반환값을 그대로 돌려주기 때문에, 호출 결과를 변수에 담거나 체이닝을 이어갈 수 있습니다.<br/>

```kotlin
@OptIn(ExperimentalStdlibApi::class)
fun main() {
    val tags = mutableSetOf("kotlin", "jvm")

    // add()가 true를 돌려줄 때만 메시지를 출력합니다.
    val added = tags.add("wasm").onTrue {
        println("Tag added")
    }
    println(added) // Tag added
    // true
}
```

`Set.add`처럼 성공 여부를 `Boolean`으로 돌려주는 API와 함께 쓰면, 결과 확인과 로그를 한 줄로 묶을 수 있습니다.<br/>

#### onFalse

`onFalse`는 `Boolean` 값이 `false`일 때만 지정한 블록을 실행합니다.<br/>
`onTrue`와 마찬가지로 원래의 `Boolean` 값을 그대로 돌려줍니다.<br/>
실패했을 때만 처리하고 싶은 경우에 사용합니다.<br/>

```kotlin
@OptIn(ExperimentalStdlibApi::class)
fun main() {
    val tags = mutableSetOf("kotlin", "jvm")

    // remove()가 false를 돌려줄 때만 메시지를 출력합니다.
    val removed = tags.remove("native").onFalse {
        println("Tag not found")
    }
    println(removed)
    // Tag not found
    // false
}
```

`onTrue`와 `onFalse`를 함께 쓰면, 성공과 실패 분기를 각각 한 줄씩 표현할 수 있습니다.<br/>

#### ifOrNull

`ifOrNull`은 `Boolean` 값이 `true`일 때만 블록을 실행하고 그 결과를 돌려줍니다.<br/>
`Boolean` 값이 `false`이면 블록을 실행하지 않고 `null`을 돌려줍니다.<br/>
`onTrue`와 `onFalse`가 `Boolean`에 붙는 확장 함수인 것과 달리, `ifOrNull`은 `Boolean`을 인자로 받는 함수입니다.<br/>

```kotlin
@OptIn(ExperimentalStdlibApi::class)
fun main() {
    val tags = mutableSetOf("kotlin", "jvm", "wasm")

    // "wasm"이 tags 안에 있을 때만 메시지를 돌려줍니다.
    val message = ifOrNull("wasm" in tags) {
        "Wasm tag is available"
    }
    println(message)
    // Wasm tag is available
}
```

조건이 거짓이면 `null`이 나오므로, 엘비스 연산자나 널 안전 호출과 자연스럽게 이어집니다.<br/>
조건에 따라 값이 있을 수도 없을 수도 있는 경우에 `if` 식과 `else` 분기를 직접 쓰지 않아도 됩니다.<br/>

#### 적용하기

세 함수는 Kotlin 2.5.0-RC부터 사용할 수 있습니다.<br/>
Version Catalog에서 Kotlin 버전을 교체하면 RC를 적용할 수 있습니다.<br/>

```toml
[versions]
kotlin = "2.5.0-RC"

[plugins]
kotlin-android = { id = "org.jetbrains.kotlin.android", version.ref = "kotlin" }
```

RC는 정식 출시 직전 단계이므로, 새 기능이 동결되고 안정화 작업이 중심이 됩니다.<br/>
실험 API라는 점도 함께 고려해야 합니다.<br/>
정식 출시 전에 API 형태가 바뀔 수 있으므로, 핵심 로직보다는 주변 코드부터 적용하는 것이 안전합니다.<br/>

### 실무 관점

국내 MTS 프로젝트에 적용한다면, 반환값을 그대로 돌려준다는 점을 활용하는 것이 좋습니다.<br/>
`onTrue`와 `onFalse`는 검사 결과를 그대로 이어주기 때문에, 기존 체이닝 구조를 바꾸지 않고 끼워 넣을 수 있습니다.<br/>
다만 블록 안에 무거운 로직을 넣으면 안 됩니다.<br/>
이 함수들은 조건부 실행을 짧게 표현하는 용도이지, 분기 로직 자체를 대신하는 용도가 아닙니다.<br/>
`ifOrNull`은 조건에 따라 값이 없을 수 있는 경우에만 쓰고, 조건이 복잡해지면 기존 `if` 식이 더 읽기 쉽습니다.<br/>
실험 API이므로, 적용한 위치를 목록으로 남겨 두면 정식 출시 때 확인하기 편합니다.<br/>

### 마치며

`onTrue`와 `onFalse`, `ifOrNull`은 짧은 분기 패턴을 한 줄로 줄여주는 함수입니다.<br/>
조건 검사와 결과 처리를 분리하지 않고 묶을 수 있어, 작은 코드가 모이는 곳에서 효과가 큽니다.<br/>
