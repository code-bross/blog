### 배경

지금까지 [Google AI Studio](https://aistudio.google.com/)에서 만든 Android 앱은 로컬 세션 저장만 지원했습니다.<br/>
데이터를 기기 간에 동기화하거나 로그인 기능을 넣으려면 Firebase 프로젝트를 직접 만들고 연결해야 했습니다.<br/>
API 키를 APK 안에 넣으면 추출될 위험이 있어 Gemini 호출도 별도 서버 작업이 필요했습니다.<br/>
11월 17일 공개된 업데이트에서는 [Build 에이전트](https://aistudio.google.com/apps)가 이런 백엔드 설정을 대신 처리합니다.<br/>
[Gemini 4 Carbon과 Hydrogen](https://developers.googleblog.com/build-full-stack-android-apps-with-gemini-in-google-ai-studio/)을 기반으로 프롬프트 하나로 풀스택 Kotlin 앱을 만들고 Play 스토어에 게시하는 흐름이 마련되었습니다.<br/>

### Google AI Studio 풀스택 앱 살펴보기

#### Cloud Firestore로 데이터 저장하기

프롬프트에 데이터 저장이나 로그인, 생성형 AI 기능이 필요하다는 단서가 있으면 Build 에이전트가 요구 사항을 먼저 감지합니다.<br/>
사용자가 확인하면 에이전트가 [Cloud Firestore](https://firebase.google.com/docs/firestore) 데이터베이스를 프로비저닝하고 앱의 데이터 모델에 맞는 [Security Rules](https://firebase.google.com/docs/firestore/security/get-started)를 생성합니다.<br/>
오프라인 캐시가 포함되어 연결이 끊긴 동안의 변경 사항은 연결이 복원되면 자동으로 동기화됩니다.<br/>
태블릿에서 시작한 작업을 휴대전화에서 이어서 할 수 있습니다.<br/>

#### Firebase Authentication으로 로그인하기

사용자 프로필이나 개인 작업 공간이 필요한 앱에는 [Firebase Authentication](https://firebase.google.com/docs/auth)이 Google Sign-In과 함께 설정됩니다.<br/>
사용자별 권한 규칙이 함께 적용되어 각 사용자는 자신의 문서만 읽고 쓸 수 있습니다.<br/>
로그인 UI와 토큰 관리를 직접 구현하지 않아도 됩니다.<br/>

#### Firebase AI Logic으로 Gemini 안전하게 호출하기

APK 안에 API 키를 직접 넣으면 키가 추출될 수 있습니다.<br/>
Build 에이전트는 [Firebase AI Logic](https://firebase.google.com/docs/ai-logic)을 설정하고 [Firebase App Check](https://firebase.google.com/docs/app-check)를 적용합니다.<br/>
App Check는 [Google Fraud Defense](https://firebase.google.com/docs/app-check)(구 reCAPTCHA Enterprise)로 요청이 변조되지 않은 정식 앱에서 왔는지 확인합니다.<br/>
자격 증명은 서버 쪽에 남아 있고, 앱에서는 키를 노출하지 않고 Gemini 모델을 호출합니다.<br/>
공식 블로그에 소개된 생성 코드는 다음과 같습니다.<br/>

```kotlin
// Generated by Google AI Studio Build agent using Firebase AI Logic & Cloud Firestore
class WorkoutRepository(context: Context) {
    private val generativeModel by lazy {
        Firebase.ai(backend = GenerativeBackend.googleAI())
            .generativeModel("gemini-4-hydrogen")
    }

    private val db = FirebaseFirestore.getInstance(
        context.applicationContext.getString(R.string.firestore_database_id)
    )

    suspend fun generateAndSaveWorkout(goal: String, uid: String) {
        val response = generativeModel.generateContent("Create a 20-minute workout for: $goal")
        val workout = hashMapOf(
            "ownerId" to uid,
            "goal" to goal,
            "plan" to (response.text ?: ""),
            "createdAt" to FieldValue.serverTimestamp()
        )
        db.collection("workouts").add(workout).await()
    }
}
```

`Firebase.ai`로 생성 모델을 만들고, 응답 텍스트를 Firestore 컬렉션에 저장하는 구조입니다.<br/>
`ownerId`를 함께 저장해 사용자별 문서 분리가 가능합니다.<br/>

#### HD 에뮬레이터와 스크린샷 디버깅

브라우저 안의 Android 에뮬레이터가 더 빠르게 시작되고 HD 토글을 켜면 1200p 고화질 스트리밍으로 전환됩니다.<br/>
실시간 오디오 출력도 지원되어 음성 기반 기능이나 TTS, 미디어 앱을 브라우저 안에서 테스트할 수 있습니다.<br/>
에뮬레이터 툴바의 스크린샷 버튼을 누르면 실행 중인 화면을 캡처해 프롬프트에 바로 첨부할 수 있습니다.<br/>
레이아웃 간격이나 대비 같은 시각적인 수정 요청을 글로 설명하지 않고 화면으로 전달할 수 있습니다.<br/>
커스텀 폰트도 지원되어 Compose 테마에 원하는 서체를 적용할 수 있습니다.<br/>
내부적으로는 공식 [Android CLI](https://developer.android.com/tools/cli)가 프로젝트 생성과 Gradle 빌드를 담당합니다.<br/>

#### 개인 Play 라이브러리로 바로 게시하기

지금까지 실기기에 앱을 설치하려면 USB 디버깅을 켜거나 서명 키스토어를 직접 관리해야 했습니다.<br/>
[Google Play](https://play.google.com/) 연동을 이용하면 게시 패널에서 몇 번의 클릭으로 Play 계정을 설정할 수 있습니다.<br/>
AI Studio가 Android App Bundle(`.aab`)을 빌드하고 서명한 뒤 개인 Play 라이브러리에 바로 게시합니다.<br/>
일반 Google 계정으로 이용할 수 있고, 휴대전화에 바로 설치해 테스트할 수 있습니다.<br/>

### 실무 관점

생성된 코드는 프로토타입이나 MVP를 빠르게 만드는 데 적합합니다.<br/>
실제 서비스에 쓰려면 생성된 Security Rules가 데이터 모델과 권한 정책을 정확히 반영하는지 직접 검토해야 합니다.<br/>
백엔드가 Cloud Firestore와 Firebase Authentication으로 고정되므로, 나중에 다른 백엔드로 옮기려면 데이터 계층을 다시 작성해야 합니다.<br/>
자동 테스트와 CI/CD, UX 품질 검토는 아직 수동 작업으로 남아 있습니다.<br/>
개인 Play 라이브러리 게시는 정식 Play Console 배포와 다르므로, 상용 배포 전에는 스토어 정책과 심사 절차를 별도로 확인해야 합니다.<br/>
