### 배경

구조 분해는 객체를 여러 변수로 한 번에 나누는 문법입니다.<br/>
데이터 클래스의 값을 꺼낼 때 자주 사용합니다.<br/>
지금까지의 구조 분해는 위치 기반이었습니다.<br/>
변수는 프로퍼티 순서대로 `componentN()` 함수의 결과와 연결되었습니다.<br/>
이 방식에서는 변수 이름과 프로퍼티 이름이 달라도 컴파일러가 아무런 경고를 내지 않았습니다.<br/>
순서만 맞으면 이름이 뒤바뀐 채로 값이 들어가도 그대로 동작했습니다.<br/>
프로퍼티 순서가 바뀌면 받는 쪽 코드도 함께 바꿔야 했습니다.<br/>
이름 기반 구조 분해는 이 문제를 해결하기 위해 도입되었습니다.<br/>
변수를 위치가 아니라 프로퍼티 이름으로 연결하는 방식입니다.<br/>

### 이름 기반 구조 분해 살펴보기

이름 기반 구조 분해는 [Kotlin 2.5.0-RC](https://kotlinlang.org/docs/whatsnew-eap.html)에서 `only-syntax` 모드로 안정화되었습니다.<br/>
`only-syntax` 모드는 이제 기본값이므로, 별도의 컴파일러 옵션을 지정하지 않아도 새 문법을 사용할 수 있습니다.<br/>
기존 문법의 동작은 그대로 유지됩니다.<br/>
하나씩 살펴보겠습니다.<br/>

#### 기존 방식의 문제

위치 기반 구조 분해에서는 변수가 선언된 순서대로 값이 들어갑니다.<br/>
다음 예시에서 `email` 변수에는 `username` 값이 들어갑니다.<br/>

```kotlin
data class User(val username: String, val email: String)

fun main() {
    val user = User("alice", "alice@example.com")

    val (email, username) = user
    println(email) // alice
    println(username) // alice@example.com
}
```

`email`이라는 이름으로 `username` 값을 받는 코드가 컴파일됩니다.<br/>
실행 결과도 오류가 아니라 잘못된 값으로 나옵니다.<br/>
이런 실수는 코드 리뷰에서도 놓치기 쉽습니다.<br/>

#### 새 문법

이름 기반 구조 분해는 변수 앞에 `val`을 붙이는 명시적 형식을 사용합니다.<br/>
변수는 프로퍼티 이름과 연결됩니다.<br/>
이름을 바꿔서 받고 싶으면 `=`으로 새 이름을 지정할 수 있습니다.<br/>

```kotlin
data class User(val username: String, val email: String)

fun main() {
    val user = User("alice", "alice@example.com")

    (val mail = email, val name = username) = user
    println(name) // alice
    println(mail) // alice@example.com
}
```

`mail` 변수에는 `email` 프로퍼티 값이 들어갑니다.<br/>
`name` 변수에는 `username` 프로퍼티 값이 들어갑니다.<br/>
선언 순서와 프로퍼티 순서는 달라도 됩니다.<br/>
이름이 기준이 되므로, 프로퍼티 순서가 바뀌어도 받는 쪽 코드는 그대로 동작합니다.<br/>

#### 세 가지 모드

이름 기반 구조 분해의 동작은 컴파일러 옵션 `-Xname-based-destructuring`으로 조절할 수 있습니다.<br/>
모드는 세 가지입니다.<br/>
`only-syntax` 모드는 명시적 형식만 허용하고, 기존 구조 분해의 동작은 바꾸지 않습니다.<br/>
2.5.0-RC에서는 이 모드가 기본값입니다.<br/>
`name-mismatch` 모드는 위치 기반 구조 분해에서 변수 이름이 프로퍼티 이름과 다르면 경고를 냅니다.<br/>
`complete` 모드는 괄호 짧은 형식을 이름 기반으로 바꾸고, 위치 기반은 대괄호 문법으로 옮깁니다.<br/>

```kotlin
val point = Pair(10, 20)

// complete 모드에서 위치 기반 구조 분해는 대괄호를 사용합니다.
val [x, y] = point
```

대괄호 문법은 순서가 중요한 타입에 사용합니다.<br/>
`Pair`나 `Triple`, 리스트 같은 타입이 그 예입니다.<br/>
`complete` 모드는 아직 실험 단계이므로, 당장은 기본값인 `only-syntax` 모드로 시작하는 것이 안전합니다.<br/>

#### Full Value Class와 함께 쓰기

[Kotlin 2.5.0-RC](https://kotlinlang.org/docs/whatsnew-eap.html)에는 실험 기능인 full value class도 함께 들어왔습니다.<br/>
full value class에는 `componentN()` 함수가 없습니다.<br/>
그래서 위치 기반 구조 분해는 사용할 수 없고, 이름 기반 구조 분해로 값을 꺼냅니다.<br/>

```kotlin
value class Complex(val real: Double, val imaginary: Double)

fun main() {
    val value = Complex(1.0, 2.0)

    (val real, val imaginary) = value
    println(real) // 1.0
    println(imaginary) // 2.0
}
```

이름 기반 구조 분해는 full value class의 값을 꺼내는 기본 수단이 됩니다.<br/>
데이터 클래스와 full value class를 같은 방식으로 다룰 수 있습니다.<br/>

#### 적용하기

Kotlin 2.5.0-RC는 Version Catalog에서 Kotlin 버전을 교체하면 적용할 수 있습니다.<br/>

```toml
[versions]
kotlin = "2.5.0-RC"

[plugins]
kotlin-android = { id = "org.jetbrains.kotlin.android", version.ref = "kotlin" }
```

RC는 정식 출시 직전 단계이므로, 새 기능이 동결되고 안정화 작업이 중심이 됩니다.<br/>
`only-syntax` 모드는 안정화된 기능이지만, RC 버전 자체는 정식 버전이 아닙니다.<br/>
새 문법은 브랜치에서 먼저 사용해 보고, 정식 출시 이후에 본 코드에 적용하는 것이 안전합니다.<br/>

### 실무 관점

국내 MTS 프로젝트에 적용한다면, API 응답 모델처럼 프로퍼티가 많은 데이터 클래스부터 살펴보는 것이 좋습니다.<br/>
서버 응답 필드 순서가 바뀌어도 이름으로 꺼내면 받는 쪽이 영향을 받지 않습니다.<br/>
다만 새 문법을 팀 전체가 같은 기준으로 써야 합니다.<br/>
일부는 위치 기반, 일부는 이름 기반으로 섞어 쓰면 코드가 읽기 어려워집니다.<br/>
`complete` 모드는 아직 실험 단계이므로, 기본값인 `only-syntax` 모드로 시작하고 정식 출시를 기다리는 것이 좋습니다.<br/>
기존 코드는 동작이 그대로 유지되므로, 마이그레이션 부담 없이 새 코드부터 적용할 수 있습니다.<br/>

### 마치며

이름 기반 구조 분해는 변수와 값을 이름으로 연결해 순서 실수를 줄여주는 기능입니다.<br/>
기본값으로 안정화되었으므로, 새 코드부터 명시적 형식으로 적용해 보는 것을 권합니다.<br/>
