### CameraX 도입 전의 문제

기존 구현은 Camera1과 저수준 Camera2 API를 직접 사용했습니다.<br/>
세 가지 문제가 반복되었습니다.<br/>

#### 미리보기 왜곡과 회전 문제

제조사마다 카메라 센서 방향을 다르게 보고했습니다.<br/>
미리보기가 회전되거나 얼굴 촬영이 잘못된 방향으로 저장되었습니다.<br/>
저가형 기기에서는 요청한 프레임 크기가 맞지 않아 미리보기가 늘어났습니다.<br/>
얼굴이 일그러지면 생체 인증 자체가 무용지물이 됩니다.<br/>

#### 메모리 부족 충돌

RAM 1GB 이하인 기기에서 고해상도 이미지를 처리하면 메모리 부족 충돌이 발생했습니다.<br/>
실시간 생체 확인을 포기하고 정적 사진을 REST API로 업로드하는 방식으로 돌아가야 했습니다.<br/>
그 결과 SDK 도입 성장률은 연간 2배에서 3배 수준에 머물렀습니다.<br/>

### CameraX 살펴보기

SmileID는 모바일 SDK를 처음부터 다시 만들며 [CameraX](https://developer.android.com/training/camerax)로 이전했습니다.<br/>
CameraX는 기기 차이를 추상화하고 수명 주기를 인식하는 인터페이스를 제공합니다.<br/>
Android 5.0(API 21)부터 지원되며 기존 기기의 98% 이상을 커버합니다.<br/>

#### Preview와 ImageAnalysis 파이프라인

두 가지 유스 케이스를 함께 묶어 이중 목적 파이프라인을 구성했습니다.<br/>
`Preview`는 사용자를 안내하는 실시간 미리보기를 담당합니다.<br/>
`ImageAnalysis`는 프레임을 실시간으로 분석해 얼굴 위치 확인과 생체 여부를 판단합니다.<br/>
검증된 셀피 프레임도 같은 파이프라인에서 추출합니다.<br/>

#### ResolutionSelector로 해상도 제어하기

고해상도 촬영과 메모리 부족 충돌을 함께 해결한 핵심은 `ResolutionSelector`입니다.<br/>
목표 해상도를 지정하고 해당 크기를 지원하지 않는 기기에서의 대체 규칙을 선택합니다.<br/>
선명도를 우선하면 `FALLBACK_RULE_CLOSEST_HIGHER_THEN_LOWER`를 사용합니다.<br/>
메모리 사용량을 제한하면 `FALLBACK_RULE_CLOSEST_LOWER_THEN_HIGHER`를 사용합니다.<br/>
백프레셔 전략은 `STRATEGY_KEEP_ONLY_LATEST`로 지정해 이전 프레임 분석이 끝나지 않았으면 오래된 프레임을 버립니다.<br/>

```kotlin
val resolutionSelector = ResolutionSelector.Builder()
    .setResolutionStrategy(
        ResolutionStrategy(
            Size(1200, 900),
            ResolutionStrategy.FALLBACK_RULE_CLOSEST_HIGHER_THEN_LOWER
        )
    )
    .setAspectRatioStrategy(AspectRatioStrategy.RATIO_4_3_FALLBACK_AUTO_STRATEGY)
    .build()

val imageAnalysis = ImageAnalysis.Builder()
    .setResolutionSelector(resolutionSelector)
    .setBackpressureStrategy(ImageAnalysis.STRATEGY_KEEP_ONLY_LATEST)
    .build()

imageAnalysis.setAnalyzer(executor, analyzer)

val preview = Preview.Builder().build().also {
    it.surfaceProvider = surfaceProvider
}

cameraProvider.bindToLifecycle(
    lifecycleOwner,
    CameraSelector.DEFAULT_FRONT_CAMERA,
    preview,
    imageAnalysis
)
```

고밀도 픽셀 프레임을 요청하고 단말에서 처리한 결과 셀피 해상도가 4배 증가했습니다.<br/>
얼굴 영역만 단말에서 압축해 전송하므로 네트워크 업로드 용량은 이전과 동일하게 유지되었습니다.<br/>
모델에 더 선명한 데이터를 제공하면서 사용자의 데이터 비용은 늘지 않았습니다.<br/>

#### 호환성을 지탱하는 두 가지 계층

첫 번째 계층은 Google의 Camera and Media Test Lab입니다.<br/>
190종이 넘는 실물 기기에서 자동 테스트가 매일 실행됩니다.<br/>
칩셋과 OS 버전, 하드웨어 사양이 다른 기기를 순환하며 검증합니다.<br/>
회귀가 발생하면 프로덕션 코드에 영향을 주기 전에 잡아냅니다.<br/>

두 번째 계층은 기기별 결함에 대한 자동 우회 처리입니다.<br/>
일부 기기는 노출 설정을 적용하지 못하거나 특정 종횡비에서 이미지를 뒤집어 보고합니다.<br/>
CameraX는 `DeviceQuirks`와 `CameraQuirks` 같은 내부 클래스로 알려진 문제를 감지합니다.<br/>
감지된 기기에는 맞는 우회 처리를 자동으로 적용합니다.<br/>
SmileID는 기기별 패치 없이 1만 8천 종이 넘는 기기에서 SDK를 동작시켰습니다.<br/>

#### 도입 결과

도입 결과는 수치로 확인됩니다.<br/>
SDK 도입 성장률은 2년 차에 20배에 도달했습니다.<br/>
검증 통과율은 SDK를 사용하는 앱 기준으로 20% 증가했습니다.<br/>
누적 본인 확인 건수는 1억 6천만 건을 넘어섰습니다.<br/>

### 실무 관점

MTS에서도 신분증 촬영과 본인 확인 같은 카메라 기능이 필요합니다.<br/>
저사양 기기까지 고려한다면 해상도는 요청만으로 끝나지 않습니다.<br/>
대체 규칙과 백프레셔 전략까지 함께 설계해야 메모리 문제를 피할 수 있습니다.<br/>
기기별 분기는 직접 작성하기보다 CameraX의 우회 처리에 맡기는 편이 유지보수에 유리합니다.<br/>
다만 `ResolutionSelector`의 대체 규칙은 촬영 품질과 메모리 사용량 사이의 선택입니다.<br/>
서비스 성격에 따라 선명도 우선과 메모리 제한 중 어느 쪽을 택할지 먼저 정하는 것이 좋습니다.<br/>
AI 코딩 에이전트를 사용한다면 CameraX Skill을 활용할 수 있습니다.<br/>
`android skills add camerax` 명령으로 추가하면 마이그레이션과 수명 주기 바인딩에 현재 패턴을 적용할 수 있습니다.<br/>

### 마치며

CameraX 도입은 파편화된 기기 환경의 문제를 SDK의 강점으로 바꾸었습니다.<br/>
카메라 기능을 직접 구현하기 전에 라이브러리가 제공하는 호환성 계층을 먼저 검토하는 것이 좋습니다.<br/>
