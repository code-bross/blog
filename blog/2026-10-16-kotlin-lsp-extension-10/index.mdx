최근 정식 릴리스된 JetBrains의 LSP 기반 확장 "Java and Kotlin by IntelliJ IDEA" 1.0에 대해 설명해드리겠습니다.<br/>

### 배경

Kotlin 코드를 Android Studio가 아닌 에디터에서 작성하면, IntelliJ 수준의 코드 분석 기능을 그대로 쓰기 어렵다는 아쉬움이 있었습니다.<br/>
10주 전 프리뷰로 공개됐던 JetBrains의 LSP 기반 확장이 드디어 1.0 정식 릴리스를 맞았습니다.<br/>
이번 릴리스로 VS Code와 Cursor에서도 IntelliJ IDEA 데스크톱 IDE의 Java·Kotlin 분석 엔진을 그대로 쓸 수 있게 됐습니다.<br/>
자세한 내용은 JetBrains의 발표 글 [IntelliJ IDEA's Java and Kotlin for Cursor and VS Code Hits 1.0](https://blog.jetbrains.com/idea/2026/10/intellij-idea-s-java-and-kotlin-for-cursor-and-vs-code-hits-1-0/)에서 확인할 수 있습니다.

### "Java and Kotlin by IntelliJ IDEA" 1.0 살펴보기

#### LSP 기반 분석 엔진
- IntelliJ IDEA의 Java·Kotlin 언어 지능을 LSP(언어 서버 프로토콜)로 뽑아내 VS Code와 Cursor에 그대로 올린 확장입니다. Cursor 팀과 함께 협업해 개발됐습니다.
- 핵심 아이디어는 단순합니다. 언어 지원을 한 번만 구현하고, 어떤 에디터에서든 재사용하는 것입니다.
- 에이전트가 LSP를 직접 호출하면 더 빠르고 결정적인 결과를 얻고, 토큰 소모도 줄일 수 있습니다.
- 앞으로는 Cursor와 VS Code의 Agents 뷰에서 에이전트가 LSP를 직접 호출해 코드를 작성하는 흐름까지 열릴 예정이라고 합니다.
- 터미널 기반 에이전트(Claude Code, Codex 등)가 IntelliJ의 Kotlin 이해를 직접 호출하는 실험도 병행 중입니다.

#### 1.0에서 제공하는 기능
- Java·Kotlin·혼합 언어 프로젝트를 지원합니다.
- 스마트 완성, 이동, 코드 분석과 리팩터링을 제공합니다.
- Maven, Gradle, Bazel 빌드를 지원합니다.
- 대규모 프로젝트와 모노레포에서도 빠른 성능을 냅니다.
- JUnit 테스트 러너를 제공합니다.
- 에뮬레이트 브레이크포인트와 비동기 스택 트레이스를 지원하는 디버깅을 제공합니다.
- Cursor에서는 Agents Window 전용 지원이 있습니다. 에이전트 윈도우가 자체 Language Server 인스턴스를 띄워 IntelliJ 인스펙션 기반 분석(JSpecify 널러빌리티, Spring 특화 분석 포함)을 수행합니다.

#### 라이선스
- 프리뷰 기간의 무료가 끝나고 라이선스가 유료로 전환됐습니다.
- 30일 평가판을 지나면 IntelliJ IDEA Ultimate 구독이 필요합니다.
- 같은 라이선스로 데스크톱 IDE와 VS Code 계열 에디터를 모두 커버합니다.
- 공지에서 흥미로운 대목이 하나 있습니다. 이 라이선스는 인간 사용을 전제로 설계됐으며, 순수 에이전트 용도(purely agentic use)의 라이선스 모델은 별도로 발표하겠다고 했습니다.

#### 권장 설정
- 설치는 Visual Studio Marketplace 또는 Open VSX Registry에서 합니다.
- Red Hat과 Oracle의 Java 확장과 분석 기능이 겹치므로, JetBrains는 해당 확장을 끄고 쓸 것을 권장합니다.

```jsonc
// .vscode/settings.json — JetBrains 확장과 함께 쓸 때 권장 설정
{
  // Red Hat Java 확장과 분석이 중복되므로 비활성화 (정확한 ID는 설치 목록에서 확인)
  // "redhat.java" 확장을 끄고 "Java and Kotlin by IntelliJ IDEA"만 켭니다.
}
```

- 팀 위키에 "Kotlin 분석은 JetBrains 확장으로 통일"이라는 한 줄만 적어둬도 온보딩 혼란이 줄어듭니다.

### 실무에서 주의할 점

- 기존 Java 확장과 충돌합니다. Red Hat의 Java 확장을 켠 채로 쓰면 분석 결과가 중복되거나 엇갈립니다. 조직 단위로 도입한다면 settings 수준에서 비활성화 정책을 같이 배포하는 것이 좋습니다.
- 10주 동안 무료 프리뷰로 쓰던 팀이 있다면 이제 구독 비용을 예산에 넣어야 합니다. 개인 취미용으로 Cursor에서 Kotlin을 건드리던 개발자에게는 다소 부담스러운 가격 정책입니다. 다만 이미 Ultimate를 쓰는 개발자에게는 추가 비용 없이 에디터 선택지가 늘어나는 셈입니다.
- 빌드 서버나 CI 에이전트에 이 확장을 깔아 코드 분석을 돌릴 계획이라면, 순수 에이전트 용도 라이선스 모델이 발표될 때까지 기다렸다가 확인하는 쪽이 안전합니다.
- Android 개발자 입장에서는 주 에디터가 Android Studio라 당장 바꿀 이유는 없습니다. 다만 공유 Kotlin 모듈(멀티플랫폼 common 코드, 서버 코드)을 Cursor나 VS Code에서 만지는 일이 있다면, 이제 IDE 기능이 떨어진다는 이유로 IntelliJ를 따로 열 필요가 없어집니다.
- Gradle과 Bazel 기반 프로젝트를 자동으로 임포트하므로, 기존 IntelliJ 프로젝트를 VS Code에서 여는 마이그레이션 비용은 낮은 편입니다.

### 마치며

에디터마다 달랐던 Kotlin 분석 품질이 하나의 엔진으로 통일되는 흐름입니다.<br/>
이미 IntelliJ IDEA Ultimate를 구독 중이라면, 추가 비용 없이 VS Code와 Cursor에서도 같은 분석 환경을 구성할 수 있습니다.
