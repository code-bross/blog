### 배경

Compose Runtime은 Compose의 상태 모델과 컴파일러 플러그인이 대상으로 하는 핵심 런타임입니다.<br/>
1.13 버전은 10월 7일에 beta01, 10월 21일에 beta02가 공개되었습니다.<br/>
이번 글은 Material3의 변경이 아니라 런타임의 상태 계산 규칙 변화에 초점을 맞춥니다.<br/>
공식 [Compose Runtime 릴리스 노트](https://developer.android.com/jetpack/androidx/releases/compose-runtime)를 기준으로 실무에 닿는 변경만 정리합니다.<br/>

### Runtime 1.13 베타에서 달라진 것

#### `computedStateOf` 계산 블록 읽기 전용 강제

가장 주의해야 할 변경은 beta01에 들어갔습니다.<br/>
`computedStateOf`의 계산 블록은 이제 읽기 전용으로 강제됩니다.<br/>
계산 블록 안에서 상태를 쓰면 `IllegalStateException`이 발생합니다.<br/>
이전에는 계산 블록 안의 쓰기가 조용히 잘못 동작했습니다.<br/>
그 결과 예측하기 어려운 무효화 연쇄와 리컴포지션 루프가 생길 수 있었습니다.<br/>
이제 프레임워크가 잘못된 코드를 바로 가리켜 줍니다.<br/>
`derivedStateOf`도 같은 계산 블록 규칙을 사용하므로 동일한 주의가 필요합니다.<br/>

```kotlin
// 변경 전 — 계산 블록 안에서 상태를 쓰면 IllegalStateException이 발생합니다.
val totalPrice = remember {
    derivedStateOf {
        // 아래와 같은 쓰기는 1.13 베타부터 허용되지 않습니다.
        // discountApplied.value = true
        cartItems.sumOf { it.price }
    }
}

// 권장 방식 — 상태 변경은 이벤트 핸들러에서 수행합니다.
fun onItemAdded(item: CartItem) {
    cartItems.add(item)
}

val totalPrice = remember {
    derivedStateOf { cartItems.sumOf { it.price } }
}
```

#### `ComputedState` 메모리 누수 수정

beta02에서는 `ComputedState`와 관련된 수정이 들어갔습니다.<br/>
기록된 상태 값이 해제되지 않던 메모리 누수가 수정되었습니다.<br/>
계산 블록이 `Snapshot.withoutReadObservation`을 호출할 때 무효화가 제대로 되지 않던 문제도 함께 수정되었습니다.<br/>
파생 상태를 많이 사용하는 화면에서는 메모리와 무효화 동작을 함께 점검해 볼 만합니다.<br/>

#### 그 밖의 beta01 변경

- `CompositionObserver`는 한 컴포지션 패스당 한 번만 해석됩니다.<br/>
- 진행 중인 컴포지션에서 `setObserver`를 호출하면 다음 패스부터 적용됩니다.<br/>
- Movable content 삽입 시 `onBeginComposition`과 `onEndComposition`이 보고됩니다.<br/>
- `LinkComposer`에서 movable content를 이동할 때 래퍼 그룹 슬롯을 유지하던 누수가 수정되었습니다.<br/>
- `lifecycle-runtime`이 2.10.0으로 업데이트되었습니다.<br/>
- 해당 버전은 AGP 9.5.0-alpha04 이상에서 번들된 lifecycle runtime lint 검사가 동작하는 데 필요합니다.<br/>
- `ComposeTracer`가 메인 스레드 밖에서도 사용할 수 있게 되었습니다.<br/>
- `Float.NaN`이나 `Double.NaN`을 `@Composable` 함수에 전달하면 리컴포지션 스킵이 되지 않던 문제가 수정되었습니다.<br/>
- `Dp.Unspecified`이 `Float.NaN` 기반이라 이 수정과 직접 연결됩니다.<br/>
- 라이브러리가 Kotlin 2.2를 대상으로 하며 kotlinc 2.2가 요구됩니다.<br/>

베타를 적용하는 의존성 선언은 다음과 같습니다.<br/>

```kotlin
dependencies {
    implementation("androidx.compose.runtime:runtime:1.13.0-beta02")
}
```

### 실무 관점

MTS 앱처럼 파생 상태를 많이 쓰는 코드에서는 계산 블록 안의 쓰기부터 점검하는 것이 좋습니다.<br/>
계산 블록은 순수한 계산만 담당하고, 상태 변경은 클릭이나 콜백 같은 이벤트 핸들러에서 수행합니다.<br/>
베타는 디버그 빌드에서 먼저 적용하고, 스테이블 전환 전에 회귀 테스트를 거치는 것이 안전합니다.<br/>
`Dp.Unspecified` 관련 스킵 수정은 레이아웃 측정 코드의 리컴포지션 횟수에도 영향을 줄 수 있습니다.<br/>

### 마치며

1.13 베타는 상태 계산 블록의 규칙을 명확히 하고 누수를 정리하는 업데이트입니다.<br/>
계산 블록 안의 쓰기를 찾아내는 것만으로도 스테이블 전환 전에 한 가지 위험을 줄일 수 있습니다.<br/>
