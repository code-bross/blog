안녕하세요, 한국투자증권 [한투](https://play.google.com/store/apps/details?id=com.truefriend.neosmartpension&hl=ko) 앱 개발자 way입니다.

10월 ProAndroidDev에 올라온 글 "The Evolution of Flow Collection in Jetpack Compose"가, Compose에서 Flow를 수집하는 API가 어떻게 진화해 왔는지 깔끔하게 정리했습니다. 익숙한 내용이지만, 실무에서 여전히 `collectAsState()`를 관성으로 쓰는 코드가 많아서 이번 기회에 정리해 봅니다.

## 핵심 요약

- Compose 1.0(2021년 7월)의 `collectAsState()`는 Flow를 State로 바꾸는 가장 단순한 방법이지만, **라이프사이클을 모른다**
- 액티비티가 백그라운드로 가도 composition이 살아 있으면 수집이 계속된다
- 지금의 정답은 `collectAsStateWithLifecycle()` — STARTED 미만이면 수집을 멈추고, 돌아오면 재개한다

## 무엇이 달라졌는지

### 1단계: collectAsState() (Compose 1.0)

```kotlin
val uiState by viewModel.uiState.collectAsState()
```

새 값이 emit될 때마다 Compose가 state를 업데이트하고 관련 UI를 리컴포즈합니다. 코드는 간단하지만, 중요한 차이가 하나 있습니다. `collectAsState()`는 라이프사이클이 STARTED 아래로 내려가도 수집을 자동으로 멈추지 않습니다. composition이 살아 있는 한 백그라운드에서도 계속 수집합니다.

### 2단계: collectAsStateWithLifecycle()

`lifecycle-runtime-compose`가 제공하는 API로, 라이프사이클을 인식합니다. 기본 `minActiveState`는 STARTED라서, 화면이 보이지 않으면 수집을 멈췄다가 다시 보이면 재개합니다.

```kotlin
val uiState by viewModel.uiState.collectAsStateWithLifecycle()
```

### 3단계: 일회성 이벤트는 다른 패턴으로

상태가 아니라 이벤트(네비게이션, 스낵바 등)를 소비할 때는 `collectAsState*` 계열이 아니라 `LaunchedEffect` + `repeatOnLifecycle` 조합이 맞습니다.

```kotlin
val lifecycle = LocalLifecycleOwner.current.lifecycle
LaunchedEffect(lifecycle) {
    lifecycle.repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.events.collect { event ->
            // 네비게이션, 스낵바 등 일회성 이벤트 처리
        }
    }
}
```

## 실무 영향 / 주의점

- 뷰모델의 `uiState` 같은 StateFlow는 **`collectAsStateWithLifecycle()`를 기본값**으로 두는 게 안전합니다
- `collectAsState()`는 upstream이 가벼우면 문제가 없지만, 소켓·위치·센서처럼 비싼 작업을 하는 Flow면 백그라운드에서 리소스를 낭비합니다
- `minActiveState` 파라미터로 기준을 RESUMED까지 올릴 수도 있으니, 화면 요구사항에 맞게 조정하세요
- SharedFlow 기반 일회성 이벤트에 `collectAsState`를 붙이는 실수는 여전히 흔합니다. 이벤트면 수집 패턴을 바꾸세요
