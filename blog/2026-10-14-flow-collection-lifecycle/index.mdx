Compose에서 Flow를 수집하는 API가 어떻게 진화해 왔는지 설명해드리겠습니다.<br/>

### 배경

Compose에서 UI 상태는 주로 Flow로 노출되고, 화면에서는 이를 State로 변환해 수집합니다.<br/>
문제는 수집 API가 라이프사이클을 모르면 액티비티가 백그라운드로 가도 수집이 계속된다는 점입니다.<br/>
실무에서는 여전히 `collectAsState()`를 관성으로 쓰는 코드가 많습니다.<br/>
10월 ProAndroidDev에 올라온 [The Evolution of Flow Collection in Jetpack Compose](https://proandroiddev.com/the-evolution-of-flow-collection-in-jetpack-compose-e93416a9d52d?gi=f6de1321b4bc&source=post_page---post_publication_info--b2a8232cbd12-----------------------------------------) 글(chanzmao)이 이 진화 과정을 정리했습니다.<br/>

### Flow 수집 API의 진화

#### 1단계: collectAsState()
- Compose 1.0(2021년 7월)에 도입된 가장 단순한 수집 방법입니다.
- Flow를 State로 바꾸고, 새 값이 emit될 때마다 관련 UI를 리컴포즈합니다.
- 라이프사이클을 모르기 때문에 STARTED 아래로 내려가도 수집을 자동으로 멈추지 않습니다.
- composition이 살아 있는 한 백그라운드에서도 계속 수집합니다.

```kotlin
val uiState by viewModel.uiState.collectAsState()
```

#### 2단계: collectAsStateWithLifecycle()
- `lifecycle-runtime-compose`가 제공하는 라이프사이클 인식 API입니다.
- 기본 `minActiveState`는 STARTED입니다.
- 화면이 보이지 않으면 수집을 멈추고, 다시 보이면 재개합니다.
- 지금의 정답에 해당하는 방법입니다.

```kotlin
val uiState by viewModel.uiState.collectAsStateWithLifecycle()
```

#### 3단계: 일회성 이벤트는 다른 패턴으로
- 상태가 아니라 이벤트(네비게이션, 스낵바 등)를 소비할 때는 `collectAsState` 계열이 맞지 않습니다.
- `LaunchedEffect`와 `repeatOnLifecycle` 조합을 사용합니다.

```kotlin
val lifecycle = LocalLifecycleOwner.current.lifecycle
LaunchedEffect(lifecycle) {
    lifecycle.repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.events.collect { event ->
            // 네비게이션, 스낵바 등 일회성 이벤트 처리
        }
    }
}
```

### 실무에서 주의할 점

ViewModel의 `uiState` 같은 StateFlow는 `collectAsStateWithLifecycle()`를 기본값으로 두는 것이 안전합니다.<br/>
`collectAsState()`는 upstream이 가벼우면 문제가 없지만, 소켓·위치·센서처럼 비싼 작업을 하는 Flow면 백그라운드에서 리소스를 낭비합니다.<br/>
`minActiveState` 파라미터로 기준을 RESUMED까지 올릴 수도 있으니, 화면 요구사항에 맞게 조정해야 합니다.<br/>
SharedFlow 기반 일회성 이벤트에 `collectAsState`를 붙이는 실수는 여전히 흔하므로, 이벤트면 수집 패턴을 바꿔야 합니다.<br/>

### 마치며

Flow 수집은 단순한 API 선택이 아니라 라이프사이클과 리소스 관리의 문제입니다.<br/>
상태는 `collectAsStateWithLifecycle()`로, 일회성 이벤트는 `repeatOnLifecycle`로 구분해 사용하는 것이 좋겠습니다.<br/>
