2026년 11월 4일에 공개된 [Biometric](https://developer.android.com/jetpack/androidx/releases/biometric) 1.4.0-beta01에 대해 설명해드리겠습니다.<br/>

### 배경

Biometric의 현재 stable 버전은 1.1.0입니다.<br/>
1.4 라인은 2024년 5월 alpha01부터 이어져 왔고, 11월 4일 beta01에 들어섰습니다.<br/>
베타 단계는 API 표면이 기능적으로 완성된 상태입니다.<br/>
이번 1.4의 핵심은 기존 `BiometricPrompt` 콜백 방식을 Activity Result 패턴으로 바꾸는 것입니다.<br/>

### Biometric 1.4.0-beta01 살펴보기

#### registerForAuthenticationResult로 등록합니다

1.4에서는 `BiometricPrompt`와 `biometric-ktx` 모듈을 대체하는 새로운 진입점이 도입되었습니다.<br/>
Activity Result API와 같은 방식으로 인증을 등록하고 실행합니다.<br/>
인증 입력은 `AuthenticationRequest`로, 결과는 `AuthenticationResult`로 받습니다.<br/>

```kotlin
private val auth = registerForAuthenticationResult { result ->
    when (result) {
        is AuthenticationResult.Success -> onAuthenticated()
        is AuthenticationResult.Error -> showError(result.errString)
        is AuthenticationResult.CustomFallbackSelected -> onFallbackSelected(result)
    }
}
```

`AuthenticationRequest`는 두 가지 종류가 있습니다.<br/>
생체 인증용 `BiometricRequest`는 강도(`Strength`)와 선택적인 `Fallback`을 지정합니다.<br/>
기기 자격 증명 전용 인증용 `CredentialRequest`도 함께 제공됩니다.<br/>
하나의 Activity나 Fragment에서 여러 인증 런처를 동시에 쓸 수도 있습니다.<br/>

#### biometric-compose에서 rememberAuthenticationLauncher를 사용합니다

1.4.0-alpha05부터는 Compose 전용 `biometric-compose` 라이브러리도 함께 제공됩니다.<br/>
컴포저블 안에서 `rememberAuthenticationLauncher`로 인증 요청과 콜백을 처리합니다.<br/>

```kotlin
val auth = rememberAuthenticationLauncher { result ->
    when (result) {
        is AuthenticationResult.Success -> onAuthenticated()
        is AuthenticationResult.Error -> showError(result.errString)
        is AuthenticationResult.CustomFallbackSelected -> Unit
    }
}
```

의존성은 다음과 같이 추가합니다.<br/>

```kotlin
dependencies {
    implementation("androidx.biometric:biometric:1.4.0-beta01")
    implementation("androidx.biometric:biometric-compose:1.4.0-beta01")
}
```

#### Fallback 옵션을 여러 개 둘 수 있습니다

Android 36.1(Baklava)부터는 생체 인증 프롬프트에서 최대 네 개의 커스텀 Fallback 옵션을 지원합니다.<br/>
기존의 단일 부정 버튼 대신, 아이콘을 함께 제공하는 여러 Fallback 옵션을 둘 수 있습니다.<br/>
Fallback 옵션은 `AuthenticationRequest.Biometric.Fallback`으로 제공합니다.<br/>
사용자가 Fallback을 선택하면 에러 코드가 아니라 `AuthenticationResult.CustomFallbackSelected`로 전달됩니다.<br/>

#### 그 외 변경점

`BiometricPrompt.CryptoObject`에 `KeyAgreement` 지원이 추가되었습니다.<br/>
기본 `minSdk`가 API 21에서 API 23으로 올라갔습니다.<br/>
라이브러리는 이제 JSpecify nullness 어노테이션을 사용합니다.<br/>
그 밖에 기기 회전 시 지문 아이콘이 사라지는 문제와 `canAuthenticate()`에서 잠금 오류를 잘못 반환하는 문제가 수정되었습니다.<br/>

### 실무 관점

MTS의 로그인이나 이체 인증 화면에서 `BiometricPrompt`를 쓰고 있다면, 교체 설계는 지금 시작하는 것이 좋습니다.<br/>
다만 적용 시점은 stable 릴리스 이후로 잡는 편이 안전합니다.<br/>
베타 단계의 API는 기능적으로 완성되었지만, 변경 가능성이 남아 있기 때문입니다.<br/>
Fallback 옵션은 PIN이나 패턴 같은 기기 자격 증명 경로와 연결해 설계합니다.<br/>
`minSdk` 23 변경도 적용 대상 단말 목록과 함께 확인합니다.<br/>

### 마치며

Biometric 1.4는 생체 인증을 Activity Result 패턴으로 바꾸고, Compose 전용 런처와 복수 Fallback 옵션을 함께 가져왔습니다.<br/>
인증 화면을 새로 만들거나 고칠 계획이 있다면, 1.4의 새 API를 기준으로 설계하는 것이 좋습니다.<br/>
