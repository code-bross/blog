2026년 10월에 공개된 [Kotlin Toolchain 0.13](https://blog.jetbrains.com/kotlin/2026/10/start-your-next-kmp-app-with-kotlin-toolchain-0-13/)에 대해 설명해드리겠습니다.<br/>

### 배경
Kotlin Multiplatform 프로젝트를 시작하려면 플랫폼마다 도구를 따로 설치해야 했습니다.<br/>
Android 개발자가 iOS를 처음 접하면 Xcode와 시뮬레이터 설정부터 낯설게 느껴졌습니다.<br/>
웹이나 데스크톱으로 확장할 때도 빌드 설정이 플랫폼마다 달라지는 문제가 있었습니다.<br/>
[Kotlin Toolchain](https://blog.jetbrains.com/kotlin/2026/10/start-your-next-kmp-app-with-kotlin-toolchain-0-13/)은 이런 진입 장벽을 낮추기 위해 나온 통합 진입점입니다.<br/>
선언형 설정 하나로 JVM과 Android, iOS, 멀티플랫폼, 서버 애플리케이션을 만들고 빌드할 수 있습니다.<br/>
0.13부터는 JetBrains이 대부분의 신규 KMP 프로젝트에 이 도구를 권장하기 시작했습니다.<br/>

### Kotlin Toolchain 0.13 살펴보기

#### 대화형 프로젝트 생성
0.13에는 `kotlin new` 명령이 새로 들어갔습니다.<br/>
Kotlin Multiplatform Wizard와 비슷한 대화형 흐름으로 프로젝트를 만듭니다.<br/>
애플리케이션 종류를 고른 뒤 타깃 플랫폼을 선택하는 순서로 진행됩니다.<br/>
기존 `kotlin init` 명령은 그대로 남아 있습니다.<br/>
다만 이제는 현재 디렉터리 안에 프로젝트 파일을 직접 생성하도록 동작이 바뀌었습니다.<br/>

```bash
kotlin new
kotlin update
```

#### iOS 시작 경험 개선
깨끗한 머신에서 iOS 앱을 설정하는 과정이 한결 매끄러워졌습니다.<br/>
Xcode 설치 문제에 대해서는 라이선스 동의 여부와 최초 실행 상태를 알기 쉽게 안내합니다.<br/>
필요한 iOS 시뮬레이터 런타임은 자동으로 내려받습니다.<br/>
시뮬레이터가 하나도 없으면 새로 자동 생성합니다.<br/>
도구 다운로드 중에는 진행률 표시줄이 표시되어 대기 상태를 확인할 수 있습니다.<br/>

#### Android SDK 프로비저닝 정렬
이전에는 Android SDK가 빌드나 실행 시점에만 자동으로 준비되었습니다.<br/>
프로젝트를 IDE에서 먼저 열면 SDK 누락으로 설정 오류가 나는 경우가 있었습니다.<br/>
0.13부터는 프로젝트 임포트 시점에도 누락된 Android SDK 구성 요소가 자동으로 준비됩니다.<br/>
CLI와 IDE의 동작이 정렬되면서 처음 여는 순간의 마찰이 줄었습니다.<br/>
네임스페이스와 애플리케이션 ID 검증도 강화되었습니다.<br/>
샘플 ID로 앱이나 라이브러리 빌드를 게시하는 실수를 사전에 막는 취지입니다.<br/>

#### SwiftPM 의존성 지원
Apple 플랫폼 모듈에서 Swift Package Manager 의존성을 쓸 수 있게 되었습니다.<br/>
원격 패키지는 저장소와 버전, 프로덕트를 지정하는 방식으로 선언합니다.<br/>
로컬 패키지는 `localSwiftPackage` 키로 연결합니다.<br/>
가져온 Objective-C API는 모듈 이름과 함께 접두사가 붙은 형태로 임포트합니다.<br/>

```yaml
product: ios/app
dependencies:
  - swiftPackage:
      repository: "https://github.com/firebase/firebase-ios-sdk.git"
      version: "12.17.0"
      products: [ "FirebaseCore", "FirebaseFirestore", "FirebaseAnalytics" ]
```

```kotlin
import swiftPMImport.app.FIRAnalytics
import swiftPMImport.app.FIRApp

fun initAnalytics() {
    FIRApp.configure()
}
```

#### 라이브러리 게시와 네이티브 캐시
멀티플랫폼 라이브러리를 게시하면 Compose Resources와 SwiftPM 의존성 메타데이터가 함께 게시됩니다.<br/>
서드파티 멀티플랫폼 라이브러리의 Compose Resources도 해석할 수 있게 되었습니다.<br/>
Kotlin/Native 재빌드 속도도 개선되었습니다.<br/>
컴파일된 네이티브 의존성은 빌드와 프로젝트를 넘어 캐시로 재사용됩니다.<br/>
프로젝트 코드는 파일 단위 캐시를 이용해 변경된 부분만 다시 빌드합니다.<br/>
캐시가 채워진 뒤에는 작은 수정에 대한 편집과 빌드, 실행 주기가 짧아집니다.<br/>

#### 에이전트 친화적인 설계
자동 환경 설정과 선언형 설정, 명확한 오류 메시지는 AI 에이전트에게도 유리한 기반입니다.<br/>
0.13에서는 Hot Reload MCP 서버와 전용 에이전트 스킬이 함께 제공됩니다.<br/>
공식 Kotlin 에이전트 스킬은 아래 명령으로 설치할 수 있습니다.<br/>

```bash
npx skills add kotlin/kotlin-agent-skills
```

JetBrains의 내부 벤치마크에서는 에이전트가 Toolchain 프로젝트를 더 안정적으로 다루고 토큰을 덜 썼다고 합니다.<br/>
독립 벤치마크가 아니므로 수치는 참고 수준으로 받아들이는 것이 좋습니다.<br/>

### 실무 관점
Toolchain은 아직 알파 단계라는 점을 먼저 기억해야 합니다.<br/>
JetBrains도 기존 Gradle 프로젝트의 마이그레이션 권장은 격차를 좁힌 뒤로 미루고 있습니다.<br/>
운영 중인 MTS 앱의 빌드를 바로 옮기기보다는 신규 KMP 실험 프로젝트부터 적용하는 것이 안전합니다.<br/>
IDE에서 최신 기능을 쓰려면 IntelliJ IDEA 2026.2.3이나 Android Studio Rabbit 1 2026.2.1 이상이 필요합니다.<br/>
최신 Kotlin Toolchain 플러그인 설치 여부도 함께 확인해야 합니다.<br/>
SwiftPM 의존성을 쓰는 라이브러리는 게시 메타데이터까지 함께 검증하는 것이 좋습니다.<br/>

### 마치며
Kotlin Toolchain 0.13은 신규 KMP 프로젝트의 시작 비용을 크게 낮춘 릴리스입니다.<br/>
iOS 설정과 SwiftPM 지원, 네이티브 캐시까지 실무에서 체감되는 개선이 모여 있습니다.<br/>
