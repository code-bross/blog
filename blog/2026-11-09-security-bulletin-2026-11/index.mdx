안녕하세요, [한국투자증권](https://securities.koreainvestment.com/main/Main.jsp)에서 [한투-한국투자증권](https://play.google.com/store/apps/details?id=com.truefriend.neosmartarenewal&hl=ko) 개발을 담당하고 있는 way입니다.<br/>
2026년 11월 2일에 공개된 [Android Security Bulletin](https://source.android.com/docs/security/bulletin/2026/2026-11-01)에 대해 설명해드리겠습니다.<br/>
이번 달 게시판은 Framework의 원격 코드 실행 취약점을 포함해 총 216건의 취약점을 다룹니다.<br/>

### 배경

Google은 매월 첫 월요일에 Android 보안 게시판을 공개합니다.<br/>
게시판은 보안 패치 레벨 단위로 취약점을 나눕니다.<br/>
11월 게시판은 2026년 11월 2일에 공개되었고, 11월 6일에 업데이트되었습니다.<br/>
패치 레벨은 2026-11-01과 2026-11-05 두 가지입니다.<br/>
2026-11-05 이상이면 게시판의 모든 취약점이 해결됩니다.<br/>
2026-11-01만 적용된 단말은 아직 해결되지 않은 수정분이 남아 있습니다.<br/>

### 2026년 11월 보안 게시판 살펴보기

#### 가장 심각한 취약점 확인하기

이번 달에 가장 심각한 문제는 Framework의 원격 코드 실행 취약점입니다.<br/>
`CVE-2026-58868`이며 Critical 등급입니다.<br/>
추가 실행 권한이 없어도 공격이 가능하고, 사용자 상호작용도 필요하지 않습니다.<br/>
Android 14와 15, 16, 16 QPR2, 17이 영향을 받습니다.<br/>
게시판이 공개된 시점에는 실제 악용 사례가 보고되지 않았습니다.<br/>

#### 패치 레벨 2026-11-01 살펴보기

2026-11-01 패치 레벨은 Framework와 System, Android 런타임의 취약점을 다룹니다.<br/>
Framework에는 `CVE-2026-58868` 외에도 권한 상승과 정보 노출, 서비스 거부 등급의 취약점이 포함됩니다.<br/>
System에도 원격 코드 실행 Critical 등급이 있습니다.<br/>
`CVE-2026-58876`과 `CVE-2026-58936`입니다.<br/>
System의 서비스 거부 Critical 등급으로는 `CVE-2026-58814`와 `CVE-2026-58882`가 있습니다.<br/>
2026-11-01 패치 레벨에 포함된 취약점은 119건입니다.<br/>

#### 패치 레벨 2026-11-05 살펴보기

2026-11-05 패치 레벨은 커널과 칩셋 부품의 취약점을 다룹니다.<br/>
Arm과 Imagination, MediaTek, Unisoc, Qualcomm 부품이 포함됩니다.<br/>
2026-11-05 패치 레벨에 포함된 취약점은 97건입니다.<br/>
2026-11-01만 적용된 단말은 커널과 칩셋 수정분을 받지 못한 상태입니다.<br/>
그래서 게시판은 2026-11-05 이상을 전체 해결의 기준으로 삼습니다.<br/>

#### 단말의 패치 레벨 확인하기

단말의 패치 레벨은 설정에서 확인할 수 있습니다.<br/>
앱에서는 `Build.VERSION.SECURITY_PATCH`로 읽을 수 있습니다.<br/>

```kotlin
val patchLevel = Build.VERSION.SECURITY_PATCH // 예: "2026-11-05"
val isFullyPatched = patchLevel >= "2026-11-05"
```

Google Play 시스템 업데이트로 해결되는 Mainline 부품도 있습니다.<br/>
Media 코덱과 MediaProvider, WiFi 등이 포함됩니다.<br/>
다만 게시판의 모든 수정분이 Play 시스템 업데이트로 오는 것은 아닙니다.<br/>
단말 제조사의 업데이트가 필요합니다.<br/>

### 실무 관점

MTS처럼 금융 앱에서는 단말 패치 상태를 보안 신호로 쓸 수 있습니다.<br/>
`Build.VERSION.SECURITY_PATCH`를 읽어 기준일보다 오래된 단말에는 추가 인증이나 안내를 붙이는 방식을 검토할 수 있습니다.<br/>
다만 패치 레벨만으로 단말을 차단하면 사용자 불편이 커집니다.<br/>
안내와 단계적 조치를 함께 설계하는 것이 좋습니다.<br/>
사내 테스트 단말은 2026-11-05 패치 적용 여부를 먼저 확인하고, 제조사 업데이트 일정을 함께 챙겨야 합니다.<br/>

### 마치며

11월 게시판의 핵심은 Framework 원격 코드 실행 취약점과 두 단계로 나뉜 패치 레벨입니다.<br/>
테스트 단말부터 2026-11-05 적용 여부를 확인하고, 실무 단말의 업데이트 일정을 챙기는 것이 좋습니다.<br/>
