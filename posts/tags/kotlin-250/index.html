Kotlin 2.5.0-RC 살펴보기: 동반자 객체 없이 쓰는 동반자 블록과 확장

2026년 11월 16일 · 약 3분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.

11월 11일에 공개된 Kotlin 2.5.0-RC의 동반자 블록과 동반자 확장에 대해 설명해드리겠습니다.
동반자 블록과 동반자 확장은 Kotlin 2.5.0-RC의 새로운 기능에 포함된 실험적 기능입니다.

배경​

타입 이름으로 접근하는 멤버를 선언하려면 동반자 객체가 필요했습니다.
동반자 객체가 없는 타입에는 이런 멤버를 확장으로 추가할 방법이 없었습니다.
팩토리 함수나 상수를 타입 이름 아래에 두고 싶어도 동반자 객체를 먼저 만들어야 했습니다.
동반자 블록과 동반자 확장은 이 제약을 없애는 기능입니다.

동반자 블록과 확장 살펴보기​

동반자 블록​

동반자 블록은 클래스나 인터페이스 안에 companion 블록을 직접 작성하는 방식입니다.
별도의 객체 인스턴스를 만들지 않고 멤버를 선언할 수 있습니다.
JVM에서는 정적 멤버로 생성되므로 JvmStatic 애너테이션이 필요 없습니다.

data class Vector(val x: Double, val y: Double) {
    companion {
        val Zero: Vector get() = Vector(0.0, 0.0)
    }
}

fun main() {
    println(Vector.Zero) // Vector(x=0.0, y=0.0)
}

동반자 확장​

동반자 확장은 최상위 확장에 companion 변경자를 붙이는 방식입니다.
확장 대상 타입에 동반자 객체가 없어도 타입 이름으로 접근하는 멤버를 선언할 수 있습니다.
타입을 직접 제어하지 않는 경우에도 멤버를 추가할 수 있습니다.

import kotlin.math.cos
import kotlin.math.sin

companion val Vector.UnitX get() = Vector(1.0, 0.0)

companion fun Vector.unit(angle: Double) = Vector(cos(angle), sin(angle))

fun main() {
    println(Vector.UnitX) // Vector(x=1.0, y=0.0)
}

사용 설정​

실험적 기능이므로 컴파일러 옵션을 추가해야 합니다.
동반자 블록만 쓰려면 다음 옵션을 사용합니다.

kotlin {
    compilerOptions {
        freeCompilerArgs.add("-Xcompanion-blocks")
    }
}

동반자 확장까지 쓰려면 다음 옵션을 사용합니다.

kotlin {
    compilerOptions {
        freeCompilerArgs.add("-Xcompanion-blocks-and-extensions")
    }
}

동반자 확장을 사용하면 컴파일러가 정식 출시 전 바이너리를 생성합니다.
그래서 동반자 확장을 쓰는 라이브러리는 기능이 정식화되기 전까지 의존성으로 소비할 수 없습니다.
설계 배경은 동반자 블록과 확장 소개 글에서 확인할 수 있습니다.

실무 관점​

MTS에서는 화면 상태나 요청 파라미터를 타입 이름 아래의 팩토리 함수로 만드는 경우가 많습니다.
동반자 블록을 쓰면 동반자 객체 선언 없이 이런 팩토리를 정리할 수 있습니다.
다만 실험적 기능이므로 앱 모듈에서 먼저 검증하고, 라이브러리 모듈에는 적용하지 않는 것이 좋습니다.
특히 동반자 확장은 바이너리 호환성에 영향을 주므로 공유 모듈에서는 피해야 합니다.

마치며​

동반자 블록과 동반자 확장은 동반자 객체 없이 타입 이름으로 접근하는 멤버를 선언하는 방식을 제공합니다.
팩토리 함수와 상수 정리가 간결해집니다.

Kotlin 2.5.0-RC 살펴보기: 여러 프로퍼티를 갖는 전체 값 클래스

2026년 11월 16일 · 약 3분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.

11월 11일에 공개된 Kotlin 2.5.0-RC의 전체 값 클래스에 대해 설명해드리겠습니다.
전체 값 클래스는 실험적 기능으로, 여러 프로퍼티를 하나의 값으로 묶는 방식을 제공합니다.

배경​

기존 인라인 값 클래스는 하나의 프로퍼티만 가질 수 있었습니다.
여러 값을 묶어야 할 때는 일반 클래스나 데이터 클래스를 사용해야 했습니다.
데이터 클래스는 같은 데이터를 가진 인스턴스라도 참조가 다르면 별개로 구분될 수 있습니다.
값 자체가 본질인 타입에서는 이 참조 구분이 불필요한 제약이 됩니다.
전체 값 클래스는 이런 경우를 위해 프로퍼티 전체가 값이 되는 타입을 제공합니다.

전체 값 클래스 살펴보기​

기본 선언​

전체 값 클래스는 value class 키워드로 선언합니다.
프로퍼티를 여러 개 가질 수 있고, 컴파일러가 equals와 hashCode, toString을 자동으로 생성합니다.
이 점은 데이터 클래스와 비슷합니다.
다만 componentN 함수는 생성되지 않습니다.
대신 이름 기반 구조 분해를 사용합니다.
copy 함수는 제공되지 않으며, 향후 복사 변수 기능으로 대체될 예정입니다.

value class Complex(val real: Double, val imaginary: Double)

fun main() {
    val complex = Complex(1.0, 2.0)
    val (val real, val imaginary) = complex
    println(real)
    println(imaginary)
}

이름 기반 구조 분해에서는 변수 이름이 프로퍼티 이름과 일치해야 합니다.
순서가 바뀌어도 이름이 같으면 올바른 값이 들어갑니다.
이 문법은 2.5.0-RC에서 기본 동작이 되었습니다.

추상 값 클래스​

전체 값 클래스는 추상 클래스로 선언할 수도 있습니다.
인터페이스와 달리 모든 하위 클래스가 실행하는 초기화 로직을 정의할 수 있습니다.
다음 예시에서는 시작 값이 끝 값보다 크지 않은지 생성 단계에서 검증합니다.

sealed value class OrderedInterval<T : Comparable<T>> protected constructor(
    start: T,
    end: T,
) {
    init {
        require(start <= end)
    }
}

value class IntInterval(
    val start: Int,
    val end: Int
) : OrderedInterval<Int>(start, end)

값 객체​

프로퍼티가 없는 전체 값 클래스는 값 객체라고 부릅니다.
하나의 값만 가질 수 있는 상태를 표현할 때 사용합니다.
다음 예시에서는 조회 결과를 찾음과 찾지 못함으로 나눕니다.

sealed interface UserResponse

value class UserFound(val userName: String) : UserResponse
value object UserUnknown : UserResponse

사용 설정​

전체 값 클래스는 실험적 기능이므로 컴파일러 옵션을 추가해야 합니다.
build.gradle.kts에 다음과 같이 작성합니다.

kotlin {
    compilerOptions {
        freeCompilerArgs.add("-Xfull-value-classes")
    }
}

자세한 내용은 Kotlin 2.5.0-RC의 새로운 기능에서 확인할 수 있습니다.

실무 관점​

MTS에서는 금액과 통화를 함께 다루는 타입이 많습니다.
이런 복합 값을 전체 값 클래스로 표현하면 참조 구분에 의존하는 실수를 줄일 수 있습니다.
다만 아직 실험적 기능이고 RC 단계이므로, 프로덕션 모듈에 바로 적용하기보다는 별도 브랜치에서 검증하는 것이 좋습니다.
정식 출시 이후 안정화 여부를 다시 확인해야 합니다.

마치며​

전체 값 클래스는 여러 프로퍼티를 하나의 값으로 묶는 방식을 제공합니다.
데이터 클래스와 비슷하지만 참조 구분이 없는 점이 다릅니다.

Kotlin 2.5.0-RC 살펴보기: 이름 기반 구조 분해와 정식 출시 전 점검 사항

2026년 11월 12일 · 약 3분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.

11월 11일에 공개된 Kotlin 2.5.0-RC에 대해 설명해드리겠습니다.

배경​

Kotlin 2.5.0은 12월 정식 출시를 앞두고 있습니다.
10월 21일에 나온 Beta2에 이어 11월 11일에 RC가 공개되었습니다.
RC는 정식 출시 직전 단계로, 새 기능이 동결되고 안정화 작업이 중심이 됩니다.
이번 RC에서 가장 주목할 변화는 이름 기반 구조 분해의 안정화입니다.

Kotlin 2.5.0-RC 살펴보기​

이름 기반 구조 분해​

기존 구조 분해는 위치 기반으로 동작했습니다.
데이터 클래스의 프로퍼티 순서가 바뀌면 변수에 들어가는 값이 함께 바뀌었습니다.
이름 기반 구조 분해에서는 변수 이름이 프로퍼티 이름과 일치해야 합니다.
순서가 바뀌어도 이름이 같으면 올바른 값이 들어갑니다.

data class Person(val name: String, val age: Int)

val person = Person("way", 33)
val (name, age) = person
val (age, name) = person // 순서가 달라도 이름으로 매칭됩니다

2.5.0에서는 새 문법을 추가 설정 없이 사용할 수 있습니다.
컴파일러는 기존 위치 기반 코드에 대해 마이그레이션 힌트도 함께 제공합니다.
위치 기반이 꼭 필요한 경우에는 대괄호 문법을 사용합니다.

val pair = "way" to 33
val [first, second] = pair

미사용 반환값 검사​

반환값을 무시한 호출을 찾아주는 검사가 추가되었습니다.
실수로 결과를 확인하지 않은 호출을 컴파일 단계에서 발견할 수 있습니다.
Json.encodeToString 같은 호출의 결과를 쓰지 않고 넘기는 경우에 경고를 받을 수 있습니다.

JDK 17 요구 사항​

Beta2부터 JDK 17보다 낮은 버전으로 컴파일러를 실행하면 오류가 발생합니다.
Android Studio는 이미 JDK 17을 내장하고 있어 대부분은 영향이 없습니다.
CI 환경에서 별도 JDK를 지정하고 있다면 버전을 확인해야 합니다.

그 외 변경 사항​

Java 28을 지원합니다.
Swift Export가 새로운 DSL과 함께 베타 단계에 들어갔습니다.
Kotlin/Native 증분 컴파일이 Apple 타겟에서 기본으로 활성화되었습니다.
멀티 필드 값 클래스가 알파 단계로 추가되었습니다.
Lombok의 @Builder 애너테이션은 Kotlin 코드에서 비활성화되었습니다.
Android 프로젝트의 kotlin 블록 안에서 sourceSets를 쓰는 기존 방식이 deprecation 대상으로 지정되었습니다.

RC 적용하기​

Version Catalog에서 Kotlin 버전을 교체하면 RC를 적용할 수 있습니다.

[versions]
kotlin = "2.5.0-RC"

[plugins]
kotlin-android = { id = "org.jetbrains.kotlin.android", version.ref = "kotlin" }

실무 관점​

RC는 프로덕션 적용 대상이 아닙니다.
별도 브랜치에서 빌드와 테스트를 먼저 확인하는 것이 좋습니다.
JDK 버전과 KAPT 사용 여부를 함께 점검해야 합니다.
KAPT를 사용하는 프로젝트라면 릴리스 노트에 정리된 변경 사항을 함께 확인하는 것이 좋습니다.
정식 출시는 12월로 예정되어 있습니다.

마치며​

Kotlin 2.5.0-RC는 이름 기반 구조 분해를 안정화하고, 정식 출시를 위한 마지막 점검 단계에 들어갔습니다.
12월 정식 출시 전에 미리 적용해 보고, JDK 17 요구 사항과 마이그레이션 힌트를 확인해 두는 것이 좋습니다.

Kotlin 2.5.0-Beta2, 이름 기반 구조 분해와 반환값 검사기

2026년 10월 30일 · 약 3분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 21일에 공개된 Kotlin 2.5.0-Beta2에 대해 설명해드리겠습니다.

배경​

기존 구조 분해는 위치를 기준으로 동작했습니다.
프로퍼티 순서가 바뀌면 구조 분해 결과도 함께 바뀌는 문제가 있었습니다.
반환값을 무시하고 호출해도 컴파일러가 이를 지적하지 않는 경우도 있었습니다.
이번 베타는 이런 지점을 언어 차원에서 다듬은 릴리스입니다.

Kotlin 2.5.0-Beta2 살펴보기​

이름 기반 구조 분해​

이름 기반 구조 분해는 only-syntax 모드에서 정식 기능이 되었습니다.
기존 문법 val (name, age)는 위치 기반 동작을 그대로 유지합니다.
새 문법 (val name, val age)는 이름을 기준으로 값을 꺼냅니다.
순서와 무관하게 프로퍼티 이름으로 매칭되므로 리팩터링에 안전합니다.

data class User(val name: String, val age: Int)

fun printUser(user: User) {
    (val age, val name) = user
    println("$name, $age")
}

반환값 검사기​

반환값 검사기는 이번 릴리스에서 기본으로 활성화됩니다.
의미 있는 반환값을 버리고 호출하면 컴파일러가 경고를 냅니다.
검사 강도는 -Xreturn-value-checker 옵션으로 조절할 수 있습니다.
자체 함수에는 MustUseReturnValues 애너테이션으로 검사 대상을 표시할 수 있습니다.

kotlin {
    compilerOptions {
        freeCompilerArgs.add("-Xreturn-value-checker=check")
    }
}

Java 28 지원과 JDK 17 요구 사항​

Kotlin/JVM은 Java 28을 지원합니다.
컴파일러 실행에는 JDK 17 이상이 필요합니다.
Beta1에서는 오래된 JDK에서 경고만 나왔습니다.
Beta2와 정식 2.5.0에서는 오류가 나며, 임시 플래그로만 구버전 사용을 이어갈 수 있습니다.
2.5.20-Beta1부터는 JDK 17 이상이 필수입니다.
CI 머신의 JDK 버전을 먼저 확인하는 것이 좋습니다.

Swift Export와 네이티브 개선​

Swift Export는 새 DSL과 함께 베타 단계에 들어갔습니다.
Kotlin/Native 증분 컴파일은 Apple 타깃에서 기본으로 활성화됩니다.
멀티플랫폼 프로젝트의 iOS 빌드 시간이 줄어들 것으로 기대됩니다.

버전 적용 예시는 다음과 같습니다.

[versions]
kotlin = "2.5.0-Beta2"

실무 관점​

베타 릴리스이므로 운영 모듈에 바로 적용하지 않는 것이 좋습니다.
별도 브랜치에서 컴파일과 테스트를 먼저 통과시키는 것이 안전합니다.
이름 기반 구조 분해는 신규 코드부터 점진적으로 적용할 수 있습니다.
JDK 버전이 낮은 CI가 있다면 릴리스 전에 교체 계획을 세워야 합니다.

마치며​

이름 기반 구조 분해와 반환값 검사기는 코드의 실수를 줄이는 방향의 개선입니다.
JDK 요구 사항까지 함께 확인하면 베타 검증이 한결 수월해집니다.
