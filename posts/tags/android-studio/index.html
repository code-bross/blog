Android Dev Summit 2026 정리: 에이전트와 적응형 UI의 시대

2026년 11월 5일 · 약 5분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 28일부터 29일까지 열린 Android Dev Summit 2026의 핵심 발표를 정리해드리겠습니다.

배경​

이번 서밋은 도구와 에이전트, 에이전트 경험 API, 적응형 UI, XR이라는 네 가지 방향으로 발표가 나뉘었습니다.
구글은 개발자가 원하는 코딩 에이전트를 직접 고를 수 있게 하고, 앱이 에이전트와 연결되는 방식을 넓히는 데 초점을 맞췄습니다.
공개된 내용 중 상당수는 이미 stable 단계에 도달했거나, 베타와 알파로 구분되어 공개되었습니다.
실무에서는 어느 발표가 당장 적용 대상인지, 어느 발표가 준비 단계인지 구분하는 것이 중요합니다.

Android Studio Rabbit 2 살펴보기​

Android Studio Rabbit 2가 stable로 공개되었습니다.
이제 Claude Agent, Codex, Antigravity를 비롯해 40개 이상의 ACP 호환 에이전트를 IDE 안에서 직접 고를 수 있습니다.
에이전트는 에뮬레이터와 빌드 시스템, Logcat 같은 Android Studio의 개발 도구를 함께 쓸 수 있습니다.
Gemini만 쓰던 구조에서 벗어나 팀이 이미 쓰고 있는 에이전트를 그대로 가져올 수 있게 된 점이 가장 큰 변화입니다.

Android CLI 살펴보기​

Android CLI도 에이전트 중심으로 기능이 넓어졌습니다.
Firebase 기반의 Android Device Streaming으로 실제 기기를 원격으로 테스트할 수 있습니다.
에이전트는 Jetpack Compose 프리뷰를 렌더링해서 에뮬레이터나 APK 배포 없이 화면을 바로 확인할 수 있습니다.
프로파일링은 Perfetto 기반의 시스템 트레이스를 수집해 콜드 스타트와 UI 끊김, 백그라운드 깨움을 분석합니다.
Analyze 기능은 앱 번들과 라이브러리의 난독화와 최적화, 축소 점수를 검사해 Play 업로드 전에 품질 문제를 찾습니다.
20개 이상의 영역을 다루는 30개 이상의 Android 스킬도 함께 공개되었습니다.

android init
android skills list

위 명령으로 에이전트용 Android CLI 환경을 초기화하고, 설치된 스킬 목록을 확인할 수 있습니다.
공식 에이전트 플러그인도 Antigravity용에 이어 Claude Code와 Codex용이 새로 나왔습니다.

에이전트 경험을 만드는 API 살펴보기​

앱이 에이전트의 도구가 되는 흐름도 이번 서밋의 한 축입니다.
AppFunctions는 앱 기능을 에이전트가 호출할 수 있게 만드는 통합 도구 호출 계층입니다.
이번 서밋에서 AppFunctions가 베타 단계에 들어섰습니다.
에이전트는 함수 이름과 설명만 보고 호출을 결정하므로, 이름과 KDoc이 곧 스키마라는 점을 염두에 두어야 합니다.

/**
 * 코스피 지수 요약 정보를 반환합니다.
 *
 * @param market 조회할 시장 코드입니다.
 */
@AppFunctionDeclaration(isDescribedByKDoc = true)
suspend fun getIndexSummary(
    market: String
): IndexSummary = withContext(Dispatchers.IO) {
    marketRepository.getIndexSummary(market)
}

A2UI for Jetpack Compose는 알파로 공개되었습니다.
에이전트가 텍스트 답변이 아니라 앱 자체 컴포넌트로 만든 인터랙티브 UI를 반환할 수 있게 됩니다.
네이티브 Jetpack Compose 렌더러가 들어가 앱 안에서 자연스럽게 동작합니다.

ML Kit의 새로운 Agentic API도 알파로 공개되었습니다.
Gemini Nano 4를 기반으로 함수 실행과 대화 기록, 오케스트레이션 루프를 자동으로 처리하고 가드레일도 포함합니다.
온디바이스 에이전트를 만들 때 서버 왕복 없이 기기 안에서 루프를 돌릴 수 있다는 점이 특징입니다.

Connected Apps Platform도 함께 소개되었습니다.
앱 서비스를 Gemini가 시스템 AI 에이전트로 동작하는 사용자에게 공유하는 구조입니다.
지금은 프로토타입 단계이며, 프로덕션 게시를 위해서는 미리보기 프로그램 등록이 필요합니다.

Compose 1.13과 적응형 개발 살펴보기​

다가오는 Compose 1.13 stable에는 적응형 레이아웃 지원이 들어갑니다.
Grid와 Flexbox가 stable로 전환되고, Progressive Blur와 Formatted Text가 새로 추가됩니다.
Navigation 3 1.2는 딥 링크 지원과 함께 stable이 되었습니다.
AppState는 Compose의 반응형 모델을 상태 계층까지 확장하는 알파 단계의 building block입니다.
기기 설정이 바뀌어도 상태를 유지하는 구조를 앱과 AI 에이전트가 함께 쓸 수 있게 만드는 것이 목표입니다.

적응형 개발은 폰과 폴더블, 태블릿, 노트북, 차량, XR까지 한 코드베이스로 대응하는 방향으로 정리되었습니다.
Compose adaptive skill이 업데이트되어 기존 Compose UI를 감사하고 키보드 단축키와 커서, 호버 상태, 툴팁을 자동으로 구현합니다.
내비게이션 패턴 이전과 Grid, Flexbox, mediaQuery 기반의 레이아웃 이전도 skill이 다룹니다.
미디어와 카메라 화면을 폴더블의 테이블탑 레이아웃으로 바꾸는 최적화도 포함되었습니다.
내년부터 Google Play는 폴더블에서의 앱 동작을 자세히 살피고, 적응형으로 잘 만든 앱에 더 많은 노출 기회를 줄 예정입니다.
구체적인 스토어 요구사항은 올해 안에 발표될 예정입니다.

@Composable
fun AdaptiveStockList() {
    BoxWithConstraints {
        if (maxWidth > 600.dp) {
            StockGrid()
        } else {
            StockList()
        }
    }
}

XREAL과 함께 XREAL AURA가 공개되었습니다.
Android XR 기반의 첫 유선 XR 글라스입니다.
SceneCore와 ARCore for Jetpack XR, XR Runtime을 비롯한 핵심 Jetpack XR SDK 라이브러리가 stable이 되었습니다.
Android Studio의 Android XR 에뮬레이터도 stable이 되어 실물 기기 없이 XR 글라스 경험을 검증할 수 있습니다.

실무 관점​

MTS 앱에 적용한다면, 단계를 나눠 접근하는 것이 안전합니다.
Rabbit 2의 BYOA는 stable이므로 팀이 이미 쓰는 에이전트를 IDE에 연결하는 것부터 검토할 수 있습니다.
AppFunctions는 베타, A2UI와 ML Kit Agentic API는 알파 단계이므로 프로덕션 노출보다 내부 빌드에서의 검증이 먼저입니다.
AppFunctions에 노출할 함수는 조회처럼 부작용이 없는 것부터 시작하고, 주문이나 이체처럼 돈이 움직이는 동작은 대상에서 빼는 편이 안전합니다.
Compose 1.13의 적응형 기능은 폴더블 대응을 준비하는 팀이라면 미리 살펴볼 만합니다.
내년 Play의 폴더블 평가에 대비해 Compose adaptive skill로 현재 화면을 한 번 감사해 보는 것도 좋습니다.

마치며​

이번 서밋은 에이전트를 IDE에 들이는 것과 앱을 에이전트에 연결하는 것, 두 방향을 동시에 제시했습니다.
적응형 UI까지 합치면, 앞으로의 Android 개발은 폼팩터와 에이전트라는 두 축으로 넓어질 것으로 보입니다.

IntelliJ IDEA 2026.3 살펴보기: Kotlin 개발자를 위한 수정 사항 정리

2026년 11월 5일 · 약 3분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
최근 공개된 IntelliJ IDEA 2026.3의 주요 수정 사항을 정리해드리겠습니다.

배경​

이번 릴리스는 1,000개가 넘는 버그 수정과 300개가 넘는 성능 수정을 담았습니다.
성능과 Java, Kotlin 코드 인텔리전스, 그리고 매일 쓰는 핵심 워크플로에 집중한 릴리스입니다.
수정 대부분은 사용자의 오류 보고와 UI 멈춤 보고를 바탕으로 우선순위가 정해졌습니다.
Android Studio를 매일 쓰는 개발자에게도 IDE 기반이 되는 IntelliJ 플랫폼의 변화는 바로 체감되는 부분입니다.

Kotlin 살펴보기​

CancellationException 검사​

새로운 검사는 suspend 코드에서 CancellationException을 잡고 다시 던지지 않는 경우를 경고합니다.
빠른 수정도 함께 제공됩니다.
코루틴 취소는 예외를 다시 던져야 전파되는 구조라, 잡아서 삼키면 취소가 조용히 사라집니다.
특히 네트워크 재시도나 리소스 정리 로직에서 흔히 만나는 실수입니다.

suspend fun loadQuotes() {
    try {
        quoteRepository.refresh()
    } catch (e: CancellationException) {
        throw e
    }
}

위처럼 취소 예외는 반드시 다시 던져야 합니다.
잡아서 로그만 남기고 끝내면 코루틴 취소가 전파되지 않습니다.

suspend 람다의 블로킹 호출 표시​

suspend 람다 안에서 블로킹 호출이 일어나면 이제 에디터에서 강조 표시됩니다.
suspend 함수 안에서 블로킹 I/O를 직접 호출하면 스레드를 점유한 채 멈추게 됩니다.
컴파일은 되지만 런타임에 성능 문제로 이어지는 유형이라, 에디터 단계에서 잡아주는 것이 도움이 됩니다.

suspend fun readCache(): String {
    return withContext(Dispatchers.IO) {
        fileReader.read()
    }
}

블로킹 작업은 위처럼 Dispatchers.IO로 전환해서 실행하는 것이 원칙입니다.

Java를 Kotlin으로 변환할 때 Lombok 처리​

Java를 Kotlin으로 변환할 때 @lombok.Data 클래스가 이제 data class로 변환됩니다.
기존에는 변환 뒤에 data class 정리를 손으로 다시 해야 하는 경우가 있었습니다.
서버 코드나 공유 모듈을 Kotlin으로 옮기는 팀이라면 변환 품질이 조금씩 나아지는 변화입니다.

프로젝트 가져오기 살펴보기​

대규모 Maven과 Gradle 프로젝트 가져오기가 최적화되었습니다.
Kotlin 저장소를 Gradle 9.7로 가져올 때 5분이 걸리던 과정이 대부분 오류 처리 시간이었다는 문제가 수정되었습니다.
원격 개발 호스트에서 가져오기 중 발생하던 데드락도 사라졌습니다.
IDE를 실행할 때 필요하지 않은 상황에서는 WSL이 더 이상 자동으로 시작되지 않습니다.
대형 멀티모듈 프로젝트를 여는 일이 잦은 팀일수록 체감 폭이 큰 수정입니다.

IDE 전반의 개선 살펴보기​

JaCoCo가 새로운 Java 실행 설정의 기본 커버리지 러너가 되었습니다.
Gradle과 Maven, CI 시스템, SonarQube가 이미 쓰는 러너라 IDE와 파이프라인의 커버리지 수치가 일치합니다.
Git worktree는 이제 멀티 루트 프로젝트에서도 동작하고, 별도의 worktree에서 머지 요청을 열 수 있습니다.
GitLab 계정은 개인 액세스 토큰을 붙여넣지 않고 브라우저 로그인으로 연결할 수 있게 되었습니다.
터미널은 ghostty 에뮬레이터를 도입했고 40개가 넘는 수정이 함께 들어갔습니다.
플러그인 관리 화면은 설치됨과 마켓플레이스 탭이 하나로 합쳐져 한 번의 검색으로 찾을 수 있게 되었습니다.
MCP 서버 포트도 설정에서 직접 바꿀 수 있게 되었습니다.

실무 관점​

MTS 앱에 적용한다면, CancellationException 검사가 가장 먼저 눈에 들어옵니다.
코루틴 취소 전파는 시세 갱신이나 주문 조회처럼 반복 호출되는 코드에서 조용히 틀어지기 쉬운 부분입니다.
이번 릴리스로 업데이트한 뒤에는 기존 suspend 코드에서 경고가 뜨는지 먼저 확인해 보는 것이 좋습니다.
JaCoCo 기본값 변경은 IDE와 CI의 커버리지 수치를 맞추는 데 도움이 됩니다.
Gradle 가져오기 개선은 멀티모듈 프로젝트를 매일 여닫는 팀이라면 업데이트할 이유가 됩니다.

마치며​

이번 릴리스는 새 기능보다 멈춤과 가져오기 속도, Kotlin 검사를 다듬는 데 무게가 실렸습니다.
IDE 업데이트를 미뤄 왔다면, 이번 2026.3은 부담 없이 올릴 만한 릴리스입니다.

Android Studio Rabbit 3 Canary 2 살펴보기

2026년 11월 4일 · 약 3분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
Canary 채널에 올라온 Android Studio Rabbit 3 Canary 2에 대해 설명해드리겠습니다.

배경​

Rabbit 2는 현재 Stable 채널에 있습니다.
다음 버전인 Rabbit 3은 Canary 채널에서 제공되고 있습니다.
Canary 빌드는 최신 기능을 먼저 써볼 수 있지만 가볍게 테스트된 단계입니다.
기능이 추가되거나 변경될 수 있다는 전제가 붙습니다.
Canary 2는 Android Gradle Plugin 9.6.0-alpha02와 함께 릴리스됐습니다.
프리뷰 버전의 Studio는 대응하는 프리뷰 AGP와 함께 쓰는 것이 원칙입니다.
이번 글에서는 Rabbit 3에 새로 들어온 기능 네 가지를 살펴보겠습니다.

Rabbit 3 살펴보기​

Compose Preview Screenshot Testing 도구​

Compose UI의 회귀를 막는 스크린샷 테스트 도구가 들어왔습니다.
이 도구는 Compose 프리뷰를 기준으로 스크린샷 테스트를 수행합니다.
결과는 HTML 리포트로 생성돼 UI 변화를 눈으로 확인할 수 있습니다.
디자인 시스템 컴포넌트처럼 화면이 자주 바뀌는 영역에 유용합니다.
스냅샷 비교를 수동 눈대중이 아니라 테스트로 고정할 수 있습니다.

Model Assignment​

AI 모델을 작업 종류별로 다르게 지정하는 기능입니다.
복잡한 추론이 필요한 Agent Mode에는 큰 규모의 모델을 지정할 수 있습니다.
커밋 메시지 생성이나 다음 편집 예측처럼 지연에 민감한 작업에는 가벼운 모델을 지정합니다.
이렇게 하면 품질과 속도, 쿼터 사용량을 작업별로 균형 있게 조절할 수 있습니다.
설정은 다음 경로에서 변경합니다.

File > Settings > Tools > AI > Model Providers > Model Assignment 탭

Agent Mode 패널의 모델 선택 드롭다운에서 직접 바꾸는 방법도 있습니다.
이 경우 Thinking 기능에 대한 Model Assignment 설정이 함께 업데이트됩니다.

iOS, Flutter, React Native 앱 마이그레이션​

기존 크로스 플랫폼 앱을 네이티브 Android 앱으로 바꾸는 도구가 들어왔습니다.
새 프로젝트 마법사에서 마이그레이션 어시스턴트를 호출합니다.
변환 대상은 iOS와 Flutter, React Native 프로젝트입니다.
결과물은 Kotlin과 Jetpack Compose 기반의 Android 앱입니다.
작업 계획과 코드 변환, 컴파일 검사가 통합 진행 UI로 보입니다.
결과물은 바로 테스트와 검증이 가능한 기능하는 프로젝트 형태입니다.

Publish to Google Play for testing​

Play Console 테스트 트랙에 IDE에서 바로 업로드하는 기능이 들어왔습니다.
서명된 앱 번들 생성 흐름이 끝나는 지점에서 이어서 선택합니다.
새 앱의 첫 릴리스는 내부 테스트 트랙에 업로드할 수 있습니다.
기존 앱은 다른 종류의 테스트 트랙에도 업로드할 수 있습니다.
이 기능을 쓰려면 Google Play Console에 등록돼 있어야 합니다.

실무 관점​

Canary는 Stable과 별도로 설치해 운영하는 것이 안전합니다.
운영 프로젝트의 빌드 환경을 Canary로 통째로 옮기는 것은 피하는 것이 좋습니다.
스크린샷 테스트는 전체 화면보다 디자인 시스템 컴포넌트부터 적용하는 것이 좋습니다.
Model Assignment는 쿼터가 소진되는 지점을 확인하면서 조정하는 것이 좋습니다.
Play 테스트 업로드는 내부 트랙부터 검증하고, 이후 트랙을 넓히는 순서가 안전합니다.
마이그레이션 도구는 자동 변환 결과를 그대로 운영에 쓰기보다 컴파일과 동작 검증 뒤에 적용합니다.

마치며​

Rabbit 3는 AI 모델 선택과 UI 회귀 방지, 마이그레이션, 테스트 배포를 한 번에 다룹니다.
Canary라는 전제를 지키면서, 팀에 맞는 기능부터 별도 환경에서 검증하는 것이 좋습니다.

Android Studio Rabbit 2와 Bring Your Own Agent, 에이전트 시대의 IDE

2026년 10월 29일 · 약 4분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 28일에 열린 Android Dev Summit 2026에서 공개된 Android Studio Rabbit 2와 Bring Your Own Agent에 대해 설명해드리겠습니다.

배경​

그동안 Android Studio의 AI 기능은 Google이 제공하는 에이전트 중심으로 제공되었습니다.
팀에서 이미 사용 중인 에이전트가 따로 있는 경우, IDE 안에서 그 에이전트를 그대로 쓰기 어려웠습니다.
에이전트는 열려 있는 파일만 읽는 수준에서는 디버깅에 한계가 있습니다.
프로젝트 구조와 빌드 상태, 에뮬레이터와 로그까지 함께 볼 수 있어야 실제 개발 작업에 쓸 수 있습니다.

Android Studio Rabbit 2 살펴보기​

Bring Your Own Agent​

Bring Your Own Agent은 오픈 프로토콜인 Agent Client Protocol을 이용해 외부 코딩 에이전트를 IDE 안에 직접 연결하는 기능입니다.
이번 Rabbit 2 정식 버전에서 안정화되었으며, 40개 이상의 ACP 호환 에이전트를 지원합니다.
대표적으로 Claude Agent와 Codex, Google Antigravity를 마켓플레이스에서 설치해 사용할 수 있습니다.
설정은 Settings > Tools > AI > Agents 메뉴에서 진행합니다.
여러 에이전트를 함께 설치해 두고 작업 중간에 전환할 수도 있습니다.
연결된 에이전트는 프로젝트 구조와 빌드 진단, 심볼 해석, Compose Preview 렌더링, 에뮬레이터와 Logcat에 접근합니다.

Change Review​

에이전트가 만든 큰 변경 사항을 검토하는 일은 그 자체로 부담이 됩니다.
Change Review는 보류 중인 에이전트 변경 사항이나 Git 변경 창에서 검토 세션을 시작하는 기능입니다.
잠재적인 문제를 정리한 보고서를 만들고, 에이전트 도구 창에서 /review 명령으로 호출할 수도 있습니다.
긴 변경 사항은 AI 안내 워크스루로 흐름을 파악하고, 발견된 문제는 에이전트가 직접 수정하게 할 수 있습니다.

Android CLI​

터미널과 CI 파이프라인에서도 에이전트가 Android 도구 체인을 쓸 수 있게 Android CLI가 강화되었습니다.
android device remote 명령으로 Google 기기 랩의 실제 기기를 원격으로 할당받아 테스트할 수 있습니다.
android preview 명령은 에뮬레이터나 IDE 없이 Compose Preview를 터미널에서 렌더링합니다.
Google 내부 테스트에서는 이 방식을 쓴 에이전트가 UI 작업을 77% 더 빠르게 마쳤고, 토큰 사용량은 최대 3분의 1 수준이었다고 밝혔습니다.
Claude Code와 Codex용 공식 Android 플러그인도 함께 공개되었습니다.

android device remote
android preview
android profiler leakcanary
android signals
android analyze

LeakCanary와 성능 분석​

메모리 누수는 OOM 크래시로 이어지기 전까지 조용히 앱을 느리게 만듭니다.
Android CLI에는 LeakCanary를 직접 통합한 android profiler leakcanary 명령이 추가되었습니다.
힙 덤프를 기기가 아니라 컴퓨터에서 분석하므로 앱 속도가 느려지지 않습니다.
Android Studio Profiler에도 LeakCanary가 내장되었고, Canary 빌드에서는 Fix with AI로 누수 원인과 수정안을 함께 볼 수 있습니다.
성능 분석 쪽에서는 Android Performance Analyzer가 CLI의 android profiler 명령을 지원하게 되었습니다.
R8 설정 분석은 AGP 9.3에 내장된 R8 Configuration Analyzer로 확인할 수 있으며, ./gradlew :app:analyzeReleaseR8Config 명령으로 보고서를 만듭니다.

./gradlew :app:analyzeReleaseR8Config

실무 관점​

MTS 앱 관점에서는 에이전트 선택의 자유보다 검증 경로가 먼저입니다.
에이전트가 만든 변경 사항은 Change Review로 한 번 걸러낸 뒤, 실제 기기 테스트와 릴리스 심사로 이어지는 흐름이 필요합니다.
금융 앱은 개인정보와 보안 정책이 엄격하므로, 외부 에이전트에 프로젝트 접근을 허용하기 전에 조직의 보안 기준을 먼저 확인해야 합니다.
android preview와 android analyze 같은 CLI 명령은 CI에 붙이기 좋은 형태라, 코드 리뷰 자동화에 활용할 여지가 있습니다.

마치며​

Rabbit 2는 IDE를 특정 에이전트에 묶지 않고, 개발자가 고른 에이전트를 IDE의 이해력과 연결했습니다.
에이전트가 코드를 만드는 단계에서, 만든 결과를 검증하는 단계까지 IDE 안에서 이어지게 된 점이 이번 발표의 핵심입니다.
