Jetpack Compose 1.13 안정화 버전 살펴보기

2026년 11월 25일 · 약 4분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.

2026년 11월 18일에 공개된 Jetpack Compose November '26 릴리스에 대해 설명해드리겠습니다.

이번 릴리스는 코어 Compose 모듈 전반이 1.13으로 안정화되었습니다.
그래픽, 텍스트, 레이아웃, 성능 영역에 걸쳐 새로운 기능이 추가되었고, 주의해야 할 변경 사항도 함께 포함되었습니다.

배경​

기존에는 점진적 블러나 다각형 모양을 구현하려면 별도의 라이브러리를 직접 사용해야 했습니다.
다각형 모양은 graphics-shapes 의존성을 추가하고, 픽셀 크기에 맞는 도형을 만든 뒤 경로로 변환하는 과정이 필요했습니다.
또한 Flow 레이아웃과 ConstraintLayout 등 여러 레이아웃 방식이 공존하면서 선택 기준이 모호한 경우도 있었습니다.
이번 릴리스는 이런 영역을 정리하고, 자주 쓰이는 패턴을 기본 기능으로 끌어올렸습니다.

Compose 1.13 살펴보기​

업데이트를 적용하려면 Compose BOM을 2026.11.01로 올립니다.
이 업그레이드에는 Kotlin 2.2 이상과 compileSdk 37.1이 필요합니다.

dependencies {
    implementation(platform("androidx.compose:compose-bom:2026.11.01"))
}

점진적 블러​

Compose 1.13에서는 요소가 선명한 상태에서 흐릿한 상태로 자연스럽게 전환되는 점진적 블러를 지원합니다.
Modifier.blur의 람다 형태와 BlurRadiusSpec을 사용합니다.
선형 그라데이션, 방사형 그라데이션, 커스텀 AGSL 셰이더를 이용한 블러 맵까지 표현할 수 있습니다.

Modifier.blur {
    blurRadiusSpec = BlurRadiusSpec.linearGradient(
        start = DpOffset.Zero,
        end = DpOffset(size.width, size.height),
        stops = listOf(
            BlurStop(fraction = 0f, radius = 0.dp),
            BlurStop(fraction = 0.5f, radius = 0.dp),
            BlurStop(fraction = 0.75f, radius = 14.dp),
            BlurStop(fraction = 1f, radius = 28.dp),
        ),
    )
}

헤더 이미지의 하단 가장자리를 배경에 녹이는 효과나, 터치 위치를 따라가는 스포트라이트 효과에 활용할 수 있습니다.
다이얼로그와 팝업에도 블러 관련 속성을 직접 지정할 수 있게 되었습니다.
DialogProperties에서는 blurBehindRadius와 backgroundBlurRadius, scrimAlpha, windowShape을 설정할 수 있습니다.

다각형 모양과 모핑​

PolygonShape과 MorphPolygonShape이 androidx.compose.foundation에 추가되었습니다.
PolygonShape은 일반적인 Compose Shape이므로 Modifier.clip이나 컴포넌트의 shape 파라미터에 그대로 사용할 수 있습니다.
레이아웃 크기에 맞게 자동으로 조정되므로 별도의 크기 계산이 필요 없습니다.
MorphPolygonShape은 리컴포지션 없이 진행률 람다를 읽어 두 다각형 모양 사이를 애니메이션으로 전환합니다.

var recording by remember { mutableStateOf(false) }
val progress by animateFloatAsState(if (recording) 1f else 0f)
val shape = remember {
    MorphPolygonShape(
        start = PolygonShape.circle(),
        end = PolygonShape.star(
            numPoints = 9,
            innerRadiusRatio = 0.8f,
            outerRounding = CornerRounding.fraction(0.5f),
        ),
        progress = { progress },
    )
}

Box(
    Modifier
        .size(96.dp)
        .clip(shape)
        .background(MaterialTheme.colorScheme.primary)
        .clickable { recording = !recording }
)

Material 3 1.5.0​

Compose Material 3 버전 1.5.0이 안정화되었습니다.
Slider와 RangeSlider는 SliderState를 사용하는 상태 기반 모델로 전환되었습니다.
ToggleButtons와 WavyProgressIndicators, TimePickers 같은 새로운 컴포넌트가 추가되었습니다.
실험적 애너테이션은 120개에서 58개로 52% 줄었습니다.
이와 함께 Compose Material 2 라이브러리는 더 이상 적극적으로 유지보수되지 않으며, Material 3으로의 마이그레이션이 권장됩니다.

텍스트와 레이아웃​

값 기반 BasicTextField와 Material 2의 TextField는 공식적으로 deprecated 되었습니다.
상태 기반 BasicTextField와 TextFieldState API로의 전환이 권장됩니다.
LineHeightStyle.Mode.PerLine이 추가되어, 다국어 텍스트에서 줄마다 높이를 독립적으로 계산할 수 있게 되었습니다.
FlexBox와 Grid 레이아웃은 Compose 1.11에서 실험적으로 도입된 뒤 이번 릴리스에서 안정화되었습니다.
FlexBox는 Flow 레이아웃을 대체하며, 새 코드에서는 FlowRow와 FlowColumn 대신 FlexBox 사용이 권장됩니다.
반면 Compose용 ConstraintLayout과 MotionLayout은 deprecated 되었습니다.

성능​

computedStateOf는 derivedStateOf의 가벼운 대안으로 도입되었습니다.
계산 결과를 캐시하지 않으므로, 자주 변경되는 상태에서 조건 검사나 필터링을 수행할 때 오버헤드가 적습니다.
무거운 계산이나 캐시가 필요한 경우에는 derivedStateOf를 계속 사용하는 것이 권장됩니다.
LazyLayoutCacheWindow도 안정화되어, 지연 레이아웃의 윈도우 기반 프리페치가 기본 동작이 되었습니다.

실무 관점​

업데이트 전에 Kotlin 버전과 compileSdk 요구 사항을 먼저 확인해야 합니다.
Kotlin 2.2 이상과 compileSdk 37.1을 충족하지 못하면 빌드가 실패합니다.
값 기반 텍스트 필드와 ConstraintLayout을 사용 중인 화면은 deprecated 경고를 확인하고 마이그레이션 계획을 세워야 합니다.
특히 MTS처럼 화면이 많은 프로젝트에서는 텍스트 필드 마이그레이션을 한 번에 적용하기보다 화면 단위로 나누어 진행하는 것이 안전합니다.

마치며​

Compose 1.13은 그래픽 표현력과 레이아웃 선택지를 넓히면서도, 오래된 API를 정리한 릴리스입니다.
BOM 업데이트와 함께 deprecated 항목을 점검하면 안정적으로 적용할 수 있을 것으로 보입니다.

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
11월 18일에 정식 출시된 Compose 1.13에 대해 설명해드리겠습니다.

배경​

Compose 1.13은 핵심 Compose 모듈 전체를 1.13.0으로 올리는 정식 릴리스입니다.
업데이트는 Compose BOM 2026.11.01로 적용합니다.
이번 업그레이드에는 Kotlin 2.2 이상과 compileSdk 37.1이 필요합니다.
새 기능도 많지만, 이번 릴리스에서 더 중요한 부분은 종료되는 API입니다.
Material 2와 값 기반 텍스트 필드, Compose용 ConstraintLayout이 공식적으로 deprecated 되었습니다.
버전만 올리는 업데이트가 아니라, 마이그레이션 계획을 세워야 하는 릴리스입니다.

Compose 1.13 살펴보기​

프로그레시브 블러​

Compose 1.13에는 선명함에서 흐림으로 서서히 전환되는 프로그레시브 블러가 들어왔습니다.
Modifier.blur의 람다 형태와 BlurRadiusSpec을 사용합니다.
선형 그라데이션과 방사형 그라데이션, 커스텀 AGSL 셰이더를 이용한 블러 맵을 지정할 수 있습니다.
헤더 이미지 하단을 배경에 녹이거나, 터치 위치를 따라 초점을 이동시키는 효과를 구현할 수 있습니다.

Modifier.blur {
    blurRadiusSpec = BlurRadiusSpec.linearGradient(
        start = DpOffset.Zero,
        end = DpOffset(size.width, size.height),
        stops = listOf(
            BlurStop(fraction = 0f, radius = 0.dp),
            BlurStop(fraction = 0.5f, radius = 0.dp),
            BlurStop(fraction = 0.75f, radius = 14.dp),
            BlurStop(fraction = 1f, radius = 28.dp),
        ),
    )
}

DialogProperties와 PopupProperties에는 배경 블러 반경과 스크림 투명도를 직접 지정할 수 있게 되었습니다.
시스템의 창 간 블러 활성화 여부는 WindowInfo.isCrossWindowBlurEnabled로 조회합니다.

폴리곤 셰이프와 모핑​

PolygonShape과 MorphPolygonShape이 androidx.compose.foundation에 추가되었습니다.
기존에는 별이나 둥근 다각형을 쓰려면 graphics-shapes 의존성을 직접 추가하고 RoundedPolygon을 Path로 변환한 뒤 Shape을 직접 구현해야 했습니다.
PolygonShape은 일반 Compose Shape이라 Modifier.clip이나 컴포넌트의 shape 파라미터에 그대로 쓸 수 있습니다.
MorphPolygonShape은 리컴포지션 없이 진행률 람다를 읽어 두 도형 사이를 애니메이션합니다.

var recording by remember { mutableStateOf(false) }
val progress by animateFloatAsState(if (recording) 1f else 0f)
val shape = remember {
    MorphPolygonShape(
        start = PolygonShape.circle(),
        end = PolygonShape.star(
            numPoints = 9,
            innerRadiusRatio = 0.8f,
            outerRounding = CornerRounding.fraction(0.5f),
        ),
        progress = { progress },
    )
}

Box(
    Modifier
        .size(96.dp)
        .clip(shape)
        .background(MaterialTheme.colorScheme.primary)
        .clickable { recording = !recording }
)

Material 3 1.5.0과 Material 2 종료​

Material 3 1.5.0도 함께 정식 출시되었습니다.
Slider와 RangeSlider가 SliderState 기반의 상태 모델로 바뀌었습니다.
ToggleButtons와 물결 모양 프로그레스 인디케이터, 타임 피커 같은 익스프레시브 컴포넌트가 추가되었습니다.
실험 API 표기는 120개에서 58개로 줄었고, 대부분의 익스프레시브 컴포넌트가 정식으로 승격되었습니다.
Material 3가 나온 지 6년째가 되는 이번 릴리스에서 Compose Material 2는 deprecated 되었고, 더 이상 적극적으로 유지보수되지 않습니다.
Material 2를 쓰고 있다면 Material 3로의 이전을 계획해야 합니다.

상태 기반 텍스트 필드로의 이전​

값 기반 BasicTextField와 Material 2 TextField가 공식적으로 deprecated 되었습니다.
대신 TextFieldState 기반의 상태 기반 BasicTextField를 사용합니다.
Material 3의 값 기반 TextField 오버로드는 1.5.0에서 아직 deprecated 되지 않았지만, 공식 문서는 상태 기반 오버로드로의 이전을 권장합니다.
TextFieldState는 서식이 적용된 스타일의 저장과 복원을 기본으로 지원합니다.
동기식 상태 모델과 성능 개선이 장점입니다.
VisualTransformation도 이번 릴리스에서 deprecated 되었고, InputTransformation과 OutputTransformation이 그 자리를 대신합니다.

val textFieldState = rememberTextFieldState()

BasicTextField(
    state = textFieldState,
    modifier = Modifier.fillMaxWidth(),
)

computedStateOf​

런타임 1.13.0에는 computedStateOf라는 새로운 상태 계산 API가 들어왔습니다.
derivedStateOf의 가벼운 대안으로, 스크롤 위치나 애니메이션 임계값처럼 자주 바뀌는 상태에서 조건 검사나 필터링 결과를 계산할 때 사용합니다.
DerivedState는 계산 결과를 캐시하지만, ComputedState는 값을 읽을 때마다 계산을 다시 수행합니다.
계산이 무겁지 않다면 derivedStateOf보다 오버헤드가 적습니다.
두 API 모두 입력 상태가 바뀔 때가 아니라 계산 결과가 바뀔 때만 컴포지션을 무효화합니다.
무거운 계산이나 캐시가 필요한 경우에만 derivedStateOf를 쓰고, 그 외에는 computedStateOf를 쓰는 것이 권장됩니다.

val listState = rememberLazyListState()
val showTopBar by remember {
    computedStateOf { listState.firstVisibleItemIndex > 0 }
}

CapturedAnimatedVisibility​

AnimatedVisibility는 종료 애니메이션이 끝날 때까지 나가는 콘텐츠와 상태를 유지해야 합니다.
상세 화면을 닫으면서 선택 항목을 null로 지우면, 보여줄 내용이 없어 깜빡이거나 빈 화면이 나타납니다.
Compose 1.13의 CapturedAnimatedVisibility는 visible이 false가 되는 순간의 마지막 프레임을 스냅샷으로 캡처해 애니메이션합니다.
호출하는 쪽에서 상태를 즉시 지워도 종료 애니메이션은 화면에 남아 있던 모습 그대로 진행됩니다.
공식 벤치마크에서는 종료 시 프레임 시간이 AnimatedVisibility보다 7~8% 빠릅니다.
나가는 콘텐츠가 계속 살아 있어야 하거나 자식에 Modifier.animateEnterExit을 써야 할 때는 기존 AnimatedVisibility를 씁니다.

@Composable
fun TrackDetails(track: Track?) {
    CapturedAnimatedVisibility(
        visible = track != null,
        enter = fadeIn() + expandVertically(),
        exit = fadeOut(tween(800)) + shrinkVertically(tween(800)),
    ) {
        if (track != null) {
            TrackCard(track)
        }
    }
}

테스트 실패 진단​

UI 테스트가 실패한 순간의 화면 상태와 시맨틱 계층을 확인하는 기능이 Compose 1.13에 들어왔습니다.
ComposeUiTestConfig의 TestFailurePolicy로 실패 시 스크린샷과 UI 계층 구조를 자동으로 저장할 수 있습니다.
TestFailureHandler를 등록하면 실패 맥락과 생성된 아티팩트를 받아 외부 리포팅 도구로 전달할 수도 있습니다.
build.gradle.kts의 testInstrumentationRunnerArguments로 테스트 스위트 전체에 캡처를 켤 수도 있습니다.

val customConfig = ComposeUiTestConfig(
    failurePolicy = TestFailurePolicy(
        screenshotCaptureMode = TestFailurePolicy.CaptureMode.Enabled,
        uiHierarchyCaptureMode = TestFailurePolicy.CaptureMode.Enabled,
    )
)

@Test
fun myTest() = runComposeUiTest(config = customConfig) {
    // 테스트 내용
}

레이아웃과 동작 변경​

1.11.0에서 실험 API로 들어온 FlexBox와 Grid가 정식으로 승격되었습니다.
FlexBox에는 한 줄에 들어가는 항목 수를 제한하는 maxItemsInEachLine 설정이 추가되었습니다.
FlowRow와 FlowColumn 대신 새 코드에는 FlexBox를 쓰는 것이 권장됩니다.
반대로 Compose용 ConstraintLayout과 MotionLayout은 deprecated 되었습니다.
공유 요소 API 등 새로운 대안이 마련되었기 때문입니다.
Modifier.onFocusedBoundsChanged는 1.12에서 deprecated 된 뒤 1.13에서 구현이 제거되어 더 이상 동작하지 않습니다.
포커스된 요소의 영역이 필요하다면 FocusTargetModifierNode.getFocusedRect()를 사용합니다.
Modifier.clickable로 만든 클릭 요소는 이제 시스템 사운드 설정에 따라 표준 상호작용 효과음을 자동으로 재생합니다.

실무 관점​

국내 MTS 프로젝트에 적용한다면, 버전 업데이트와 마이그레이션을 분리해서 계획하는 것이 좋습니다.
BOM을 2026.11.01로 올리고 빌드가 통과하는지 먼저 확인합니다.
그 다음 Material 2 사용처와 값 기반 텍스트 필드, Compose용 ConstraintLayout 사용처를 목록으로 뽑습니다.
TextFieldState 기반 필드는 입력 처리와 서식 저장 방식이 달라지므로, 입력 화면부터 단계적으로 옮기는 것이 안전합니다.
computedStateOf는 스크롤 위치에 따라 앱바를 보이거나 숨기는 것처럼 자주 바뀌는 상태를 다루는 곳부터 적용해 볼 수 있습니다.
TestFailurePolicy는 CI에서 실패 원인을 찾는 시간을 줄여주므로, UI 테스트가 있는 모듈에 먼저 적용하는 것이 좋습니다.

마치며​

Compose 1.13은 새 기능보다 종료되는 API가 더 중요한 릴리스입니다.
프로그레시브 블러와 상태 기반 텍스트 필드, computedStateOf 같은 새 기능은 단계적으로 적용하면 됩니다.

Compose 1.13.0-rc01 살펴보기 — API가 확정된 1.13과 Slider 변경점

2026년 11월 6일 · 약 3분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 11월 4일에 공개된 Compose 1.13.0-rc01과 Material3 1.5.0-rc01에 대해 설명해드리겠습니다.

배경​

현재 stable 버전은 Compose 1.12.1과 Material3 1.4.0입니다.
1.13 라인은 10월 7일 beta01, 10월 21일 beta02를 거쳐 11월 4일 RC 단계에 들어갔습니다.
RC는 API 표면이 확정된 예비 stable 릴리스입니다.
이 글은 10월 8일 beta01 글과 10월 26일 beta02 글의 후속으로, RC에서 확정된 변경점을 중심으로 정리했습니다.

Compose 1.13.0-rc01 살펴보기​

Kotlin 2.2가 필요합니다​

Compose 1.13 라이브러리는 Kotlin 2.2를 대상으로 빌드되며, 컴파일러도 2.2가 필요합니다.
업데이트 전에 libs.versions.toml의 Kotlin 버전을 먼저 확인합니다.

[versions]
kotlin = "2.2"

Slider에서 onValueChange이 필수가 되었습니다​

Slider, VerticalSlider, RangeSlider에서 onValueChange이 필수 파라미터가 되었습니다.
기존에 숨겨져 있던 deprecated API와 SliderState의 DraggableState 구현, 구형 Saver 오버로드가 제거되었습니다.
SliderState의 isVertical도 제거되었고, SliderDefaults.Thumb의 SliderState 오버로드는 isVertical 오버로드로 대체되었습니다.

var value by remember { mutableFloatStateOf(0.5f) }

Slider(
    value = value,
    onValueChange = { value = it },
)

기존 코드에서 onValueChange을 생략한 Slider가 있다면 컴파일 단계에서 바로 드러납니다.
값 변경을 받지 않는 표시 전용 슬라이더는 onValueChange에 빈 람다를 넘기는 대신, 읽기 전용 표시 방식을 검토하는 편이 낫습니다.

MediaQuery의 Posture가 WindowPosture로 바뀌었습니다​

MediaQuery의 Posture 클래스가 WindowPosture로 대체되었습니다.
WindowPosture는 물리적인 WindowFold를 FoldState와 FoldOrientation으로 노출합니다.
isTabletop과 isFlat 편의 프로퍼티가 추가되었고, 기존의 Book 자세 구분은 제거되었습니다.

if (posture.isTabletop) {
    // 접은 상태에서는 하단 화면에 컨트롤을 배치합니다.
} else if (posture.isFlat) {
    // 펼친 상태에서는 전체 화면 레이아웃을 사용합니다.
}

폴더블 대응 화면에서는 자세 판정 로직을 WindowPosture 기준으로 다시 확인합니다.

Progressive Blur API가 정리되었습니다​

1.13 alpha03에서 추가된 Modifier.blur { ... } API가 RC에서 정리되었습니다.
Modifier.blur의 radius 파라미터가 blurRadiusSpec으로 개명되었고, BlurScope.radius도 blurRadiusSpec으로 바뀌었습니다.
BlurStop.fraction에는 @FloatRange가 추가되었고, BlurRadiusSpec.radialGradient의 기본 fallOffRadius는 Dp.Unspecified로 변경되었습니다.

그 외 변경점​

VectorPainter가 같은 ImageVector를 여러 컴포저블에서 그릴 때 내부 그래픽 리소스를 공유합니다.
반복 아이콘을 쓰는 리스트에서 텍스처 업로드와 메모리 사용이 줄어듭니다.
이 최적화는 ComposeUiFlags.isVectorDrawCacheSharingEnabled 플래그로 끌 수 있습니다.
Modifier.border는 이제 아웃라인 크기를 기준으로 테두리를 그립니다.
문제가 생기면 ComposeFoundationFlags.isBorderMatchesOutlineBoundsFixEnabled 플래그로 이전 동작을 되돌릴 수 있습니다.
Material3 1.5.0-rc01에서는 ToggleButton의 눌림 상태 모양이 디자인 토큰을 따르도록 수정되었고, RangeSlider의 탭 시 값 미반영, 가로 스크롤 컨테이너 안에서의 스크롤 간섭, 이산 값 스냅 시 정밀도 손실이 수정되었습니다.
한편 1.13 alpha03부터 Compose 라이브러리의 compileSdk가 37.1로 올라갔습니다.
앱과 라이브러리의 compileSdk도 함께 올려야 합니다.

실무 관점​

RC 단계에서는 프로덕션 적용보다 검증이 먼저입니다.
Slider를 쓰는 화면이 있다면 onValueChange 누락 여부를 컴파일로 확인하고, Kotlin 2.2와 compileSdk 37.1 변경은 별도 브랜치에서 빌드를 검증합니다.
MTS에서는 주문 수량이나 조건 설정처럼 Slider를 쓰는 화면이 있어, 변경점이 적용되는 화면을 목록으로 정리해 두는 편이 좋습니다.

마치며​

Compose 1.13은 API가 확정된 RC 단계에 들어섰고, Slider 필수 파라미터화와 Kotlin 2.2 요구가 가장 큰 변경점입니다.
stable 릴리스가 나오면 적용 범위를 정해 단계적으로 올리는 것이 좋습니다.

베타 미리 보기 — Compose 1.13.0-beta01과 Material3 1.5.0-beta01의 소스 브레이킹 변경

2026년 10월 19일 · 약 5분
Way
Android Developer

안녕하세요, 한국투자증권에서 한투-한국투자증권 개발을 담당하고 있는 way입니다.
2026년 10월 7일에 공개된 Compose 1.13.0-beta01과 Material3 1.5.0-beta01의 변경 사항에 대해 설명해드리겠습니다.

배경​

2026년 10월 7일, Compose BOM의 두 축이 베타로 나왔습니다.
androidx.compose.runtime:runtime:1.13.0-beta01와 androidx.compose.material3:material3:1.5.0-beta01입니다.
같은 날 stable도 runtime 1.12.1과 material3 1.4.0으로 함께 릴리스되었습니다.
둘 다 아직 베타지만 소스 브레이킹 변경이 포함되어 있어, 지금 미리 파악해 두면 나중에 스테이블로 올릴 때 수월합니다.
공식 AndroidX 릴리스 노트(Material3, Runtime)를 기준으로 실무에 닿는 변경만 정리합니다.
참고로 이 글은 최근 30일 이내 릴리스를 다루는 심화 해설입니다.

무엇이 달라졌는지​

Slider와 RangeSlider의 상태 분리​

가장 큰 소스 브레이킹 변경입니다.
Material3 1.5.0-alpha29에서 Slider와 RangeSlider의 onValueChange가 필수 파라미터가 되었고, 파라미터 순서도 바뀌었습니다.
무상태(stateless) 오버로드는 deprecated(일부는 hidden) 처리되었고, 상태를 별도 객체로 분리하는 방식으로 이관이 권장됩니다.

// 기존 방식 (1.5.0에서 deprecated)
var value by remember { mutableFloatStateOf(0.5f) }
Slider(value = value, onValueChange = { value = it })

// 새 방식 — 상태를 별도 객체로 분리
val state = remember { SliderState(value = 0.5f) }
Slider(state = state)

var range by remember { mutableStateOf(0.2f..0.8f) }
RangeSlider(value = range, onValueChange = { range = it })
// → val state = remember { RangeSliderState(startValue = 0.2f, endValue = 0.8f) }
//   RangeSlider(state = state)

함께 바뀐 사항은 다음과 같습니다.

  • RangeSliderState의 activeRangeStart와 activeRangeEnd가 startValue와 endValue로 개명되었습니다.
  • SliderState는 더 이상 공개적으로 DraggableState를 구현하지 않습니다. 바이너리 호환 유지를 위해 DraggableState는 SliderState에 복원되었고, onValueChange가 nullable인 오버로드는 hidden deprecated로 유지됩니다.

소스 코드는 고쳐야 하지만 이미 빌드된 바이너리는 깨지지 않게 설계된 셈입니다.

computedStateOf의 읽기 전용 강제​

runtime 1.13.0-beta01부터 computedStateOf의 계산 블록 안에서 state에 쓰면 IllegalStateException이 던져집니다.
이전에도 쓰면 안 되는 패턴이었지만 실제로는 조용히 넘어가거나 이상한 무효화(invalidation)를 일으키곤 했습니다.
이는 외부 기여로 들어온 SnapshotStateObserver 읽기 시 예상 밖 무효화 수정과 같은 맥락입니다.
계산 블록은 순수하게 읽고 반환만 한다는 규칙이 강제됩니다.

Kotlin 2.2와 AGP 요구사항​

Compose 라이브러리들이 Kotlin 2.2를 타깃으로 빌드되고, kotlinc 2.2가 필요합니다.
또 androidx.lifecycle:lifecycle-runtime:2.10.0 의존성 업데이트 때문에, 번들된 lifecycle lint 체크가 동작하려면 AGP 9.5.0-alpha04 이상이 필요합니다.
툴체인 전체가 2.2와 37.1 라인으로 움직이고 있다는 신호입니다.

compileSdk 37.1 전이적 요구​

Compose 라이브러리의 compileSdk가 37.1로 올라갔습니다.
이는 Compose를 쓰는 모든 앱과 라이브러리도 compileSdk를 37.1로 올려야 한다는 뜻입니다.
Android 17(targetSdk 37) 대응을 아직 하지 않았다면, Compose 1.13과 1.5 스테이블로 올라가는 시점이 강제 마이그레이션 시점이 됩니다.

그 외 변경 사항​

  • 비밀번호 필드의 기본 난독화 방식이 RevealLastTyped에서 TextObfuscationMode.System으로 바뀝니다. SecureTextField와 OutlinedSecureTextField의 기본값 변경입니다.
  • Float.NaN 관련 리컴포지션 스킵 버그가 수정되었습니다. Dp.Unspecified(내부적으로 Float.NaN 기반)를 인자로 받은 컴포저블이 인자가 변하지 않았는데도 리컴포지션을 스킵하지 못하던 문제입니다.
  • BottomAppBar와 연관 API가 스테이블로 승격되었고, BasicAlertDialog가 Experimental을 졸업했습니다.
  • LocalMotionScheme이 제거되고 MaterialTheme.motionScheme으로 교체되었습니다.
  • ExposedDropdownMenu가 멤버 함수에서 ExposedDropdownMenuBoxScope의 확장 함수로 변경되어 import를 새로 잡아야 합니다.
  • 새로운 material3-ripple 라이브러리가 추가되었습니다. 기존 material-ripple의 대체이며 inset focus ring을 지원합니다.
  • DatePicker가 월 이동 가용성을 표시 월 인덱스에서 직접 계산해 1프레임에 해결되도록 개선되었습니다.
  • TopAppBarDefaults.enterAlwaysScrollBehavior의 reverseLayout 오버로드가 1.4 호환을 위해 deprecated(경고)로 복원되었습니다.
  • HorizontalCenteredHeroCarousel의 maxItemWidth가 preferredItemWidth로 개명되었고, 멀티애스펙트 캐러셀 API가 전역 carouselParallaxScrollEffect 모디파이어로 단순화되었습니다.
  • runtime에서는 movableContent 이동 시 wrapper 슬롯을 들고 있던 LinkComposer 메모리 누수가 수정되었고, CompositionObserver가 패스당 1회 해결되도록 변경되었으며, 오프-메인 스레드 ComposeTracer가 지원됩니다.

실무에서 주의할 점​

  • Slider 사용처를 전수 조사해야 합니다. 금융 앱에 수수료 슬라이더나 투자 금액 조절 같은 Slider와 RangeSlider가 있다면 1.5.0 스테이블 전에 상태 분리 방식으로 바꿔 두는 것이 좋습니다. onValueChange 필수화는 컴파일 에러로 드러나지만, 파라미터 순서가 바뀐 오버로드는 시그니처 자체가 바뀌어 에러가 나거나 deprecated로 걸리므로 리뷰는 한 번씩 필요합니다.
  • computedStateOf와 derivedStateOf 블록 안에서 값을 쓰는 코드가 있는지 검사해야 합니다. IllegalStateException은 런타임에 발생하므로, 코드 검색으로 계산 블록 안에 대입이 있는지 미리 확인하는 것이 안전합니다.
  • Kotlin 2.2와 AGP, compileSdk 37.1은 묶어서 계획해야 합니다. Compose 1.13은 Kotlin 2.2를, lint는 AGP 9.5.0-alpha04 이상을, Compose는 compileSdk 37.1을 각각 요구하므로 서로 의존합니다. 하나씩 따로 올리기보다 한 스프린트에 묶어 CI에서 함께 검증하는 편이 낫습니다.
  • 비밀번호 입력 UX 변경은 기획과 디자인 부서와 공유해야 합니다. 기본값이 System으로 바뀌면 타이핑 중 마지막 글자를 잠깐 보여주는 동작이 사라집니다. 보안 정책상 환영할 변화지만, 릴리스 노트 한 줄로 바뀌는 UX라 미리 공유하지 않으면 버그 문의가 들어올 수 있습니다.
  • 베타 릴리스이므로 스테이블 전에 API가 또 바뀔 수 있습니다. 이 글에서 다룬 내용은 베타 시점에 확정된 변경 기준입니다.

마치며​

Compose 1.13과 Material3 1.5는 베타 단계에서 미리 확인해 두면 스테이블 상향이 훨씬 수월해집니다.
특히 Slider의 상태 분리와 툴체인 요구사항은 일정을 잡아 미리 준비하는 것이 좋습니다.
